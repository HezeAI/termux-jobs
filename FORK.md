# Основа форка Termux

База: официальный `termux/termux-app`, тег `v0.118.3`, коммит
`5b657c6adf4304e5198951ce815fe0205dcac29c`.
Ветка разработки: `fork/base`. Remote `upstream` указывает на оригинал.
Рабочая папка: `/root/termux-fork`. UI и рабочее пространство реализованы по
референсу `/sdcard/Download/Buildtermyx.png`: AMOLED-фон, бирюзовые акценты,
скруглённые карточки, нижняя навигация и вкладки терминалов.
Исходные терминал, PTY/JNI, bootstrap, сервис и лицензия сохранены.

Установленный Termux и его данные не являются целью изменений. Не устанавливайте
APK и не меняйте системные пакеты либо общий SDK. Все дополнительные инструменты
и кеши проверки должны находиться в `.tools/` внутри этого репозитория.

## Рабочее пространство

- Команды: название, команда, категория, каталог, избранное, поиск, редактирование,
  дублирование и удаление. Запуск создаёт отдельный терминал.
- Звёздочка рядом с вводом терминала открывает библиотеку (избранное первым).
  Выбор заменяет текст поля, оставляет курсор в конце и не отправляет команду.
  Каталог сохранённой команды при вставке не меняет каталог активной сессии.
  «Сохранить ввод» открывает форму с текущим текстом для добавления в библиотеку.
- Сессии: имя, каталог и стартовая команда; активные и сохранённые профили,
  восстановление по нажатию, перезапуск с подтверждением, остановка и дублирование.
- До восьми терминалов в исходном сервисе; переключение вкладками.
- История Bash хранится в отдельном HISTFILE для каждого профиля. Последний
  вывод терминала сохраняется отдельно (до 65 536 символов). История доступна
  через меню сессии, в том числе после перезапуска приложения.

Сохранённые профили не восстанавливают работающий процесс и не проигрывают
старый вывод как новое выполнение: кнопка запуска создаёт Bash, загружает историю
и повторно выполняет стартовую команду. Изменения каталога и стартовой команды
профиля применяются при следующем запуске; новое имя применяется сразу.
Обычные сессии форка используют Bash и пользовательский `~/.bashrc`.
Failsafe и сессии внешних плагинов сохраняют исходный механизм запуска;
для них доступен снимок вывода, отдельный журнал Bash не внедряется.

Данные находятся в приватных файлах приложения: `workspace-v1.json` и
`workspace-sessions/<uuid>/history`. Запись библиотеки последовательная и
атомарная; повреждённый или неизвестный формат не перезаписывается.
Снимок обновляется во время вывода и при уходе со страницы/из Activity.
Последние секунды вывода могут не сохраниться при принудительном убийстве
процесса. Bash дописывает историю после возврата к приглашению.

## Сборка

Нужны JDK 11, Android SDK Platform 30, Build Tools 30.0.3 и NDK 22.1.7171670.
Gradle 7.2 запускается через включённый wrapper; системный Gradle не требуется.
Не запускайте эту версию Gradle на JDK 21.

```sh
sdkmanager --sdk_root="$PWD/.tools/sdk" "platforms;android-30" "build-tools;30.0.3" "ndk;22.1.7171670"
# Используйте только локальный SDK; скрипты сохраняют кеши внутри .tools/.
./scripts/check.sh
./scripts/build-debug.sh
```

APK: `app/build/outputs/apk/debug/termux-app_fork-debug_universal.apk`.
Сборка скачивает Maven-зависимости и четыре bootstrap-архива;
SHA-256 архивов проверяется исходным кодом сборки.
GitHub Actions `Fork CI` выполняет тесты, сборку и сохраняет APK как artifact
при push в `fork/**`, pull request либо ручном запуске. Для запуска workflow
потребуется разместить репозиторий на GitHub; сейчас база только локальная.

## Идентификатор и подпись

Сохранён `com.termux`: bootstrap и пакеты используют абсолютные пути
`/data/data/com.termux/files/usr`. Простая замена applicationId сломает окружение.
Для отдельного идентификатора необходимо согласованно поменять константы,
manifest, права, пути и пересобрать bootstrap и пакеты под новый prefix.
Такой вариант нужно планировать после выбора имени форка.

Debug использует отдельный локальный тестовый ключ форка:
`.signing/fork-debug.jks`, alias `termux-fork-debug`. Скрипт
`./scripts/create-debug-key.sh` создаёт его один раз; ключ исключён из Git.
Пароль по умолчанию — `termux-fork-debug` (только для тестовых сборок);
его можно задать переменной `TERMUX_FORK_KEYSTORE_PASSWORD` при создании
и сборке. Сохраните резервную копию ключа вне Git для последующих обновлений.
Для выпуска потребуется продуманная постоянная подпись. Текущий APK не устанавливается
параллельно с обычным Termux. Обновление установленного Termux возможно только
при совпадении подписи. Не удаляйте установленный Termux без копии данных.

## Дальнейшая разработка

Карта исходников — [docs/fork/ARCHITECTURE.md](docs/fork/ARCHITECTURE.md).
Исходные README и LICENSE.md сохранены. При распространении соблюдайте
лицензию GPLv3 и сохраняйте сведения об авторах.

Чтобы обновить базу, получите теги через `git fetch upstream --tags`,
просмотрите изменения и объедините выбранный тег в рабочую ветку.
Не обновляйте upstream автоматически вместе с изменениями UI.

## Проверка в текущей среде

JDK 11 и Gradle 7.2 размещены в `.tools/`, SDK 30 и Build Tools 30.0.3 —
в локальном `.tools/sdk`. Все новые инструменты, кеши и выходные файлы
после уточнения границ находятся внутри `/root/termux-fork`.

ARM64 APK собран из копии исходников в `.verification/arm64` командой
`build-local-arm64.sh`: обе JNI-библиотеки скомпилированы из оригинального C/ASM
под Android API 24, официальный ARM64 bootstrap проверен по SHA-256,
Gradle собрал Java/ресурсы/DEX и подписал APK локальным ключом форка.
Этот путь сборки не требует запуска x86-версии NDK на ARM64-хосте.
Основная конфигурация Gradle с NDK сохранена для стандартной сборки в CI.

Результат: `build/apk/termux-fork-0.2-debug-arm64.apk`.
Копия: `/sdcard/Download/TermuxFork-0.2-debug-arm64.apk`.
Версия `0.118.3-fork.2`, package `com.termux`, ABI `arm64-v8a`, minSdk 24,
targetSdk 28. Подпись v2 проверена через apksigner. APK не устанавливался.
С этой подписью APK нельзя установить рядом с текущим Termux или обновить
установленный Termux, подписанный другим ключом.

Java/ресурсы компилируются; все 155 тестов прошли (145 эмулятора и 10 приложения).
Проверки библиотеки и навигации выполнены отдельно без старта реального
TermuxService, распаковки bootstrap или установки APK на устройство.
Итоговые результаты — [docs/fork/VALIDATION.md](docs/fork/VALIDATION.md).
