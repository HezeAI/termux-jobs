# Основа форка Termux

База: официальный `termux/termux-app`, тег `v0.118.3`, коммит
`5b657c6adf4304e5198951ce815fe0205dcac29c`.
Ветка разработки: `fork/base`. Remote `upstream` указывает на оригинал.
Название, дизайн и дополнительные функции пока не заданы.
Исходные UI, терминал, сессии, JNI, bootstrap и лицензия сохранены.

## Сборка

Нужны JDK 11, Android SDK Platform 30, Build Tools 30.0.3 и NDK 22.1.7171670.
Gradle 7.2 запускается через включённый wrapper; системный Gradle не требуется.
Не запускайте эту версию Gradle на JDK 21.

```sh
sdkmanager "platforms;android-30" "build-tools;30.0.3" "ndk;22.1.7171670"
# Укажите SDK через ANDROID_HOME либо sdk.dir в local.properties.
./scripts/check.sh
./scripts/build-debug.sh
```

APK: `app/build/outputs/apk/debug/termux-app_fork-debug_universal.apk`.
Сборка скачивает Maven-зависимости и четыре bootstrap-архива;
SHA-256 архивов проверяется исходным кодом сборки.
GitHub Actions `Fork CI` выполняет тесты, сборку и сохраняет APK как artifact
при push в `fork/**`, pull request либо ручном запуске. Для запуска workflow
потребуется разместить репозиторий на GitHub; сейчас база только локальная.

## Идентификатор и подпись

Сохранён `com.termux`: bootstrap и пакеты используют абсолютные пути
`/data/data/com.termux/files/usr`. Простая замена applicationId сломает окружение.
Для отдельного идентификатора необходимо согласованно поменять константы,
manifest, права, пути и пересобрать bootstrap и пакеты под новый prefix.
Такой вариант нужно планировать после выбора имени форка.

Debug использует публичный тестовый ключ upstream. Он подходит для разработки;
для выпуска потребуется собственная подпись. Текущий APK не устанавливается
параллельно с обычным Termux. Обновление установленного Termux возможно только
при совпадении подписи. Не удаляйте установленный Termux без копии данных.

## Дальнейшая разработка

Карта исходников — [docs/fork/ARCHITECTURE.md](docs/fork/ARCHITECTURE.md).
Исходные README и LICENSE.md сохранены. При распространении соблюдайте
лицензию GPLv3 и сохраняйте сведения об авторах.

Чтобы обновить базу, получите теги через `git fetch upstream --tags`,
просмотрите изменения и объедините выбранный тег в рабочую ветку.
Не обновляйте upstream автоматически вместе с изменениями UI.
