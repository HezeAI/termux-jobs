## Изменения

В четырёх чатах «Вложения» и «Изменения» имеют одну строку: векторное обновление
слева, поиск справа, без крестика. Область нажатия обновления — 48 dp,
RU/EN accessibility label, блокировка повтора и индикатор занятости.
Раздел «Файлы», история, курсоры, фильтры, поиск только по загруженному,
«Загрузить ещё» и сохранение списка при ошибке не меняются.

Каждое вложение содержит отдельную информационную карточку и расположенную
ниже общую горизонтальную плашку действий. У каждого применимого действия —
своя обводка, отклик/focus и обработчик. Плашка прокручивается со своей карточкой;
текст допускает перенос, высота определяется содержимым. У Git новых действий нет.

В просмотре изображения слева добавлена «В галерею» / «To gallery», справа
сохранено сохранение в Download. Общий просмотр используется четырьмя агентами
и для пользовательского вложения, и для конкретной локальной ссылки агента.
Экспорт копирует материализованный оригинал потоком 32 КиБ, не Bitmap/скриншот
и не модельную уменьшенную копию. Расширение и MIME сверяются с сигнатурой:
PNG/JPG/JPEG/WebP/GIF/BMP/HEIC/HEIF/AVIF. Для неподдерживаемого формата/провайдера
показывается ограничение, Download остаётся доступен. EXIF и иные исходные
метаданные также остаются в оригинале; обещания отображения в любой галерее нет.

Android 10+: вставка новой app-owned строки в MediaStore Images external_primary,
`Pictures/TermuxJobs/`, `IS_PENDING=1`, сырые байты, закрытие потока, затем
`IS_PENDING=0`. Новый URI создаёт провайдер; прежний URI никогда не обновляется.
На Android 8–9 — эксклюзивное создание файла в Pictures/TermuxJobs с суффиксом
при совпадении имени, затем регистрация в MediaStore. Отдельный continuation
запрашивает только WRITE_EXTERNAL_STORAGE на 26–28, без общего all-files helper.
На 29+ эта операция не запрашивает storage permissions. Существующие права APK,
нужные другим функциям, не удаляются и не выдаются за отсутствующие в manifest.
Механизм выбран по [документации Android](https://developer.android.com/training/data-storage/shared/media);
его реальные ограничения устройства проверяются отдельно.

Успех показывается только после завершения записи/регистрации. Обработанная
ошибка/отмена убирает только новый URI и свой новый legacy-файл. Ошибка удаления
даёт отдельное сообщение без успеха. Закрытие предпросмотра не обрывает уже
согласованную запись; закрытие владельца UI отменяет её с проверкой потока.
Аварийное завершение процесса не моделируется как обработанная отмена:
скрытая pending-запись может остаться до системной очистки, это не проверено на Android.

## Проверено заново — стенд помощника

Доказательства находятся в `.verification/test-2.1.4-test6/` этого checkout.
Полный применимый JVM-набор: **372 теста, 38 непустых наборов, 0 ошибок,
0 падений, 0 пропусков** (`jvm-summary.json`).
После уточнения Android-dispatch фикстуры отдельно прошли **4 теста разрешений**,
включая TermuxActivity → отказ → повтор → разрешение → игнорирование позднего
дубликата (`permission-final-tests.log`, `permission-final-jvm/`).
Современный Lint 7.4.2 всех пяти модулей: **0 ошибок, 246 предупреждений**,
без ошибок загрузки правил. Новые предупреждения: четыре InlinedApi про
MediaStore API29, используемые только modern-ветвью фабрики, и применение
существующего vector drawable через Android TextView. Константы встраиваются
в байткод; legacy-ветвь не передаёт новые поля провайдеру. Предупреждения не скрыты.
Старый встроенный lintVitalRelease сообщает несовместимость Kotlin metadata;
он не считается успешным современным анализом. Идентичность APK — ниже.

- `ImageGalleryExportTest`: оригинальные байты GIF с двумя кадрами, MIME/расширения
  всех перечисленных семейств, повторные имена, legacy-файлы/регистрация,
  ошибки insert/open/write/close/metadata/publish, отмена и изоляция очистки.
  Настоящий ContentResolver adapter проверен с поддельным ContentProvider и PFD.
  Заголовочные образцы HEIF/AVIF/BMP/WebP не являются декодированием реального формата ОС.
- `WorkspaceImageSaveAccessTest`: отдельный requestCode, отказ, разрешение/повтор,
  закрытый callback, отсутствие all-files/settings. SDK 29/30/33/35 — ветви
  Build.VERSION в SDK28 JVM, а не запуски настоящих версий Android.
- `ImageGalleryUiTest`: четыре агента отдельно, RU/EN, пользовательские PNG/GIF
  и ссылки агента, две записи, ошибка без успеха, Download остаётся доступен,
  исходник не меняется, staging/путь к модели не вызываются. Экспорт в этом UI-тесте
  подменён; настоящая публичная галерея не заполнялась.
- `AgentProjectPanelCompactLayoutTest`: четыре агента, две темы, RU/EN, размеры
  шрифта 1/2, геометрия панели/карточек, независимые рамки/нажатия, применимость
  действий и привязка к конкретному файлу. Явный многострочный caption проверяет
  рост высоты без обрезания. Реальный перенос глифов крупного системного шрифта
  остаётся проверкой телефона: legacy graphics Robolectric не воспроизводит его.
- Сохраняются первоначальные неудачные прогоны: неприсоединённый к окну View
  не выполнял отложенный click; после реального fixture Dialog нажатия работают.
  Отдельное ошибочное ожидание permission Intent исправлено: Robolectric не всегда
  создаёт такой Activity Intent, фактический запрос проверяется по PermissionsRequest.
  Дополнительный повтор через TermuxActivity сначала не прошёл: прямой вызов
  callback не снимает внутренний pending-флаг Android. Тест переведён на настоящий
  `dispatchRequestPermissionsResult`, который сбрасывает флаг и вызывает callback.
  Это исправление фикстуры, не изменение разрешений приложения.
  Неподтверждённый автоматический перенос текста не считается пройденным.

Открытие, поиск, перелистывание, предпросмотр, экспорт и Git-просмотр имеют
только локальные файловые/исторические маршруты. Новый Gallery exporter не знает
адаптер, send/prompt или историю CLI. UI-фикстуры запрещают вызов отправки модели.

## Короткая проверка телефона

Использовать отдельный тестовый чат и искусственные изображения без приватных метаданных.

1. В каждом из четырёх чатов открыть «Файлы и изменения». В двух новых вкладках
   обновление слева от поиска, крестика нет. Проверить фильтр, поиск, «Загрузить ещё»
   и повторное открытие; «Файлы» не меняются, предыдущие сообщения доступны.
2. Проверить плашку непосредственно под каждой карточкой: у каждой кнопки своя
   обводка/отклик, действия ведут к своему файлу. Проверить крупный шрифт и RU/EN.
3. Открыть пользовательское PNG/JPEG и ссылку агента на GIF. Нажать «В галерею»
   дважды. Получить два разных файла в Pictures/TermuxJobs, без перезаписи;
   GIF остаётся анимированным в поддерживающем его просмотрщике. Сверить байты
   с оригиналом (SHA-256 через доступный файловый инструмент); Download остаётся.
4. На Android 8–9 проверить отказ разрешения записи и повтор после разрешения.
   На 10+ новая операция не должна просить all-files. При доступной безопасной
   ошибке сохранения не должно быть сообщения об успехе/видимого неполного файла.
5. Убедиться, что просмотр/сохранение не запускают ответ агента. Сообщить версию
   Android, агент, формат, шаг и сообщение ошибки; реальные секреты не прикладывать.
