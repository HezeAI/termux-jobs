## Почему сегмент замирал

Видео разработчика8,416с показывает остановки сегмента и скачки при обновлении
экрана. Анализ10кадров/с только внешнего кольца кнопки, без аудио: на интервале
2,2–3,2с центр светлого участка остаётся261,7° во всех11выборках. Это не непрерывное
движение. Исходный файл не копировался в APK или репозиторий.

В старом оформлении текущий LayerDrawable повторно использовался внутри нового
RippleDrawable. Android View.setBackgroundDrawable отключает прежний фон:
сбрасывает callback и отменяет его расписание; у прикреплённого View также скрывает
его. Обводка теряла путь доставки обновлений. Внешняя перерисовка всё ещё могла
нарисовать участок с новой координатой времени, что соответствует ролику.
Проверены публичный метод framework именно Android36 этого устройства и отдельная
фикстура прежнего способа оборачивания. Общий метод framework прочитан без изменения
системы. Полный класс сначала не прочитался старым baksmali из-за hidden-API flags;
извлечение только нужного метода затем прошло. Неудача первого инструмента сохранена.

Теперь фон сразу состоит из круга и обводки внутри одного корневого ripple.
После общего оформления цепочка callback остаётся соединённой с кнопкой.
Во время requiresTerminal работает ValueAnimator:2000мс, линейно, INFINITE.
Он обновляет фазу и вызывает invalidate только кнопки; перерисовка не зависит от
касания/открытия меню. Paint не меняет яркость самого значка. При окончании ожидания,
снятии видимости или отсоединении хоста часы отменяются. Возврат с прежним ожиданием
восстанавливает их. При отключении системных анимаций остаётся статический индикатор.
Прежние цвет, ширина, длина сегмента22% окружности и направление CW сохранены.

Настоящий Android Canvas отрисовал production Drawable в четырёх четвертях.
Центры светлых пикселей:38,90°→130,24°→218,95°→308,63°, то есть движение по часовой
стрелке с шагом около90°. Это проверка геометрии отрисовки, не запись интерфейса.
Фикстура таймера проверяет кадры без касаний, запрос бесконечного повтора, второй
проход, снятие ожидания/возврат и reduced motion. Robolectric4.4 намеренно заменяет
INFINITE одним повтором: длительный реальный показ этим стендом не подтверждается.

## Остановка рабочего стола

Состояние ожидания привязано к точным owner/target/remote выбранной записи.
Оно устанавливается после явного подтверждения и до отправки stop. Повторный клик
заблокирован и в View, и в контроллере. Snapshot phase=stopping со started=false
не принимается за завершение: логический владелец сохраняется до результата.
Успех показывается после phase=stopped либо отключения соответствующего сервиса
при ожидаемой остановке. Неожиданный разрыв соединения имеет другое сообщение.
RPC-ошибка/ошибка состояния/30сек без подтверждения снимают ожидание и сообщают
причину. Проверки единственного владельца повторяются штатным сервисом атомарно.
При утрате владения повторная остановка недоступна.

Код X11Service, dedicated-process shutdown, process identity и старые JNI не менялись.
Терминальный процесс/история/сессия не закрываются этим UI. Фикстуры используют
собственный Binder и не отправляют сигналы настоящим процессам/сессиям.

## Первоначальные отказы и ограничения стенда

Первая компиляция нашла один оставшийся старый actions-consumer в AgentChatUi;
вызов исправлен. Первые UI-фикстуры читали состояние до dispatch сообщения кнопки
и до готовности синтетического окна. Эти отказы сохранены и не считаются PASS.
Промежуточный вариант пульсации отменён после уточнения пользователя; в итоговом
WorkspaceIconButton код рисования побайтово прежний, изменяется только обводка.

Robolectric4.4 принудительно ограничивает INFINITE одним повтором. Попытка снять
ограничение с paused clock зациклила собственный worker на одном virtual frame;
стек сохранён, завершён только проверенный Gradle CLI по PID/start time. Рабочие
процессы не затрагивались. Итоговая фикстура использует управляемый видимый хост,
виртуальные кадры16мс и явную выборку второго прохода. Она проверяет позицию,
invalidate/остановку/возврат и регистрацию INFINITE, но не физическое окно телефона.
В одном промежуточном отказавшем прогоне был фоновый class-loader error; финальный
полный120-прогон завершился без него. Промежуточные XML/logs и native evidence сохранены.
