## Репозитории рабочих столов

HTTP/HTTPS Ubuntu ports resolute и Debian trixie —200; Alpine3.24 main/community,
Termux main/x11 —200. Fedora44 metalink и repomd доступны; в исходном журнале
DNF есть временный TLS connection reset by peer, который был повторён.
Три пробы Fedora primary по1MiB дали примерно627–1502KiB/s без ошибки.
Форсированная смена зеркал не делалась: один замер не доказывает постоянное
преимущество зеркала, а установка должна сохранять проверку подписей.

## Подтверждённая причина Fedora

В dnf5.log установщика две записи «No match for argument: xorg-x11-utils».
Полные официальные ARM64 primary-метаданные Fedora44 скачаны отдельно в проект
и распарсены: из30 проверенных имён отсутствует только xorg-x11-utils;
xprop/xwininfo доступны. Это прерывает разрешение пакетов до их загрузки.

Исправление66: заменить старое имя двумя актуальными пакетами; использовать
обычный DNF makecache без --refresh при каждой попытке (свежий кэш сохраняется),
загрузку пакетов распараллелить до6; retries3/timeout30 и проверки подписей
сохранены. Принудительное обновление каталога по явному запросу остаётся.

## Поведение при ошибке

Раньше и отсутствующие компоненты при проверке, и ошибка установки получали
phase=missing. Поэтому UI повторно предлагал установку и создавал впечатление
таймаута без ошибки. Теперь неудача install →error; UI сохраняет причину
(например No match for argument), а не последнюю служебную строку.

На видео Screenrecorder-20261021-230421.mp4 видно «Установка не завершена /
CHECK:done» у Ubuntu/Debian. Служебная последняя строка не объясняет сбой.
В66 выбирается ERROR/MISSING/текст сетевой ошибки из отчёта; отсутствие
оболочки получает пояснение о найденной папке и возможной незавершённой установке.
Без полного отчёта с того устройства нельзя утверждать, что там отсутствует
именно shell. Существующие/неполные каталоги автоматически не удаляются.

## Остаточные ограничения

Установленный proot-distro5 содержит повторы сетевых ошибок, но для blob-загрузки
не задаёт явный timeout в месте открытия соединения и не делает HTTP Range
для продолжения частичного слоя: неудачная попытка начинает этот слой заново.
Его установленный код не менялся. Это возможный источник задержек на плохой
сети, а не доказанная причина проблемы на втором телефоне. Перезапуск всего
install/удаление rootfs автоматически не добавлялись.

Данные замеров: .verification/install-network-audit/*.json и probe.log.

## Отмена установки в66

Приватный supervisor отправляет собственной группе SIGINT и ждёт1 секунду,
потом TERM и3 секунды до KILL. До KILL лидер не освобождается/reap, чтобы PGID
не был переиспользован и фоновые потомки не остались без контроля. Установленный
proot-distro при KeyboardInterrupt получает шанс удалить свою неполную папку.
Тесты подтверждают очистку/повтор и отсутствие воздействия на чужой процесс.
При принудительном KILL остатки возможны, существующие папки не перезаписываются.
UI сохраняет «Остановка установщика…» и блокирует повтор до завершения worker.
