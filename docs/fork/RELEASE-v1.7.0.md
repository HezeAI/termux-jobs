# v1.7.0 — Linux-окружения, пакеты и бэкапы

Большое обновление Termux Job’s: разные Linux-системы теперь можно установить,
выбрать для сессии или пресета, открыть их файлы, установить пакеты и восстановить
из бэкапа отдельно от исходного окружения.

## Окружения Termux

В создании сессии и пресета появился раздел **«Окружения Termux»**: Termux,
Ubuntu, Debian, Alpine, Fedora, openSUSE, Void Linux и Arch Linux ARM.
У каждого экземпляра своя привязка файлов и запуска. Справа от названия —
«Установить» или серое «Установлено». Отсутствующая система устанавливается
с подтверждением и прогрессом. Есть проверка наличия окружения/оболочки и точная
команда ручного входа из Termux. Это не автоматическая проверка всех пакетов.

Void устанавливается из официального OCI-образа; Arch на ARM64 — отдельный
проект Arch Linux ARM, из закреплённого архива Termux с проверкой SHA-256.
Поддержка установки зависит от архитектуры и доступного proot-distro.
Debian, Alpine, Fedora, openSUSE, Void и Arch — самостоятельные Linux-окружения
со своими rootfs, файлами и пакетами. Для них не создаётся «своя Ubuntu»: они
не привязаны к основной Ubuntu и не используют её.
**Существующая Ubuntu и AI Agents остаются в прежнем общем окружении**;
миграция авторизации/агентов в другую Ubuntu не выполняется.

## Пакеты для каждого окружения

Панель определяет менеджер внутри выбранной системы и не объединяет пакеты
разных экземпляров. Доступны списки установленных/доступных/обновляемых пакетов,
поиск, описания и подтверждённые установка/обновление/удаление.

| Окружение | Менеджер | Проверка разработчика |
| --- | --- | --- |
| Debian | APT | Каталог, обновление, установка и запуск tree |
| Alpine | APK | Каталог, обновление, установка и запуск tree |
| Fedora | DNF | Каталог, обновление, установка и запуск tree |
| openSUSE | Zypper | Каталог, обновление, установка и запуск tree |
| Void Linux | XBPS | Каталог, обновление, установка и запуск tree |
| Arch Linux ARM | Pacman | Полное обновление, установка и запуск tree |

Перед запуском показана команда; можно выбрать свободную текущую сессию или
новую сессию того же окружения. **У Arch установка/обновление использует полное
pacman -Syu**, с отдельным пояснением: частичные обновления не предлагаются.
Выбор конкретной версии в панели пока поддерживает APT. Каталоги зависят от
подключённых репозиториев и архитектуры.

Исправлены обнаруженные в проверках особенности: хостовый APT больше не
подхватывается через PATH proot; каталог Alpine читается корректно offline;
DNF5 получает настоящий TAB; XBPS принимает буквенные версии вроде R59c_2.

## Бэкапы и отдельное восстановление

Linux-окружения выбираются по конкретному экземпляру. Полное восстановление
создаёт новый **jobs-…** и пресет запуска, не заменяя работающую систему.
Пакеты и файлы Linux переносятся вместе с rootfs; сравнение/план пакетов Termux
остаётся отдельным APT-функционалом и не смешивается с гостевыми системами.

**Разработчик проверил все шесть систем:** полный бэкап, восстановление отдельной
копией, запуск, наличие установленного тестового пакета и файла, файловый
менеджер и повторный запуск. Исходные Debian/Void также повторно проверены.
Это не утверждение, что проверены любые чужие архивы, каждый вариант выборочных
данных или перенос на любое другое устройство; работающие базы требуют согласованной
копии и завершения изменяющих их задач.

Исправлены длинные PAX-пути, архитектура Alpine/BusyBox, буквальные имена systemd
в Arch, восстановленный запуск Void без Bash и подготовка служебного .l2s при
readonly-корне Arch. Небезопасные пути/ссылки и неподтверждённая архитектура
по-прежнему блокируются. Чужие OCI Entrypoint/Env не переносятся — служебные
метаданные запуска создаются заново. Пометка «тестирование» в меню бэкапа убрана.

## Удаление восстановленных окружений

В меню бэкапа добавлен отдельный пункт: источник, имя jobs-…, размер и отметка
незавершённого восстановления. Удаление требует подтверждения, удаляет файлы
и пакеты выбранной копии, затем связанные пресеты. **Архивы Download, отчёты
и исходные окружения сохраняются.**

Открытые сессии нужно закрыть: штатная эксклюзивная блокировка proot-distro
отклоняет удаление используемой среды, включая CLI-сессии. Принудительная
остановка/force не применяются. Нужен современный менеджер с поддерживаемыми
блокировками; иначе удаление заблокировано. После подтверждения действие
нельзя отменить случайным закрытием окна. Неполная операция может оставить
частичную копию для повторной проверки, без обещания отката удаления.

Происхождение проверяется по результату восстановления/приватной записи попытки;
одного имени jobs-… недостаточно. Старые копии без подтверждения показаны серыми
без удаления. Проверены автоматические сценарии и штатная блокировка на отдельном
экземпляре внутри проекта; новый экран удаления ещё требует проверки на устройстве.

## Обновление и совместимость

- Прежние **com.termux и сертификат**, versionCode **1215**; Android8+/ARM64.
- С публичной1.6.5 и проверочных1.6.x сброс данных не предусмотрен. Библиотекаschema8,
  форматы бэкапа1/2 и серверов сохранены; команды, заметки, прежние пресеты и история
  не очищаются автоматически. Процессы при обновлении Android может завершить:
  закончите важные операции и заново откройте сессии после установки.
- Новые proot-пресеты имеют дополнительные поля. Старая версия приложения не
  запускает их команды в Termux; при пересохранении старым читателем поля могут
  потеряться. Для отката нужен APK с более высоким кодом и бэкап библиотеки новой
  версией. Не устанавливайте старый APK через удаление приложения ради обновления.
- При обновлении с версий до1.5.3 сохраняется очистка приватных данных удалённой
  локальной AI-функции; внешние модели и proot-системы не удаляются. Сохраните
  нужные старые локальные данные заранее.
- Выпуск содержит APK, SHA256SUMS, SHA-256 файл и **update.json** для обновления
  из приложения. Никаких автоматических сбросов пользовательских данных.
