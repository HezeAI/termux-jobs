# v1.5.3-test — Gemma native tools and experimental media

Private test APK only, code1140. Public v1.5.0 unchanged. Same package/certificate; no reset or model changes. Existing imports/chats/presets retained. Start a fresh test chat to avoid retaining earlier bogus tool responses.

- New Engine settings → Model communication format → JSON / Native LiteRT (testing), stored per session/preset. Native is the default when newly selecting the pinned Gemma4E2B SM8750; existing explicit JSON settings are kept. Other LiteRT models can opt in experimentally, depending on their embedded template/tool support. Uses LiteRT0.17.0 structured ToolProvider/ToolCall/ToolResponse. SDK automatic execution stays OFF; canonical calls return to application validation, permissions and approval cards. One call per response; unsupported parallel calls fail without execution. SDK history uses model/tool roles, not ordinary user messages for tool results.
- Greetings/questions explicitly request natural text; tool-only JSON formatting applies to actual actions. Native LiteRT prompt has no fabricated chat tool or Qwen tags. Custom behavior/rights text is kept; actual permission checks remain authoritative. Other models retain their selected protocol; llama native libraries untouched.
- Pinned Gemma experimental view_image/view_video enabled. Video is sampled frames only, not continuous playback or sound analysis. Media backends initialize lazily: NPU text, GPU vision and CPU audio. Media initialization failure restores text engine when possible and returns an error; do not assume every block executes on NPU.
- New listen_audio tool for pinned model: Android decodes first5seconds into bounded mono16k PCM WAV in owned cache; longer input is explicitly limited, no speech generation. The same file/environment/project permissions apply; no cloud upload. Android codec support determines supported source formats.
- Prepared image/audio paths must remain in owned media cache. Cancellation/decode deadline/cache cleanup retained; historical media is not silently reattached on later user turns.

Device checks required: new greeting+ordinary question, list/read with expected permission, screenshot text recognition, short local audio, video frames; return diagnostics for failure. Unit/SDK adapter tests do not prove hardware media support or model answer accuracy. Real downloaded model metadata inspected read-only: SHA matches pinned, actual Gemma Jinja, KV4096, prefill128, embedded vision/audio blocks. No model weights were modified.
