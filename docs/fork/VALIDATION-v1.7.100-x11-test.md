# Частная проверочная v1.7.100-x11-test

Дата: 2026-10-23. Публикация релиза ожидает проверки разработчиком HezeAI.

## Изменение и чистая установка

Alpine Mesa 26.1.6 из репозитория не содержит virpipe. В APK включён отдельный
минимальный ARM64/musl-клиент upstream Mesa 26.1.6, собранный без изменения исходников.
Его библиотеки доступны только Alpine VirGL через отдельный bind и переменные
конкретного запуска. Системная Mesa, CPU и Turnip не заменяются.
Архив проверяется по SHA-256, ELF ABI, безопасным путям и содержимому cache.
Исходники, параметры сборки, лицензии: [third-party](../../third-party/virgl-client/README.md).

Для новых Debian/Alpine/Fedora/openSUSE/Void применяется upstream fork на соединение:
старый протокол openSUSE Mesa 24.3 отклонялся режимом multi-clients.
Void переключён на ANGLE Vulkan. Настройки ранее подключённых Termux/Ubuntu/Arch
сохранены. Все дочерние процессы остаются в группе своего guardian.

X11 и Alpine-клиент поставляются в APK. Рабочий стол, host VirGL/ANGLE и обязательные
библиотеки выбранной системы устанавливаются из официальных репозиториев.
При нехватке компонента транзакция получает полный явный набор пакетов.
Готовность дополнительно требует загрузки libGL и поддержки virpipe: присутствие
пакета само по себе не выдаёт READY. Ошибка подготовки не выдаёт готовность.
Старый marker-v1 больше не принимается; может потребоваться подтвердить подготовку
один раз. Данные пользователей и системные библиотеки не очищаются.

## Проверки кода и безопасности

- 68 JVM проверок в пяти наборах, без ошибок: интеграция X11, assets,
  тема, GPU UI и редактированная диагностика запуска.
- 14 Python проверок: повреждённый/подменённый архив, ABI, traversal и symlink,
  повторное использование cache, прерванная распаковка, изменённые файлы;
  обязательные пакеты и отсутствие драйвера, отдельные сокеты и lifecycle.
- Остановка собственного сервера с fork-ребёнком подтверждена отдельно:
  ребёнок в группе guardian получает остановку, соседняя группа продолжает работать.
- Проверены shell-синтаксис и git diff --check.
- Диагностика сохраняет ограниченные категории backend/ошибки, без сырых путей,
  заголовков авторизации и произвольных текстов.

Доказательства находятся в локальной .verification/virgl-fix/: jvm-results.json,
python.log, fork-stop.log, matrix-final.json, build.log, apk-audit.json.
Тесты не изменяли установленные окружения или работающие пользовательские столы.
Дополнительные инструменты и результаты сборки находятся внутри репозитория.

## Реальный GPU, отдельно от GUI

На Adreno 830 проведены 10 изолированных EGL-проб: пять новых библиотечных наборов
(Debian, Alpine, Fedora, openSUSE, Void), каждый с ANGLE GL и Vulkan.
Все клиенты завершились с кодом 0: чтение красного пикселя 255,0,0,255,
рисование треугольника, client arrays и VBO без GL-ошибки.
Alpine использовал именно новый упакованный клиент и существующий compat preload.
Использовались отдельные сокеты и процессы, существующие библиотеки читались.

В некоторых GL-пробах при очистке контекста остаётся EGL_BAD_ACCESS в серверном
журнале, несмотря на успешную отрисовку и завершение клиента. Vulkan-проба Void
этого сообщения не дала. Отсутствие любых ошибок всех приложений не заявляется.

## Минимальная проверка разработчиком

1. Обновить APK, остановить и вновь запустить выбранный VirGL-стол.
2. Если предложена подготовка после смены marker, подтвердить её.
3. Alpine: GPU INFO и GPU/glxgears; Void: GPU INFO и полный GPU/glmark2.
4. openSUSE: GPU INFO и GPU после смены режима протокола.
5. Проверить остановку/повторный запуск и независимость второго стола.

Полный XFCE/GLX/glmark2 через обновлённый APK, установка на чистом другом телефоне,
Android-разрешения, клавиатура и другие GPU пока не проверены в этой сборке.
Изолированные GPU-пробы и mock-тесты не заменяют эти проверки.
