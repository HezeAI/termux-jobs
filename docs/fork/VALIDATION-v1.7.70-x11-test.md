# Частная v1.7.70-x11-test / code1285

## Причина и исправление

На двух скриншотах разработчика Fedora XFCE падает с кодом134:
GTK не получает значок, libwnck default_icon_at_size assertion, затем
xfce4-session Aborted. Скачивание пакетов уже завершилось.

В ограниченной фоновой команде Termux запущен Python/ctypes из установленной
Fedora через proot без X-сервера. Входы: собственные маленькие PNG и SVG
в репозитории; HOME/cache/tmp и результаты также внутри репозитория.
До исправления обе загрузки gdk_pixbuf_new_from_file завершаются ошибкой
spawn bwrap (ENOENT). Это воспроизведение реального декодера, а не UI-мок.

Отдельный x11-fedora-glycin.so (glibc/ARM64) перехватывает только
конструкторы gly_loader_new/gly_creator_new и выбирает публичный
NotSandboxed=3 для ABI libglycin-2.so.0. Уже загруженный точный модуль
находится через RTLD_NOLOAD, работает и RTLD_LOCAL, и RTLD_GLOBAL.
Системные файлы Fedora не меняются. Это не модуль Alpine/musl и не его
обход faccessat; прав доступа к файлам модуль не меняет.

## Граница доверия

Дополнительная песочница декодеров Glycin отключается в дереве запуска
рабочего стола Fedora. Декодеры получают права этого процесса, оставаясь
в Android sandbox приложения. Это снижает дополнительную изоляцию при
открытии изображений относительно полноценного Linux с Bubblewrap;
не даёт root Android и не отключает внутреннюю песочницу браузера.

Preload выставляется до приватного dbus-run-session, чтобы активируемые им
службы имели тот же режим. x11-session повторно проверяет наличие модуля
и не дублирует путь в LD_PRELOAD. Отсутствие файла прерывает запуск с явной
ошибкой. Выбор Fedora фиксированный; строка команды не формируется из
пользовательского пути. Другие окружения и работающие сессии не менялись.

## Доказательства

- До: PNG/SVG не открываются, оба требуют отсутствующий bwrap.
- После с модулем: PNG/SVG открываются; сохранение каждого в PNG также
  успешно (проверен и encoder/creator). Декодеры честно пишут предупреждение
  Glycin running without sandbox. Рабочий стол телефона не запускался.
- 2 новых теста: настоящая компиляция ABI-модуля и RTLD_LOCAL/GLOBAL;
  область только Fedora, установка preload до D-Bus, явный отказ без модуля.
  У модуля нет экспортов faccessat/stat.
- 3 прежних теста Alpine ABI/области/D-Bus прошли.
- 6 тестов установки/пакетов Fedora и 14 lifecycle/routing тестов стола прошли.

Модуль собирается из исходника локальным ARM64 C-компилятором с RELRO/NOW
и nonexecstack, без установки компиляторов/системных пакетов. Штатное ядро
X11, renderer/compositor, UI, клавиатура, агенты и отмена процессов не менялись.
Код проверен на загрузку, отсутствие/ошибки ABI, передачу окружения дочерним
процессам и сохранение отдельных сборок musl/glibc.

## Ограничения и совместимость

Нужно проверить запуск XFCE Fedora и меню/значки на телефоне после обновления.
Headless-проверки изображения не доказывают исправность всех программ,
жестов, окон, GPU или клавиатуры на устройстве.
Изменения68 (докачка) и69 (Cisco/noopenh264) сохраняются; поддержка H.264
заглушкой не добавляется. Полной повторной установки окружений не было.

Пакет com.termux, прежняя подпись, versionCode1284→1285. Формат данных не
менялся; пользовательские файлы не сбрасываются. Публикации на GitHub нет.
