# v1.5.10-test — explicit local-AI tool purposes

Private ARM64 APK, com.termux, versionCode1147, Android8+, same signing identity. No resets, history/settings/library migration, model-file changes or GitHub publication. Rounded chat pills from1.5.9 remain.

All13 descriptions in the LiteRT tool registry now distinguish when to use a function and what it does not do: directory listing vs reading, filename search vs web/content search, screenshot discovery vs visual inspection, saved chat history vs current file contents, and metadata inspection vs APK execution. Shared descriptions also reach Qwen Native and schema-based JSON instructions. Legacy JSON text instructions explicitly separate saving guides from shell execution.

write describes saving the complete requested document, with a Python-guide example that does not authorize installing Python. command describes actual requested Bash execution and routes documentation requests to write. install describes a supported dependency operation after explicit app APT-plan approval, not writing a guide. write.text and command.command carry the same distinction in parameter descriptions. listen_audio uses the shared description and remains limited to its first5seconds and actual model capability.

Descriptions are application-defined tool documentation, not a new command parser, phrase-triggered action, tool-choice filter, security policy or model training. Bash commands are generated by the model and depend on installed software; they are not a finite list learned by asking the model. All existing tool names, parameters, types, bounds/enums, availability and execution/permission/confirmation code remain unchanged. Tools only still omits extra behavior, but retains these function descriptions; custom behavior is not rewritten.

Clearer descriptions add service-input text relative to1.5.9. Measured estimates are recorded in validation; no claim of universal model obedience, speed improvement or exact tokenizer counts. This change is motivated by developer tests where Gemma selected installation instead of saving a guide even in a new chat with no prior history. Source/SDK tests verify delivery of the descriptions, not that the model will choose correctly.
