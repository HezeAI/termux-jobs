# Диктовка: устройство и Яндекс Браузер, 2026-11-07

**Проверка настоящей диктовки не завершена.** Текст с микрофона ещё не получен
в черновике Termux Job’s. Исправление раннего отказа и мок-результаты не заменяют это.
Пользователь уточнил: в Яндекс Браузере используется микрофон самой поисковой строки,
а не клавиатуры. Следующий согласованный шаг — штатное разрешение микрофона,
попытка запуска по умолчанию и точный код ошибки при отказе.

## Подтверждено на устройстве

Read-only запросы PackageManager и небольшой собственный app_process helper.
APK не устанавливались; системные настройки/разрешения не менялись.

| Проверка | Результат | Условия/границы |

Видимость пакетов **не объясняет полный отказ обнаружения** на текущем устройстве:
реальный API уже возвращает true и видит Claude. Для явной совместимости добавлен
только `<queries>` для `android.speech.RecognitionService`, без QUERY_ALL_PACKAGES.
[Контракт Android](https://developer.android.com/reference/android/speech/SpeechRecognizer)
требует такой запрос для приложений с targetAPI30+. Текущий target28 не повышался.

## Что установлено о браузере

Публичный установленный APK `com.yandex.browser`, version26.10.3.50/code1928119074,
проверен без чтения браузерной истории, аккаунтов, cookies или авторизации.
В нём есть `ru.yandex.speechkit.AudioSource`, `OnlineRecognizer`, `SpeechKit`,
`NativeVocalizer` и другие компоненты собственного речевого стека. Также присутствует
Chromium `SpeechRecognitionImpl` — другой путь, связанный с веб-платформой.

В манифесте строка `android.speech.RecognitionService` находится в **queries**,
а не в объявлении собственного provider-service. Службы с BIND_RECOGNITION_SERVICE
и реализации RecognitionService у браузера не найдены. То есть подключить его
поисковый микрофон как найденную системную RecognitionService сейчас нельзя.
Наличие SpeechKit в APK не доказывает точный runtime call-chain нажатия поискового
микрофона; он не трассировался и не перехватывался. Приватный API/ключи браузера
не извлекались и не используются приложением.

## Что изменено для следующей попытки

1506/test11: по нажатию сначала `requestPermissions(RECORD_AUDIO)`, затем после grant
`createSpeechRecognizer(activity)` и `startListening` по умолчанию. Список служб и
настройка Android больше не являются ранним блокирующим условием.
Код приложения не вызывает startActivity для Claude/Яндекса/другого распознавателя
и не меняет default Android. Поведение самой выбранной службы ещё не проверено.

При ошибке окно содержит фактический `SpeechRecognizer.onError: N (ERROR_NAME)`.
Синхронные исключения помечаются этапом `createSpeechRecognizer`/`startListening`.
Отказ системного разрешения — отдельный `PERMISSION_DENIED=-1`, без фиктивного
SpeechRecognizer-кода. В том же окне снимок перед запуском из **зарегистрированной Activity**:
буквальное значение voice_recognition_service, enabled/exported выбранной службы,
isRecognitionAvailable, RECORD_AUDIO, доступные компоненты. Если чтение не удалось,
показан класс ошибки; пустое значение не выдумывается.

Partial остаётся предпросмотром; final добавляется один раз только к неизменённому
черновику исходного чата. Нет автоматической отправки. Stop/cancel/фон/смена
владельца и поздние callbacks сохраняют прежнюю защиту. Служба по умолчанию может
обрабатывать звук по своим условиям; новый сетевой backend не подключён.

## Следующий шаг на телефоне

Установить1506 вручную, открыть нужный агентский чат, оставить короткий исходный
черновик и нажать микрофон. В штатном окне Android выдать доступ к микрофону.
Произнести контрольную фразу. Проверка завершится только после её появления
в исходном черновике без отправки и без потери прежнего текста.
Если запуск откажет, сохранить весь код/этап и снимок параметров из окна ошибки.
Тогда можно выбрать конкретное действие для найденного состояния. Единственный
найденный сейчас провайдер — ClaudeRecognitionService; его пригодность как обычной
диктовки не проверена, поэтому приложение не выбирает его автоматически.

## Неудачные/ограниченные измерения

Первый helper с эмулированным Process.myUid()==0 неверно показал permission=true
и получил ошибку attribution-package android. Этот permission-результат **не принят**.
Повтор с фактическим UID из /proc/self/status и PackageManager.checkPermission
для com.termux дал DENIED. Context attribution исправлен только в памяти helper;
никакого изменения Android settings/разрешений не было. Settings Provider отдельно
отклонил незарегистрированный IApplicationThread, затем null-thread; это ограничения
helper, а не отсутствие выбранной службы. Дальнейших обходов/эскалации не было.
D8 из старых build-tools не собрал helper с API35 stub (NPE); существующий локальный
D8/R8 8.9.35 собрал отдельный диагностический DEX. Toolchain APK/ELF не менялся.

Доказательства `.verification/dictation-device/`: runtime-probe.txt,
recognition-services-user0.txt, отдельные неудачные CLI/attribution измерения,
yandex-inspection.json/manifest/badging; helper-source/compile logs сохранены.
