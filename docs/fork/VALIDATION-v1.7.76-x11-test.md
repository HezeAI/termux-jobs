# v1.7.76-x11-test / code 1291

## Причина и исправление

Вход обычного терминала Void уже учитывал отсутствие Bash у OCI-образа. Пути X11 оставались на proot-distro login. В proot-distro 5 даже явная команда /bin/sh после `--` сначала оборачивается в оболочку пользователя из passwd; отсутствующий /bin/bash вызывает отказ до проверки или установки компонентов.

Для Void изменены три точки входа: x11-desktop.sh (проверка, установка, запуск и обслуживание), x11-programs.sh (проверка/каталоги/установка/продолжение/удаление/настройки браузера), x11-gpu.py (проверка библиотек выбранного гостя). Используется `run --work-dir /root` с прежней явной командой `/bin/sh`. Привязки, display 104, выбранное окружение и управление собственными процессами не изменены. Другие окружения остаются на прежнем login; выбор рендера и пакетов не менялся.

## Проверки

- Реальный ограниченный запуск команды чтения на телефоне: установленный proot-distro с `login` воспроизвёл ошибку; `run` завершился с кодом 0, ID=void, оболочка /usr/bin/sh. Компоненты не устанавливались. Доказательство: `.verification/x11-void-login/probe.json`.
- Установленный OCI manifest проверен: Entrypoint отсутствует, Cmd=/bin/sh. Поэтому `run` не добавляет стороннюю команду перед явно переданным `/bin/sh`.
- 50 Python-сценариев test_x11_void, test_x11_gpu, test_x11_desktop, test_x11_programs прошли. Регрессионная имитация proot-distro 5 отказывает каждому login Void и проверяет 16 вызовов run через операции X11 и программ; GPU-проверка отдельно проверяет точный argv. Оставшиеся окружения проверяются прежними сценариями.
- Bash syntax и git diff --check прошли. Проверены переходы check/install/run, повторная установка программ, обслуживание и ошибка дочернего процесса. Механизм остановки/guardian, другие сессии и данные не изменялись.
- APK и результаты сборки: `.verification/x11-void-login/`. Проверяются пакет, versionCode, ABI, подпись, ZIP, DEX/JNI, приватные маркеры и точный assets/native delta с v1.7.75.
