# OpenCode mini jobs2 — частные v1.5.11–12-test

**Исторический механизм:** с v1.5.13-test не включается в APK. Вместо него
используется Android chat; по запросу открывается официальный mini. Патч и
шаблоны installer/manifest сохранены в patches/. Packager теперь пишет только
в игнорируемый .verification/opencode-mini-jobs2-archive/.

Это отдельный frontend на основе OpenCode2.0.28, commit
026b106bc5d41b679ffc413264229c340871e4d3 (MIT). Он заменяет процесс штатного
`mini` для новых запусков OpenCode в приложении. Официальный `opencode serve`,
данные подключений, модели, авторизация и native chat ID остаются прежними.
Codex, Claude, Gemini и обычные терминалы этот frontend не используют.

## Размер и история

Штатный `--replay` объединяет восстановление истории при входе и resize.
Здесь история по-прежнему загружается при входе и переоткрытии после смены модели.
В v1.5.11-test изменение только высоты пропускало replay; изменение ширины
сохраняло штатное восстановление. Разработчик обнаружил смешивание текста ответа,
предыдущих сообщений и нижней панели после изменения размеров.

В v1.5.12-test адаптер задаёт `TERMUX_JOBS_DISABLE_RESIZE_REPLAY=0`: штатное
восстановление возвращено и для высоты, и для ширины. Двоичный jobs2 не менялся.
Проверка настоящего OpenTUI в PTY воспроизвела потерю блока последующего вывода
при отключённом восстановлении; со сбросом footer и replay блоки сохранились.
Это подтверждает опасность отключения replay, но не доказывает исправление всех
сценариев настоящего ответа OpenCode на устройстве. При клавиатуре может снова
быть видна повторная перерисовка истории; это известный компромисс ради порядка текста.

Android-стабилизация геометрии1.5.10, защита скрытой вкладки, подтверждения и записи
разрешений остаются. Нет повторной отправки текста модели, изменений прав или
inference для перерисовки интерфейса. Optional host параметр по умолчанию сохраняет
штатное поведение upstream. Jobs2 не равен историческому jobs1.

APK включает gzip tar `.bundle` (~77.3MB) с frontend177588520bytes и LICENSE.
Расширение защищает от распаковки `.gz` Android merge-assets. После первого запуска
появляется отдельный `.ai-control/opencode-mini-v2.0.28-jobs2/opencode-mini`;
его подготовка требует дополнительного места. Повторная подготовка проверяет hash
и использует файл повторно. Установка под flock, staging/rename атомарны;
повреждённый или неожиданный существующий frontend не перезаписывается молча.
Работающий официальный runtime не заменяется. Агент собирал/проверял файлы только
в репозитории; применение происходит при новом запуске из установленного APK.

## Разрешения и записи

Приложение читает native pending permissions только текущей OpenCode-сессии
через private0600 Unix socket и её авторизованный local server API. В карточке
предлагаются разовый ответ и отказ. Native request ID, неизменность полного запроса,
владелец сессии, повторный/конкурентный ответ проверяются перед POST native reply.
Неизвестные/сложные security scope, MCP и формы остаются в CLI. Постоянное правило
можно выбрать в штатном OpenCode; его нельзя называть «на эту сессию» — OpenCode
может сохранить такое правило для проекта. Full-access политика не меняется.

После native permission.replied frontend выводит компактную запись с идентификатором
`[O:xxxxxxxx]`. Она входит в native scrollback. Ответ не означает успешного исполнения
инструмента. Нажатие на строку открывает только соответствующую запись текущего чата,
не выполняет содержимое команды и не отправляет нажатие в CLI при touch mouse mode.

В Gemini аналогичная запись `[G:xxxxxxxx]` выводится внутри native группы инструмента,
включая shell/compact/обычные группы. Она появляется после успешного native callback,
а не по нажатию кнопки приложения. Ожидающая карточка пока остаётся overlay; после
совпавшего ack она скрывается. Некорректный ack не отображает выданное разрешение.
Записи о сессионных правах Gemini не выдают эти права заново после перезапуска.

Подробности сохраняются приватно по native chat ID, до200 записей/2MiB на чат,
атомарно с mode0600. Они могут содержать команды и пути, как native история агента.
Команды не добавляются в scalar status, пресеты или общий журнал. Для старых записей
за пределами лимита подробности могут быть недоступны. Внешнее удаление native чата
не гарантирует автоматическое удаление sidecar-записей. Для OpenCode записи tool
привязаны к stable part ID и восстанавливаются при повторном показе инструмента;
внесистемные запросы без tool source не гарантируют восстановление облачка при reopen.
Для старых CLI без новых hooks/старого frontend карточки не подделываются.

Codex/Claude проверены по текущим мостам: observer Codex и stdio-владелец Claude
пока не предоставляют приложению подтверждения native запросов. Они сохраняют
штатные CLI-меню; согласование общего оформления потребует отдельной интеграции.

## Сборка

Патч: `patches/opencode-v2.0.28-jobs2.patch`. Подготовить указанный upstream commit
внутри репозитория, применить patch и его зафиксированные зависимости. Системные
пакеты/общий SDK/установленные runtime менять не требуется.

В packages/cli:

```sh
OPENCODE_VERSION=2.0.28 OPENCODE_CHANNEL=latest bun run script/build.ts \
  --single --skip-install --skip-web-ui --outdir=/repo/.verification/jobs2/frontend
```

Затем из корня форка:

```sh
python3 scripts/package-opencode-mini.py \
  --binary .verification/jobs2/frontend/cli-linux-arm64/bin/opencode \
  --license .verification/jobs2/source/LICENSE
```

Packager обновляет `.bundle`, публичный JSON с hash/размером и hash в installer.
Generated bundle игнорируется Git; перед сборкой APK его надо получить этим способом.
Runtime использует поставленный рядом `agent-receipts.cjs` по явно заданному пути;
только собственный frontend получает этот путь и файл текущего чата. После изменения
опубликованного binary нужен новый immutable revision. Проверки и ограничения:
VALIDATION-v1.5.11-test.md.
