# 2.1.6-test9 /1530 — RTK jobs.1

## Результат

RTK OSS upstream1.1.0, отдельная ревизия jobs.1, runtime1.1.0-jobs.1.
Новая сборка подключена только к приватному test9. Стабильные update.json и релизы
не менялись. APK и компонент не устанавливались в рабочее окружение и не публиковались.

В «Лимиты и контекст» при обнаружении прежнего проверенного RTK1.1.0 появляется
«Обновить RTK». Перед установкой окно предупреждает о перезапуске работающего чата
для применения новой сборки. Автоматического перезапуска нет. Установка идёт в
отдельный каталог1.1.0-jobs.1; старый1.1.0 сохраняется. Выбор режима, статистика
и recall остаются в прежних каталогах чатов. Повторная совместимая установка
переиспользуется по версии/ревизии и SHA-256. Ошибка загрузки оставляет старую сборку.

До публикации архив встроен только в тестовый APK. Прогресс называется подготовкой
тестового RTK и считает реально прочитанные байты. GitHub URL загрузчика уже направлен
на отдельный будущий Release существующего HezeAI/termux-jobs-components. Публичное
скачивание проверят после разрешённой публикации; сейчас это не выдаётся за проверку сети.

Дата начала расчёта и прежние оценки скрыты только в интерфейсе. Файлы и счётчики
не удалены. Для смешанной истории краткая строка явно показывает измеренную часть;
неизвестные старые события не восстанавливаются предположениями и остаются в счётчиках.

## Точные измерения

Измеритель получает уже имеющийся буфер внутри RTK перед фильтрацией и окончательный
вывод после неё. Он не запускает команду повторно, не меняет фильтры, stdout/stderr,
коды завершения, hooks, сохранённые правила или механизм восстановления.

Покрыты общий захваченный runner (ls/wc), обычные git status/diff/log, diff --stat,
захваченные grep/rg и списки rg --files, полное чтение, выбранные head/tail окна.
Для diff исходная база не включает дополнительный stat-заголовок. Штатные служебные
вызовы Git сохранены: в проверках status/diff имели2 вызова у обеих сборок, log/поиск1.
Для git log исходный буфер имеет формат и лимит, уже выбранные самим RTK; стандартный
формат отдельного git log и неограниченная история не реконструируются.

Проверенные примеры, байты:

| Команда | До | После |
| --- | ---: | ---: |
| rtk git status | 1220 | 500 |
| rtk git diff | 32440 | 10171 |
| rtk git diff --stat | 2496 | 2496 |
| rtk git log -n 4 | 7603 | 864 |
| rtk grep needle f000.txt | 766 | 475 |
| rtk grep NO_SUCH_NEEDLE f000.txt | 0 | 0 |
| rtk read read.rs | 5280 | 5280 |
| rtk read read.rs --level minimal | 5280 | 2158 |
| rtk read read.rs --head-lines 5 | 141 | 141 |
| rtk read read.rs --tail-lines 5 | 124 | 124 |
| rtk rg needle . | 32640 | 6085 |
| rtk rg --files | 728 | 728 |

Дополнительно ls4410→1056; head5 25→25 (0%); recall600 байт отдельно.
Сохранение файла восстановления не считается передачей модели. Сопоставление с
PostToolUse проверяет профиль/run, аргументы и хеш реально возвращённого текста.
Повторный просмотр истории не удваивает счётчики. Законченные служебные измерения
сохраняются отдельно от очереди, чтобы не перечитывать всю историю на каждом действии.

Неизвестная база остаётся для потоковых/сложных путей без измерителя, find через
генерацию файлового списка, специальных raw-shape ветвей git log, чтения с одновременно
заданными фильтром/номерами/окном, невалидного текста, неоднозначных или изменённых
результатов. В настоящем Codex длинный read был обрезан CLI до10106 байт: база честно
неизвестна. Короткое полное чтение, head и чтение через Claude сопоставлены точно.
Байты не подменяются размером файла или recall. Штатный rtk gain остаётся оценкой
токенов upstream; точные байты — отдельный протокол. Токены в UI — только оценка.

  работающий бинарник, сохранение режима/счётчиков/recall, ошибку сети и повторное использование.
- 3 проверки семейств Lite: stdout/ошибки и коды0/1/2/17/128 сохранены.
- 12 JVM тестов интерфейса/статистики/запуска; полный Modern Lint всех5 модулей:
  0ошибок,290предупреждений. Java/XML входы финального APK совпадают с проверенными.
- Native CLI Codex0.166.0 и Claude2.1.296, локальный фиктивный провайдер и сетевой guard:
  12 парных сценариев ls/recall/head/Git/поиск/чтение и Codex untrusted с отказом.
  Статистика совпала с телами результатов в запросах провайдера; второй чат не изменён.
  Проверенные режимы: Codex danger-full-access/never и untrusted; Claude SDK manual/default.
  Это не проверка настоящей облачной модели или остальных режимов прав.

  в графе сборки. Лицензии и copyright Rust std сохранены отдельно от точных исходников.
- Финальный APK: ZIP, подпись, package/version, ABI, non-debuggable, DEX/runtime,
  assets/source match и встроенный архив/внутренний ELF проверены. SHA копии Download совпадает.

Legacy lintVitalRelease печатает несовместимость Kotlin metadata; его не считали
успешным Lint. Современный Lint выполнен отдельно. Изолированные проверки не заменяют
проверку интерфейса и обновления APK на телефоне.

## Исправленные отказы проверки

AAPT распаковал и переименовал asset .tar.gz; тестовый ресурс получил имя .bin с
неизменёнными gzip-байтами. На готовом APK проверены имя и хеш. В PRoot флаг
O_NOFOLLOW не защитил синтетический симлинк. Создание заменено на create_new с
проверкой существующего пути и удержанием дескриптора. Проверены симлинк, подмена
имени после открытия, несколько захватов и Unicode/пустые/1MiB варианты нормализации.
Пользовательские данные не затронуты. Неисправные кандидаты не выдавались; доказательства
сохранены в rejected-sidecar/ и apk/*.pre-*. Начальный тест обновления имел конфликт
имени fixture с полем базового теста; исправлен и повторён успешно.
