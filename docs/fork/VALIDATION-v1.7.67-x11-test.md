# Частная v1.7.67-x11-test / code1282

## Исправление записей сессий

Подтверждена старая запись Codex: saved=false, handle пуст, окружение ubuntu.
Она отсутствовала в пресетах, но блокировала удаление. Настройки прочитаны
штатной фоновой командой Termux; рабочая библиотека не редактировалась извне.

Новый несохранённый профиль регистрируется только при создании терминала,
а не перед асинхронной проверкой/подготовкой. Ошибка создания откатывает новую
пустую регистрацию. Пустые несохранённые записи, загруженные при открытии
приложения, убираются при первой сверке с подключённой службой Termux.
Сохранённые пресеты и базовая сессия остаются. История пустых старых записей
не удаляется. Новые черновики после открытия не считаются старыми записями.
Проверка удаления окружения больше не принимает пустую несохранённую запись
за действующую привязку. Сохранённые/прикреплённые записи, текущая проверка
живых процессов и native remove-lock сохраняют защиту. Перед фактическим
созданием терминала повторно проверяется занятость среды миграцией/удалением.

## Докачка окружений

Новый environment-download.py вызывается только в подпроцессе явной установки.
Установленные модули proot-distro не переписываются. Для Python proot-distro5
с проверенным API сначала получаются и проверяются все OCI-слои через штатный
resolver/cache; распаковка на этом проходе не выполняется. Затем отдельный
штатный install использует проверенный кэш. Старый shell proot-distro4 пока
использует прежнюю установку без новой докачки.

Один приватный .part на SHA-256, блокировка отдельного alias; Range/206
проверяется по Content-Range. При200 после Range файл перезаписывается на месте,
при416 неполный файл начинается заново. Обрыв/Стоп сохраняет записанные байты.
SHA-256 проверяется полностью перед публикацией. Обычно проверенный inode
атомарно переносится в штатный cache без копии; при разных ФС возможна
временная atomic copy с повторной проверкой хеша, затем исходный partial удаляется.
Готовые OCI-слои переиспользуются в штатном кэше proot-distro, дополнительного
постоянного кэша завершённых образов нет. После успешной установки удаляются
наши partial/state; остаётся один пустой lock для alias. Штатный кэш proot-distro
можно обслуживать штатными средствами — автоматически он не очищается.

Токены и signed redirect URL в state не записываются. Допускаются только
закреплённые image refs известных окружений и проверенный Arch ARM URL/hash.
Используется штатный проверяющий TLS opener proot-distro со снятием Authorization
на чужом redirect origin. Подписи/хеши/защита путей штатной распаковки не обходятся.
Кнопка «Продолжить» восстанавливается по приватному state после открытия окна
или приложения. Активный Стоп остаётся заблокированным до конца остановки.

Это продолжение загрузки, а не транзакционный откат распаковки. Если принудительное
завершение оставило rootfs во время установки, он не заменяется/не удаляется
автоматически: UI объясняет необходимость явно удалить неполную среду; скачанные
данные остаются. При наличии этого состояния доступна корзина неполной среды.
Программы/X11-пакеты этим новым загрузчиком не обслуживаются.
