# Проверка v1.3.3 — обязательное обновление

## Причина

Два отчёта разработчика на Android16 показывают NoClassDefFoundError для
com.google.common.io.RecursiveDeleteOption: TermuxService.onDestroy →
clearTermuxTMPDIR → FileUtils.clearDirectory и CrashUtils.notifyAppCrashOnLastRun →
moveRegularFile → deleteFile. В DEX1.3.2 есть ссылки, но отсутствуют определения
MoreFiles и RecursiveDeleteOption. Новая проверка APK воспроизводимо отклоняет1.3.2.
Несогласованные Guava24.1-jre/33.3.1-android существовали до этого выпуска.

## Исправление

Оба модуля и транзитивные запросы Media3 согласованы на Guava33.3.1-jre.
Штатный FileUtils не переписан: diff относительно1.3.2 отсутствует.
Минимум Android8.0/API26 принят разработчиком: современная JRE Guava использует
MethodHandle.invoke, несовместимый с minAPI24. Собственная замена удаления файлов
не включена в финальный APK. Версия1.3.3/code1086, com.termux, прежний сертификат.

## Тесты и аудит

440 JVM-тестов: ошибок/пропусков0. Три новые проверки выполняют реальные файловые
операции в изолированных временных папках: очистка с сохранением корня, замена
существующего crash-log, удаление дерева без удаления целей символьных ссылок и
отказ очистки обычного файла. Проверяются ветви API26/28 под Robolectric28;
это не тесты на реальных устройствах Android8/9. Для lstat/stat используется
тестовый адаптер к реальной файловой системе: старый Robolectric иначе сообщает
о наличии уже удалённого файла.

Дерево releaseRuntimeClasspath получено: все запросы Guava, включая Media3,
разрешаются в33.3.1-jre; неразрешённых зависимостей нет.

Новая задача preBuild проверяет классы в реальном debug/release runtime Guava,
а scripts/verify-apk-runtime.py проверяет определения во всех classes*.dex.
Инвентаризованы ссылки на типы всего APK относительно compileSDK35. Отдельно
учтены OEM Window extensions/sidecar, метаданные, скрытые API Android и опциональные
JVM API библиотек; любое новое неизвестное отсутствие останавливает проверку.
Guava AnnotatedType встречается только в Invokable/Parameter, не используемых
проектом: это не обещание общей Android-совместимости Guava reflection API.
Проверка наличия классов не доказывает все связи методов и рефлексивные вызовы.

Финальный APK: Termux-Jobs-v1.3.3-arm64.apk, 36613450 байт.
SHA-256: `72ef607dc8d1005abeeefa014ae985ec107394fc63fe8850d60e0335227592a7`.
Сертификат: `dd37d983cd2496ebe49c7e88ddbc0088f311d38b8a8503e4392c81b48a11a644`. APKv2 проверена.
Проверены ZIP CRC, пути,
package/version/minSDK/targetSDK/ABI/debug, подпись, выравнивание, соответствие
production Java/resources/assets staging, ограниченные сигнатуры секретов.
Native/bootstrap и серверный агент не меняются. Исправлено удаление устаревших
Java-исходников из staging перед копированием. Нет изменений схем данных,
автоочистки пользовательских данных, установки пакетов или управления процессами
пользовательских сессий. Существующие тесты охватывают терминал, библиотеки,
серверные операции, бэкап/обновления, AI и редактор; это не исчерпывающая проверка UI.

## Проверка разработчиком после обновления

Нужны повторный запуск после сбоя и корректное завершение/запуск приложения,
работа терминала и Ubuntu, сохранность библиотек и авторизации. Android IME,
жесты, OEM-поведение и все варианты восстановления/сети не подтверждаются JVM-тестами.
Исходные crash-log сохранены пользователем. Переустановка и очистка данных
не требуются. Обновления для Android7 прекращаются, что указано в RU/EN metadata.

Доказательства: .verification/crash-v1.3.3. Предварительные варианты и неуспешные
попытки оставлены в отдельных логах; итоговые результаты относятся к финальному APK.
