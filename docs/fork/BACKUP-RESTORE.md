# Локальное исправление OpenCode после test5

**В выданном test5 исправления ещё нет.** Новый локальный код добавляет отдельный
компонент `opencode-connections.tar.gz`, только когда выбраны библиотека приложения
и отдельный пункт «Данные подключений OpenCode». Этот пункт по умолчанию выключен.
Без него профили сохраняются, но авторизация, история и состояние подключения
не переносятся. Обе формы предупреждают об этом до экспорта.
Включаются подключения, на которые ссылаются её профили; посторонние старые
каталоги подключений не собираются автоматически.

Полный набор зависит от явного выбора в форме:

| Выбор | Состав |
| --- | --- |
| Библиотека | `workspace-v1.json`: команды, Alias, заметки, пресеты и записи библиотеки; `settings.json`: язык, ввод, настройки Termux; `app-data.tar.gz`: дерево `workspace-sessions`, если существует. Произвольные строки команд и история могут содержать секреты. |
| Данные подключений OpenCode | Отдельный `opencode-connections.tar.gz`; подробный состав ниже. Требуется отдельное согласие, библиотека сама его не включает. |
| HOME | Файлы выбранного Termux HOME, включая dotfiles, проекты и находящуюся там авторизацию. |
| PREFIX | Файлы Termux PREFIX без `tmp` и `var/lib/proot-distro`; rootfs выбираются отдельно. |
| Linux-окружение | Штатная копия выбранной rootfs, включая находящиеся внутри неё файлы, проекты и авторизацию. |
| Выбранные данные | Только выбранные группы/папки соответствующей среды; их перечень показывается перед созданием. |

Служебные файлы: `manifest.json`, `SHA256SUMS`, `README-RESTORE.txt`,
`restore.sh`, `backup-tool.py`; `packages.txt`, если доступен dpkg-query.
Настройки X11, обновлений, сортировки файлов и профили серверов не входят
в основные настройки. Android Keystore не переносится. Это не обещание
восстановить действующий вход из сохранённого зашифрованного значения профиля.
Другие файлы авторизации могут входить через выбранные HOME/rootfs/папки,
даже когда отдельный пункт OpenCode выключен.

| Часть подключения | Что сохраняется и какие секреты возможны |
| --- | --- |
| `config` | Настройки провайдеров/моделей, API-ключи и другие заданные параметры, плагины, команды и hooks. |
| `data` | Данные native CLI: авторизация, SQLite-история, сообщения, результаты инструментов, журналы, внутренние снимки файлов проектов и другие постоянные файлы. В проверенном OpenCode 2.0.28 действительно созданы `data/opencode/opencode.db`, `log` и `snapshot`. |
| `state` | Сохранённые параметры и состояние CLI; состав зависит от версии CLI и тоже может содержать приватные сведения. |
| `session-links` | Связи сохранённых app session aliases с native session ID; нужны для продолжения того же диалога. |
| `receipts` | Квитанции прежних решений и сведения о действиях/времени; команды и результаты могут содержать секреты. Это история, не разрешения на выполнение. |

Не включаются отдельный верхний каталог `cache`, текущие процессы и служебные
файлы вне перечисленных частей. Символические ссылки и специальные файлы внутри
компонента отклоняются; их внешние цели не читаются. Проекты, внешние credential
файлы и вложения вне этих каталогов выбираются отдельно. При этом копии содержимого
проектов или изображений могут уже находиться внутри native истории/снимков и тогда
войдут в `data`. Нельзя считать исключение проектной папки удалением её следов из
истории. Сам исполняемый CLI и Ubuntu AI этим компонентом не устанавливаются.

Архив **не зашифрован**. В обеих формах RU/EN предупреждение перечисляет ключи,
токены, историю, логи и внутренние снимки проектов. Перед запуском восстановленной
конфигурации нужно проверить адреса провайдеров, плагины и команды: контрольная
сумма проверяет целостность, а не доверие к автору архива. Восстановление само
по себе не запускает команды, плагины или сессии.

При наличии компонента новый manifest имеет **version 3**. Новый reader продолжает
читать прежние версии **1 и 2**; это проверяется архивами, созданными helper-ом из
неизменённого APK v2.1.2. Старый reader отказывает для version 3 вместо молчаливой
потери подключений. Без этого компонента прежние форматы создания сохраняются.

Для переноса выберите компонент OpenCode и импорт пресетов. Сначала данные
извлекаются в новую папку. Затем импорт готовит приватную копию и публикует её под
новым connection UUID, связывает с новым ID пресета и сохраняет профиль. Несколько
пресетов одного подключения сохраняют общую новую копию; повторный импорт получает
другой UUID. Существующие подключения не заменяются. Старый архив без компонента
остаётся пригодным к импорту, но OpenCode понадобится настроить отдельно. CLI
авторизация может истечь или потребовать нового входа; Android Keystore не переносится.
Standalone restore только извлекает данные; связывание выполняет импорт приложения.

SQLite копируется онлайн по отдельным базам с учётом WAL; сам WAL/SHM не переносится
вместо согласованного снимка. Это не атомарный снимок всех файлов приложения:
задачи, меняющие файлы, следует закончить самостоятельно. Экспорт не останавливает
процессы. Ошибки/отмена не подменяются успешным завершением.

Проверки и ограничения: A-BACKUP-02 в [аудите](SECURITY-AUDIT-STAGE2.md).

Архивы остаются незашифрованными и могут содержать другие секреты из выбранных
папок. Подтверждение состава на фикстурах не заменяет проверку восстановления.
Подробности, охват и предложение исправления: A-BACKUP-02 в
[аудите](SECURITY-AUDIT-STAGE2.md). В опубликованном v2.1.2 и выданном test5 исправления нет; локальное исправление
описано выше.

## v2.0.1: restored preset and history identity

Restored presets always receive independent IDs. Matching names/settings do not
merge them with existing presets, so per-preset histories remain attached to the
restored copy. Repeating an import intentionally creates further preset copies;
review or delete unwanted copies through the normal UI. Command/note merge rules
and explicit replacement of inactive presets are unchanged. Saved preset content
is checked in addition to ID presence before reporting successful restoration.
Existing histories are not overwritten. Previously orphaned histories are not
automatically reassigned or deleted: their correct owner cannot be inferred.

# Проверка Linux-окружений — 1.6.18-test (не опубликовано)

В1.6.15 исправлены PAX path/linkpath при переименовании архивов: длинные пути
теперь также получают новый alias. В1.6.14 реальное восстановление Debian
останавливалось на первом таком пути; исходный архив не повреждён и пригоден
для повторной проверки. Неудачная операция могла оставить частичный jobs-*.
Путь HOME в плане относится к отчёту/staging; полная Linux-система размещается
в штатном proot storage отдельно от исходной.

Создание бэкапа выбирает конкретные proot aliases; полное восстановление создаёт
новый jobs-* вместо замены работающей среды. Linux-файлы/passwd сохраняются,
OCI-манифест пересоздаётся из минимальных настроек (пустой Entrypoint, /bin/sh,
Linux PATH, корень /). Чужие команды/переменные/источник образа не импортируются.
Это позволяет восстановленному sh-only Void использовать native run без Bash;
исходная система не меняется. В плане восстановления есть пояснение RU/EN.
Запуск реальной восстановленной среды ещё проверяется разработчиком.

Полная система содержит установленные пакеты. Сравнение/план APT в интерфейсе
относится только к пакетам Termux и не смешивает с ними Linux-гостей.
Для других менеджеров отдельное сравнение пока не добавлено.

Первая проверка: создать бэкап только Debian, сохранить целую папку, проверить
manifest.json, восстановить Linux-компонент в новый экземпляр. Сравнить тестовый
файл, tree --version и файловый менеджер; проверить сохранность исходного Debian.
Затем остальные окружения, особенно Void без Bash. См. ENVIRONMENTS.md и
VALIDATION-v1.6.18-test.md. Результаты автоматических тестов не подтверждают
работоспособность полного переноса реальных данных.

# v1.5.3: inventory and compression

Full and Custom backup use title-right Refresh with an inline spinner and one
current-file/bytes status line. Refresh always rescans; repeated entry may reuse
bounded process-memory estimates. Creation still reads sources freshly and
validates the archive. Closing cancels only this inventory worker. Components
and destination survive refresh, while creation consent must be given again.

Compression method: gzip1 worker / pigz2 / pigz4; level below:1/3/9.
Missing pigz offers explicit installation approval. All produce .tar.gz.
Legacy proot-distro full Ubuntu keeps native compression with a warning.
A missing selected full environment stops creation rather than being omitted.
Previous backup formats remain supported. Cache is neither a filesystem snapshot
nor a substitute for source/SQLite/symlink/space/integrity checks.

## Создать свою копию

Выбор: библиотека команд/заметок/пресетов и настройки; файлы истории терминальных
сессий; HOME; PREFIX; установленные Ubuntu/proot отдельно. Каталог назначения
должен существовать и быть доступен приложению (по умолчанию Download).
Каждый запуск создаёт каталог с временем и случайным суффиксом, старые не заменяет.
Предварительно оцениваются объём и свободное место. Сбор выполняется отдельным
worker, окно показывает этап/обработанные байты; операции можно отменить.

HOME включает пользовательские dotfiles, SSH, CLI-авторизацию, проекты и скрипты,
если они физически внутри HOME. Ubuntu сохраняется штатным `proot-distro backup`;
в неё входят /root/.codex, история CLI, проекты, инструменты и другие файлы,
расположенные внутри выбранной rootfs. PREFIX сохраняется без tmp и всего
var/lib/proot-distro: rootfs выбираются отдельно, образные/build-кеши proot-distro
в PREFIX-копию не входят. Список пакетов Termux записывается отдельно.
Символические ссылки хранятся ссылками, **внешние цели не обходятся**. Файлы
Android shared storage за пределами выбранных деревьев не копируются.

Живые сокеты, устройства и FIFO не архивируются. Копия работающей базы не является
атомарной: завершите изменяющие файлы задачи перед запуском и подтвердите это.
Процессы и память не сохраняются. Современный proot-distro может самостоятельно
нормализовать права rootfs при штатном backup; это поведение upstream-инструмента.
Секреты не шифруются: храните каталог офлайн и защищённо. Общая память Android
не обеспечивает POSIX-права приватности; метаданные хранятся внутри TAR.

Состав: manifest.json, выбранные TAR.GZ/JSON, packages.txt (если доступен dpkg),
SHA256SUMS, README-RESTORE.txt, restore.sh и автономный backup-tool.py.
После записи проверяются содержимое TAR, SHA-256 и сжатый поток. Незавершённые
каталоги сохраняют INCOMPLETE и не считаются готовыми.

## Выбранные данные (v1.1.1)

Создать → «По выбору». Для Termux и каждой Ubuntu доступны раскрываемые
списки. Разделение покрывает найденные стандартные пути Codex/других агентов,
SSH/Git, shell/скриптов, верхние пользовательские каталоги, известные кеши и
сборочные каталоги, остальные пользовательские данные и систему. Нестандартная
установка CLI может находиться в «Остальные файлы» или пользовательской папке:
само обнаружение не гарантирует комплектность любого стороннего агента.

Добавление папки ограничено подпапками пользовательского HOME выбранной среды.
Ссылки на внешние пути не обходятся. Для Ubuntu интерфейс ориентирован на /root;
остальные /home включены в «Остальные пользовательские файлы». Размеры считаются
по файлам до сжатия, без двойного учёта: более точный выбранный путь имеет приоритет.
Каталоги .tools/.verification/build/target/.gradle в найденных проектах отделены в
«Инструменты, кеши и результаты сборок»; можно выбрать такой каталог явно.

«Система» Ubuntu содержит базовые файлы/установленные зависимости, без выбранных
по отдельности пользовательских компонентов. В комбинации с Codex получается
единая rootfs для отдельного alias. Полная копия через штатный backup proot-distro
остаётся прежним режимом; выборочная rootfs собирается нашим помощником, затем
проходит те же проверки/перепаковку и штатный proot-distro restore.

Без системы выбранные данные не являются самостоятельным окружением: TAR с
корнем payload, manifest v2, отдельное извлечение. Файлы внутри payload относительны
корню Ubuntu или files/ Termux (home/ и usr/). Текущие файлы не активируются поверх.
В результате есть README-SELECTED.txt. Сначала подготовьте окружение/runtime,
остановите целевой ассистент и проверьте файлы, затем переносите вручную с сохранением
исходных данных. Восстановление в существующую активную .codex не автоматизировано.

Перед созданием есть подтверждение состава, предупреждение об отсутствии системы,
Node.js и файлов проектов, возможность добавить систему. При импорте окружения и
наличие Node.js/Git/SSH проверяются заново на принимающем устройстве, без запуска бинарников.
Наличие файла Node.js не подтверждает его версию/работоспособность. Подсказки по
установке не выполняются. Автоматической установки Node.js/Ubuntu/пакетов нет.
Несовпадение/неизвестность архитектуры выбранных данных требует переустановки
бинарников; отдельное извлечение данных допускается. Для Ubuntu с системой
по-прежнему обязательно подтверждение архитектуры по ELF.

SQLite в выбранной .codex сохраняются через online backup и quick_check отдельно
для каждой базы; WAL/SHM/IPC/блокировки/временные shell snapshots исключаются.
Остальные файлы копируются «живыми»: связи между базами и JSONL не атомарны.
Чаты не содержат файлы проектов. Авторизация может потребовать повторного входа.

**Manifest v2 нужен только для выбранных данных.** Новый клиент читает v1/v2;
старый клиент v1.1.0 откажет в импорте v2. На втором телефоне нужна v1.1.1 или
доверенный restore.sh из этого нового бэкапа. Изменения формата библиотекиv8 и
сброса пользовательских данных нет. Реальное восстановление на телефоне проверяет
пользователь; тесты на фикстурах не заменяют эту проверку.

## Проверить чужой бэкап

Выберите файл или введите доступный путь. Поддерживаются:

- Наш manifest.json версии1 и workspace-v1.json с библиотекой версий1–8.
- TAR/TAR.GZ/TAR.BZ2/TAR.XZ с HOME/PREFIX под home/, usr/ либо стандартными
  относительными data/data/<package>/files/{home,usr}/ и data/user/0/… путями.
- Bare HOME с распознаваемыми shell dotfiles; bare rootfs с etc/os-release и bin/usr.
- Старый proot installed-rootfs/<alias>/ и новый <alias>/rootfs/ формат, включая
  rootfs внутри полного PREFIX. Другие произвольные форматы форков не обещаются.

ZIP, зашифрованные архивы, абсолютные TAR paths и неподдерживаемые layouts не
распаковываются автоматически. Для raw-чужого TAR нет доверенного исходного SHA:
вычисленная сумма позволяет отследить последующие изменения, а не подлинность.

Проверка читает архив потоково без извлечения/запуска. Проверяются пути, дубли,
попытки записи через символические ссылки, лимиты и целостность компрессии.
Компоненты собственного manifest сверяются с hash/size; изменение файла после
проверки требует нового анализа. Перед извлечением выбранные архивы копируются
в приватное рабочее место и повторно сверяются. Нужен запас места для копии,
извлечения и перепаковки Ubuntu; оценка намеренно консервативна.

Совместимость Ubuntu подтверждается по ELF-архитектуре, а не имени архива.
Неизвестная/другая архитектура блокирует установку rootfs. Для регистрации отдельной
Ubuntu в этой бете нужен современный Python proot-distro; старый shell runtime
может создавать копии, но автоматический импорт rootfs в него заблокирован.
Различия package ID/путей не делают PREFIX переносимым: он только извлекается для
проверки, никогда не заменяет работающий PREFIX. HOME переносится как файлы;
встроенные бинарники и жёсткие пути могут требовать исправления.

## Выбрать и восстановить

Окно выбора показывает компоненты и результат проверки. Нужно отдельно подтвердить
доверие и план; ничего не применяется при простом выборе файла или просмотре.

- HOME/PREFIX/app-data извлекаются в **новую** подпапку выбранного каталога внутри
  Termux HOME. Существующие файлы не объединяются/не перезаписываются. Дальнейшая
  активация HOME/PREFIX остаётся ручной: слепого восстановления работающей среды нет.
- Ubuntu перепаковывается только из rootfs под новым jobs-<id>, затем используется
  штатный restore. Чужие host config scripts/manifest-команды не выполняются.
  Существующий alias не заменяется. Создаётся пресет `proot-distro login --isolated
  '<alias>'`: нет добавленных общих проектных bind-папок. Это не защитная VM;
  процессы всё равно работают с Android UID приложения.
- Библиотеки: выбор команд/заметок/пресетов, объединение или замена выбранного
  списка; точные дубликаты пропускаются. Активные сессии и базовый Terminal не
  удаляются при замене пресетов. Перед импортом библиотека сохраняется в
  files/workspace-import-recovery/before-<uuid>.json.
- Все профили получают новые идентификаторы/IPC-сокеты, без live handles и
  непереносимого зашифрованного SSH-пароля. При первом запуске импортированного
  пресета открываются настройки для проверки среды/команд/путей. Его нельзя
  автоматически считать привязанным к новой Ubuntu; она имеет отдельный пресет.
- Файлы истории импортируемых пресетов можно перенести при выборе app-data.
  Это история оболочки, а не восстановление процесса с места остановки.
- Простые статические `alias name='body'` распознаются чтением .bashrc/.zshrc/
  .bash_aliases; выбранные раскрываются в сохранённые команды. Не выполняются
  source/eval или динамические определения. Скрипты .sh добавляются как команды
  запуска только после выбора восстановления соответствующих файлов.
  Bash/Zsh history автоматически не превращается в библиотеку команд.
- Настройки интерфейса импортируются отдельно; для части изменений нужен новый
  запуск приложения. Android Keystore, APK-разрешения и живые процессы не переносятся.

Операции компонентные, не транзакция всей среды. При ошибке/отмене новая папка
может содержать частичный результат с INCOMPLETE; существующие среды не заменяются.
После успешного извлечения, но неудачного импорта библиотеки, проверяйте каталог
результата и recovery-копию. Не удаляйте исходный бэкап до проверки работы.

## Пакеты — отдельный раздел проверки

Сравниваются только пакеты Termux из packages.txt/его dpkg status с локальным
`dpkg-query`; статус вложенной Ubuntu не смешивается с Termux. Показываются
различающиеся/отсутствующие версии. Список без версий доступен для просмотра,
но не для точной замены. Пакеты отдельно восстановленной Ubuntu уже внутри rootfs.

Выбор отдельных пакетов, всех различий (до200 за план) либо ничего. `apt-get -s
--no-remove install -- name=version …` получает предварительный план без установки,
без обновления индекса и без установки пакетов во время анализа архива. Недоступные
версии/конфликты отображаются в APT-ответе, кнопки установки при ошибке нет.
После отдельного подтверждения открывается новый Termux-терминал с обычным APT;
он снова запрашивает подтверждение, и его актуальный план нужно перечитать.
Общая среда Termux и зависимости могут измениться — завершите важные задачи.

## Ограничения тестирования и проверка

До500000 TAR entries,512GiB payload; JSON-метаданные/библиотека до8MiB,
до100 компонентов и500 распознанных aliases/скриптов; выбор APT до200 пакетов.
Права/mtime сохраняются где возможно, владелец — текущий Android UID, setuid/setgid
не восстанавливаются. Большие/неподдерживаемые метаданные блокируются.

обычном Termux требует Python/proot-distro и сначала показывает выбор компонентов;
он также извлекает HOME/PREFIX отдельно. Не запускайте скрипты чужого бэкапа.

пользовательские проверки на тестовой копии, включая Python/proot версии, свободное
место, Android storage permissions, историю и авторизацию после восстановления.

Для долгого копирования держите приложение открытым: отдельного foreground
service/wake lock и докачки нет. Выгрузка Android может оставить INCOMPLETE.
ACL/xattrs/SELinux labels не являются переносимым состоянием этой беты.

## Исправления локальной v1.1.2

При инвентаризации недоступные пути показываются в карточке окружения (до8 в UI,
до100 в отчёте). Затронутые компоненты имеют неполный размер и отключены,
включая компоненты, которым нужен недоступный родитель. При переполнении списка
ошибок весь scope считается неполным. Другие группы можно выбрать. Ошибки при
создании выбранного архива не игнорируются; частичная копия остаётся INCOMPLETE.
Никакого автоматического chmod источников в режиме «По выбору» нет.

Служебная .l2s proot не архивируется отдельной группой. Ссылки на её поддерживаемые
backing-файлы копируются обычными файлами; источники не переписываются. Обычные
символические ссылки не разыменовываются. Разрешённые backing-файлы ограничены
внутренним .l2s или каталогом исходного файла и marker-префиксом proot; открытие
идёт относительно rootfs с O_NOFOLLOW, не допускает подменённого предка-ссылки.
Точная причина недоступности конкретного каталога в исходной среде в старом сообщении
не была сохранена; новое окно показывает путь, а не обещает устранение любых
проблем прав. Нужна проверка пользователя в той же среде.

В полной форме и финальном подтверждении «По выбору» создание недоступно до
согласия; снятие галочки снова отключает кнопку. В обеих формах над полем пути
написано «Папка создания резервной копии», затем кнопка выбора каталога.

## Локальная v1.1.3: прогресс и сжатие (тестирование)

Окна резервного копирования, проверки, восстановления и все их подменю не
закрываются нажатием за рамками. Явная отмена/Back сохранены; отмена операции
оставляет INCOMPLETE. Установка pigz отдельно не отменяется кнопкой бэкапа.
Таймер показывает прошедшее время, не оценку окончания. Имя текущего файла/каталога
сменяется в одной строке. Полоса относится к текущему этапу: процент только при
известном полном объёме. Сканирование и native proot используют неопределённую
полосу; у native потока показывается прочитанный объём, не придуманный процент.

В обоих режимах создания: gzip либо pigz и уровни 1 (быстро), 3 (сбалансировано),
9 (компактно). По умолчанию gzip3. Оба создают обычный .tar.gz, восстановлению
pigz не нужен. pigz использует до4 потоков, повышает нагрузку и нагрев; ускорение
ограничено накопителем и обходом файлов. Отсутствующий pigz можно установить
по отдельному подтверждению: фиксированный apt-get install -y pigz в общей среде
Termux, возможны зависимости. Рабочие сессии не получают команды установки.
Оставьте приложение открытым до её завершения: это фоновый worker, не foreground
service. Другие операции APT могут вызвать отказ; блокировки не обходятся.
При ошибке gzip остаётся доступен. После успеха проверяется executable и выбирается
pigz. Установка пакета не запускается лишь при открытии окна или чтении архива.

Современный proot-distro сохраняет Ubuntu поддерживаемой командой backup
--compress none в stdout, затем поток сжимается выбранным способом без временного
несжатого TAR. Legacy proot-distro использует прежний backup --output и своё
сжатие независимо от выбора: это ограничение явно описано в форме.
Manifestv1/v2 и libraryv8 не менялись. Итог создания: «Бэкап создан и проверен»
и путь. Для безопасного переноса нужна вся папка бэкапа, включая manifest и helper.


Alpine с1.6.16: архитектура определяется также по regular BusyBox ELF, поскольку
sh/env обычно ссылки. Ограничение совместимости не отключается; повторно создавать
ранее сделанный полный архив не требуется. Восстановление/повторный старт Debian
и Void подтверждены разработчиком; Alpine пока прошёл исправленную inspect-проверку.


Arch/systemd с1.6.17: штатные буквальные hex-escape имена файлов допустимы и не
декодируются. Старое создание могло оставить INCOMPLETE без manifest.json —
для проверки полного создания повторите бэкап только Arch в новой папке.
Чужой архив по-прежнему требует проверки структуры/ссылок и подтверждения.


С1.6.18: в новую восстановленную rootfs добавляется пустой private .l2s, если его
нет в архиве. Это подготовка transient runtime store для proot link2symlink;
права readonly корня (например Arch0555) сохраняются. File/symlink вместо каталога
отклоняются. Существующие работающие экземпляры автоматически не меняются.

### Состав, предупреждение и формат

Только при выборе библиотеки **и отдельного выключенного по умолчанию пункта**
«Данные подключений OpenCode» `workspace-backup.py.opencode_sources/create_opencode_tar`
добавляют отдельный компонент `opencode-connections.tar.gz`. Собираются только
connection IDs из её профилей, с частями `config`, `data`, `state`, `session-links`
и `receipts`. Один общий connection ID не дублируется для нескольких пресетов.

Возможны API-ключи/токены и авторизация провайдеров, настройки/плагины/команды,
сообщения, результаты инструментов, native-логи, внутренние снимки файлов проектов
и текст прежних решений. На фикстуре native 2.0.28 действительно создал SQLite DB,
`data/opencode/log` и `data/opencode/snapshot`. Копия не зашифрована. Исключение
самой проектной папки не исключает её прежнее содержимое внутри истории/снимков.

выбора данные не включаются; предупреждение объясняет неполное восстановление.

явный выбор. Manifest фиксирует выбор и фактическое включение отдельно.

подключения. Без нового компонента сохраняются прежние версии создания.

### Восстановление и права

`inspect_opencode_tar` проверяет индекс, UUID, состав и отсутствие ссылок.
`restore` сначала извлекает компонент отдельно и возвращает проверенные источники.
`WorkspaceBackupImport.prepare/apply` и `OpenCodeBackupRestore` готовят приватную
копию, атомарно публикуют новый каталог и связывают новые пресеты с новым UUID.
Сохранённые policy-поля не заменяются разрешениями из квитанций. Существующие
подключения/авторизации не заменяются. Общие подключения нескольких пресетов
остаются общими внутри новой копии; повтор импорта создаёт независимую копию.

До apply/при ошибке подготовки удаляются только собственные новые staging-копии.
Коллизия не заменяет существующий каталог; повтор использует новый UUID.
Пресет сохраняет `restoreReview`, не получает live handle, не запускается при
импорте. Перед явным запуском требуется проверка среды/папки, адресов провайдеров,
плагинов и команд. В старом архиве без компонента импорт по-прежнему возможен,
но OpenCode нужно настроить отдельно; чужую действующую авторизацию он не подбирает.

### Полный native-цикл и квитанции

Тест использует настоящий закреплённый **OpenCode 2.0.28**, Node **22.22.1**,
production bootstrap/controller, настоящий Python create/inspect/restore,
Java importer, atomic WorkspaceStore save/reopen и generated launch восстановленного
профиля. Подменены guest mount/socket пути Android/proot и GUI-среда (Robolectric).
Это не установка/приёмка APK на телефоне и не настоящий вход в аккаунт провайдера.

CLI/JDK/SDK переиспользованы; данные чистые: новые HOME/XDG/config/data и библиотека,
искусственный ключ только в настройках локального провайдера. Исходные connection
и runtime HOME переименованы и сохранены перед повторным запуском. Старую
авторизацию или системные переменные с ключами тест не использует. Исполнитель
берёт только прежний проверенный native бинарник; ничего не устанавливает.
Сеть ограничена kernel guard: только listeners собственного тестового дерева.

Для shell и direct Write проверяются отдельные полные циклы:

1. Native инструмент спрашивает разрешение; фикстура явно отвечает Allow once.
2. Создаётся реальный эффект на искусственном файле и сохраняется квитанция.
3. Экспорт выполняется с настоящими native данными; профиль импортируется в чистое
   app storage, получает новый ID/connection UUID, сохраняется и перечитывается.
4. После явного запуска прежние native session ID, история и квитанции видимы.
   До нового запроса нет inference/нового разрешения. Байты и mtime тестового
   файла не изменяются: квитанция сама не воспроизводит действие.
5. Идентичная shell-команда либо новый Write того же файла снова требуют разрешения.
