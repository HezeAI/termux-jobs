# Резервное копирование и импорт — бета v1.1.0

**Шестерёнка справа сверху → Резервное копирование · бета** на любой вкладке.
Функция экспериментальная: проверка архива не доказывает успешное восстановление
всех программ. Сначала проверяйте на отдельном устройстве/некритичной копии.
Приложение не останавливает рабочие сессии молча и не запускает содержимое архива.
Нужен Python3 в Termux (`pkg install python` вручную); для Ubuntu — proot-distro.
Установка этих зависимостей не производится скрыто.

## Создать свою копию

Выбор: библиотека команд/заметок/пресетов и настройки; файлы истории терминальных
сессий; HOME; PREFIX; установленные Ubuntu/proot отдельно. Каталог назначения
должен существовать и быть доступен приложению (по умолчанию Download).
Каждый запуск создаёт каталог с временем и случайным суффиксом, старые не заменяет.
Предварительно оцениваются объём и свободное место. Сбор выполняется отдельным
worker, окно показывает этап/обработанные байты; операции можно отменить.

HOME включает пользовательские dotfiles, SSH, CLI-авторизацию, проекты и скрипты,
если они физически внутри HOME. Ubuntu сохраняется штатным `proot-distro backup`;
в неё входят /root/.codex, история CLI, проекты, инструменты и другие файлы,
расположенные внутри выбранной rootfs. PREFIX сохраняется без tmp и всего
var/lib/proot-distro: rootfs выбираются отдельно, образные/build-кеши proot-distro
в PREFIX-копию не входят. Список пакетов Termux записывается отдельно.
Символические ссылки хранятся ссылками, **внешние цели не обходятся**. Файлы
Android shared storage за пределами выбранных деревьев не копируются.

Живые сокеты, устройства и FIFO не архивируются. Копия работающей базы не является
атомарной: завершите изменяющие файлы задачи перед запуском и подтвердите это.
Процессы и память не сохраняются. Современный proot-distro может самостоятельно
нормализовать права rootfs при штатном backup; это поведение upstream-инструмента.
Секреты не шифруются: храните каталог офлайн и защищённо. Общая память Android
не обеспечивает POSIX-права приватности; метаданные хранятся внутри TAR.

Состав: manifest.json, выбранные TAR.GZ/JSON, packages.txt (если доступен dpkg),
SHA256SUMS, README-RESTORE.txt, restore.sh и автономный backup-tool.py.
После записи проверяются содержимое TAR, SHA-256 и сжатый поток. Незавершённые
каталоги сохраняют INCOMPLETE и не считаются готовыми.

## Проверить чужой бэкап

Выберите файл или введите доступный путь. Поддерживаются:

- Наш manifest.json версии1 и workspace-v1.json с библиотекой версий1–8.
- TAR/TAR.GZ/TAR.BZ2/TAR.XZ с HOME/PREFIX под home/, usr/ либо стандартными
  относительными data/data/<package>/files/{home,usr}/ и data/user/0/… путями.
- Bare HOME с распознаваемыми shell dotfiles; bare rootfs с etc/os-release и bin/usr.
- Старый proot installed-rootfs/<alias>/ и новый <alias>/rootfs/ формат, включая
  rootfs внутри полного PREFIX. Другие произвольные форматы форков не обещаются.

ZIP, зашифрованные архивы, абсолютные TAR paths и неподдерживаемые layouts не
распаковываются автоматически. Для raw-чужого TAR нет доверенного исходного SHA:
вычисленная сумма позволяет отследить последующие изменения, а не подлинность.

Проверка читает архив потоково без извлечения/запуска. Проверяются пути, дубли,
попытки записи через символические ссылки, лимиты и целостность компрессии.
Компоненты собственного manifest сверяются с hash/size; изменение файла после
проверки требует нового анализа. Перед извлечением выбранные архивы копируются
в приватное рабочее место и повторно сверяются. Нужен запас места для копии,
извлечения и перепаковки Ubuntu; оценка намеренно консервативна.

Совместимость Ubuntu подтверждается по ELF-архитектуре, а не имени архива.
Неизвестная/другая архитектура блокирует установку rootfs. Для регистрации отдельной
Ubuntu в этой бете нужен современный Python proot-distro; старый shell runtime
может создавать копии, но автоматический импорт rootfs в него заблокирован.
Различия package ID/путей не делают PREFIX переносимым: он только извлекается для
проверки, никогда не заменяет работающий PREFIX. HOME переносится как файлы;
встроенные бинарники и жёсткие пути могут требовать исправления.

## Выбрать и восстановить

Окно выбора показывает компоненты и результат проверки. Нужно отдельно подтвердить
доверие и план; ничего не применяется при простом выборе файла или просмотре.

- HOME/PREFIX/app-data извлекаются в **новую** подпапку выбранного каталога внутри
  Termux HOME. Существующие файлы не объединяются/не перезаписываются. Дальнейшая
  активация HOME/PREFIX остаётся ручной: слепого восстановления работающей среды нет.
- Ubuntu перепаковывается только из rootfs под новым jobs-<id>, затем используется
  штатный restore. Чужие host config scripts/manifest-команды не выполняются.
  Существующий alias не заменяется. Создаётся пресет `proot-distro login --isolated
  '<alias>'`: нет добавленных общих проектных bind-папок. Это не защитная VM;
  процессы всё равно работают с Android UID приложения.
- Библиотеки: выбор команд/заметок/пресетов, объединение или замена выбранного
  списка; точные дубликаты пропускаются. Активные сессии и базовый Terminal не
  удаляются при замене пресетов. Перед импортом библиотека сохраняется в
  files/workspace-import-recovery/before-<uuid>.json.
- Все профили получают новые идентификаторы/IPC-сокеты, без live handles и
  непереносимого зашифрованного SSH-пароля. При первом запуске импортированного
  пресета открываются настройки для проверки среды/команд/путей. Его нельзя
  автоматически считать привязанным к новой Ubuntu; она имеет отдельный пресет.
- Файлы истории импортируемых пресетов можно перенести при выборе app-data.
  Это история оболочки, а не восстановление процесса с места остановки.
- Простые статические `alias name='body'` распознаются чтением .bashrc/.zshrc/
  .bash_aliases; выбранные раскрываются в сохранённые команды. Не выполняются
  source/eval или динамические определения. Скрипты .sh добавляются как команды
  запуска только после выбора восстановления соответствующих файлов.
  Bash/Zsh history автоматически не превращается в библиотеку команд.
- Настройки интерфейса импортируются отдельно; для части изменений нужен новый
  запуск приложения. Android Keystore, APK-разрешения и живые процессы не переносятся.

Операции компонентные, не транзакция всей среды. При ошибке/отмене новая папка
может содержать частичный результат с INCOMPLETE; существующие среды не заменяются.
После успешного извлечения, но неудачного импорта библиотеки, проверяйте каталог
результата и recovery-копию. Не удаляйте исходный бэкап до проверки работы.

## Пакеты — отдельный раздел проверки

Сравниваются только пакеты Termux из packages.txt/его dpkg status с локальным
`dpkg-query`; статус вложенной Ubuntu не смешивается с Termux. Показываются
различающиеся/отсутствующие версии. Список без версий доступен для просмотра,
но не для точной замены. Пакеты отдельно восстановленной Ubuntu уже внутри rootfs.

Выбор отдельных пакетов, всех различий (до200 за план) либо ничего. `apt-get -s
--no-remove install -- name=version …` получает предварительный план без установки,
без обновления индекса и без установки пакетов во время анализа архива. Недоступные
версии/конфликты отображаются в APT-ответе, кнопки установки при ошибке нет.
После отдельного подтверждения открывается новый Termux-терминал с обычным APT;
он снова запрашивает подтверждение, и его актуальный план нужно перечитать.
Общая среда Termux и зависимости могут измениться — завершите важные задачи.

## Лимиты беты и проверка

До500000 TAR entries,512GiB payload; JSON-метаданные/библиотека до8MiB,
до100 компонентов и500 распознанных aliases/скриптов; выбор APT до200 пакетов.
Права/mtime сохраняются где возможно, владелец — текущий Android UID, setuid/setgid
не восстанавливаются. Большие/неподдерживаемые метаданные блокируются.
Автономный restore.sh предназначен для **своего доверенного бэкапа**, на чистом
обычном Termux требует Python/proot-distro и сначала показывает выбор компонентов;
он также извлекает HOME/PREFIX отдельно. Не запускайте скрипты чужого бэкапа.

Реальное полное восстановление на другом телефоне ещё не подтверждено. Нужны
пользовательские проверки на тестовой копии, включая Python/proot версии, свободное
место, Android storage permissions, историю и авторизацию после восстановления.

Для долгого копирования держите приложение открытым: отдельного foreground
service/wake lock и докачки нет. Выгрузка Android может оставить INCOMPLETE.
ACL/xattrs/SELinux labels не являются переносимым состоянием этой беты.
