# Известные проблемы

Текущий выпуск — v1.1.4. OpenCode использует адаптер v1.0.9, без screen/resize/
frontend экспериментов v1.0.10–12. Автоматическое продолжение истории восстановлено,
ручного пункта сохранения чата нет. OC-001 не объявлен исправленным.

## BACKUP-001 — бета, реальное восстановление ещё не подтверждено

Поддерживаются только распознаваемые форматы, не любой форк. Нужен Python;
отдельная Ubuntu — современный Python proot-distro и подтверждённая архитектура.
HOME/PREFIX только извлекаются отдельно; нет слепой активации/замены работающей
среды. Live DB consistency, внешние цели ссылок, Android Keystore/permissions и
процессы не восстанавливаются автоматически. Компоненты не общая транзакция.
Проверка на тестовых fixtures/моках не доказывает перенос реальной среды между
телефонами. [Подробности](BACKUP-RESTORE.md).

## UPDATE-001 — проверка реальной установки

Источники/сборка/хеши/подпись и совместимость update.json с v1.0.19 проверяются
перед релизом, но системный установщик агент не запускал. Первый реальный in-app
upgrade v1.0.19→v1.1.0 предстоит подтвердить пользователю. Докачки нет.

## AI-002 — неполная проверка агентов

Claude: version/help и isolated runtime проверки, реальный вход/ответ/вся история
не подтверждены. Gemini: Google individual OAuth отключён поставщиком, API
интерфейс открыт на телефоне, успешный ответ/квота не подтверждены. OpenCode:
не проверены все провайдеры/аккаунты/модели. Antigravity не встроен.

## DIAG-001 — границы журнала

Структурированные события и коды — не HTTP trace и не полный transcript.
Цитата ошибки в терминале может дать сигнал. Память журнала теряется при смерти
app-процесса; сохранённые файлы остаются. Полная проверка Android UI/экспорта на
разных устройствах не выполнена; тесты и успешная сборка её не заменяют.

## OC-001 — ВАЖНО: мерцание и рывки вывода OpenCode

Статус: **не исправлено, подтверждено пользователем на телефоне после v1.0.10**.
Пользователь разрешил проверочную v1.0.11 после отдельной диагностики. Не объявлять исправленным
по прохождению тестов транспорта или сборки APK.

Наблюдения пользователя:
- Возникает при переходе из другой терминальной сессии обратно в OpenCode.
- Также заметно при изменении окна, открытии/закрытии клавиатуры.
- Есть в новом чате без истории и во время вывода ответа/работы индикатора.
- Пробная обработка кадров и resize batching в v1.0.10 не устранила проблему.

Подтверждённые факты кода: native OpenCode mini v2.0.28 может заново выводить
историю при resize; использует DEC2026. Они не доказывают первопричину всех
наблюдаемых рывков. Точная причина пока не установлена.

Свидетельство: /sdcard/Pictures/Screenshots/Screenrecorder-20261014-014531.mp4.
Ссылка на исходные проверки: [v1.0.10](VALIDATION-v1.0.10.md).

При возвращении к задаче: воспроизвести на телефоне пустой/существующий чат,
зафиксировать actual PTY размеры и время обновлений, сравнить native mini
с нашей оболочкой и отдельно проверить влияние включённого буфера. Не менять
пользовательские процессы без соответствующего разрешения. Возврат просмотра
вниз при новом выводе пользователь просил оставить; это не часть OC-001.

Смена модели с переоткрытием и историей подтверждена пользователем в v1.0.9.
Исторический APK v1.0.10 сохранён. На том этапе публикация GitHub не выполнялась.

Проверочная v1.0.11: OpenCode attach ожидает final layout перед первым updateSize;
resize batching отключён для OpenCode, DEC2026/native replay сохранены. В isolated
пустом native чате --replay даёт clear/reset около260ms, --no-replay не даёт очистку;
ответ на OSC4 не устраняет replay. Полный секундный возврат на телефоне не доказан.
Автопрокрутка, в том числе старый сброс вниз при реальном resize, не менялась;
наблюдение пользователя о прыжке при открытии IME остаётся в проверке.

## Выборочные бэкапы (локальная v1.1.1)

Выборочная активация поверх существующей среды не автоматизирована: данные без
системы только извлекаются. Обнаружение Node.js не проверяет версию или запуск;
нестандартные установки AI-агентов требуют ручного включения папок и проверки
зависимостей. Manifest v2 не читается v1.1.0. Базы согласованы по отдельности,
не все одновременно с JSONL. Реальное восстановление на втором телефоне не
проверено агентом; авторизация может потребовать повторного входа.

## SOURCE_UNREADABLE при выборе компонентов (v1.1.1)

Подтверждено скриншотом пользователя. Старый onerror прекращал весь расчёт,
не сообщая путь. В локальной v1.1.2 проблемные группы отмечаются и отключаются,
другие остаются доступными; исправление проверено на фикстурах, реальный повтор
на телефоне ещё нужен. Это не обход Android-прав и не разрешение игнорировать
ошибки уже выбранных данных. Полный режим пользователь сообщил работающим.

### Local v1.1.3 backup verification limits

Elapsed time is not ETA; unknown totals use indeterminate progress. Native full
Ubuntu compression choices require modern proot-distro; legacy remains native.
pigz installation needs network/repositories/free APT locks and may add dependencies.
No foreground service or wake lock: keep the app open. Android process death can
interrupt copying or APT. Fixture tests do not prove on-device cancellation,
background installation, thermal behavior or restore compatibility; user verification
is required. No actual package installation or real user-data restore was performed.
