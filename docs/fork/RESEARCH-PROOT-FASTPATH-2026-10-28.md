# Исследование ускорений PRoot из DroidDeck

Дата: 28 октября 2026. Это исследование и изолированный прототип, не изменение
APK или установленных окружений. Рабочая сборка приложения остаётся code1432.

**Рекомендация: отдельный опыт в тестовой Ubuntu имеет смысл.** Начинать стоит
с небольшого набора патчей самого PRoot. Оснований обещать ускорение приложения
на 57% или включать всю связку preload/LD_AUDIT для пользователей пока нет.

## Проверенные исходники

commit `22eac0831d10671f6bc2ad914a93a0da5046c7df`. Получены 43 файла, 438160 байт,
каждый проверен по Git blob SHA-1 из закреплённого дерева; SHA-256 записаны отдельно.
Их набор PRoot построен на Termux commit `4dba3afbf3a63af89b4d9c1a59bf2bda10f4d10f`.

На телефоне установлен PRoot `5.1.107.96`, proot-distro `5.9.0`, гостевая glibc
`2.43`. Исходники точного тега `v5.1.107.96` получены и проверены по SHA-256

## Как устроено ускорение

Есть два разных слоя. Патчи PRoot уменьшают затраты на поиск отслеживаемых
процессов, преобразование путей и некоторые остановки системных вызовов.
Отдельная glibc-библиотека переводит поддерживаемые пути внутри гостевого
процесса и обращается к ядру из выделенной страницы trampoline. Для этого нужен
согласованный патч PRoot и ключ конкретного запуска. LD_AUDIT дополнительно
сокращает часть поиска отсутствующих библиотек.

Библиотека ориентирована на glibc/AArch64. Она не является готовым бинарником
для Alpine/musl или Android/Bionic. Исследовательская сборка содержит зависимости
от GLIBC_2.34/2.38; для общего компонента нужен отдельно выбранный совместимый
build baseline. Сам Android-бинарник PRoot и гостевой preload — разные компоненты.

## Что удалось собрать и проверить

В `.verification/proot-fastpath-research/` сохранены исходники, скрипты и результаты.
Никакие пакеты не устанавливались. Использованы существующие компиляторы;
временные файлы и все результаты находятся в репозитории.

1. Собраны исходный и полный патченный PRoot на базе DroidDeck, парные loader,
   `libblfastpath.so` и `libblaudit.so`. В обоих PRoot включены process_vm и seccomp.
   Android-бинарники собраны установленным Termux clang, а не официальным NDK CI;
   они предназначены для исследования. Это не проверка минимального Android API.
2. Подготовлен минимальный временный rootfs. Системное `/usr` используется для
   чтения библиотек/программ; записи идут в временные `/root`, `/tmp` и shared
   внутри каталога исследования. Установленная Ubuntu не используется как цель записи.
3. Семь пробных запусков проверили обычный запуск, preload, выключатель, неверный
   ключ и audit. Они завершились успешно. При вложенном PRoot быстрый preload-путь
   **не активировался**: видимый TracerPid принадлежит внешнему PRoot, его ключ не
   совпадает. Эти проверки подтверждают отказ от включения, а не ускорение preload.
4. Шесть микрозамеров дали небольшие разнонаправленные изменения с пересекающимися
   диапазонами. Для трёх повторов медианы задержек приведены ниже. Это измерения
   вложенного PRoot; они не устанавливают прирост обычного запуска на телефоне.

| Операция | Исходный, мс | Патченный, мс |
|---|---:|---:|
| stat | 2.590 | 2.585 |
| stat через ссылку | 3.827 | 3.464 |
| open + close | 3.113 | 2.897 |
| stat отсутствующего пути | 2.434 | 2.218 |
| uname | 0.670 | 0.687 |
| getcwd | 1.341 | 1.399 |

Набор `equiv2.py` проверяет операции с путями, ссылками, файлами, Unix-сокетами,
расширенными атрибутами и рабочими каталогами. Три запуска старой базы завершились
с кодом0 и дали по 507 строк; после нормализации PID результат совпал. У варианта
с настроенным preload фактическое ускорение было выключено защитой, как описано выше.

## Перенос на нашу версию

Полный набор из 19 patch-файлов нельзя считать готовым для 5.1.107.96:
механически применились 9, причём 4 использовали нечёткий контекст (fuzz).
Остальные требуют разбора; текстовое применение само по себе не доказывает
семантическую совместимость.

Отдельно собраны исходная 5.1.107.96 и кандидат с четырьмя выбранными патчами,
применёнными без fuzz:

- `0001`: поиск tracee по PID;
- `0002`: преобразование родительского каталога пути;
- `0009`: сокращение обходов при завершении процессов;
- `0011`: сокращение ненужной работы kompat при подходящей виртуальной версии ядра.

Пара запускалась с fake-root и `--kernel-release=6.17.0`, без preload.
Оба запуска `equiv2.py` завершились с кодом0, по 507 строк. Различались только
два вывода пути `/proc/<PID>/status`, соответствующие разным процессам.
Их нормализованные результаты идентичны. Полноценный рабочий стол и сборка APK
под этим кандидатом ещё не запускались.

## Воспроизводимый случай отказа библиотеки

В исходной glibc-библиотеке при занятой странице `0xffff00000` ветка EEXIST
допускает использование существующего адреса без проверки его содержимого.
Изолированный C-пробник заранее занял страницу как PROT_NONE. Вызов stat через
библиотеку достиг этой страницы до проверки ключа tracer. Обработчик сигнала
зафиксировал обращение и завершил только пробник кодом77; рабочие процессы
не затронуты. Без ключа, с выключателем и при свободной странице пробы успешны.

Подготовлен консервативный экспериментальный патч: при любом занятом адресе
отключать быстрый путь. Все четыре контрольные пробы с ним завершились кодом0.
Это не готовое общее решение: при LD_AUDIT страница может быть занята самим audit,
и такой отказ выключит fastpath. Совместное использование требует отдельной проверки.
Исходные закреплённые файлы сохранены без изменений.

## Как подключать будущий опыт

В установленном proot-distro 5.9.0 предусмотрен `PD_PROOT_BIN`. Он позволяет
задавать другой исполняемый файл для конкретного запуска. Для опыта нужны
парный `PROOT_LOADER` и параметры только этого запуска. Системный proot заменять
не требуется. Поддержку других версий proot-distro нужно проверять отдельно.

В наших X11-скриптах перед запуском гостя очищается LD_PRELOAD, а затем добавляются
отдельные библиотеки совместимости. Будущее включение fastpath должно учитывать
этот порядок и сочетание с Bionic-to-glibc, а не перезаписывать их настройки.
Наши сессии обычно используют fake-root; оптимизация DroidDeck для совпадающих
реальных UID не равнозначна этому режиму.

Следующий минимальный шаг — контрольный запуск из базового Termux, вне PRoot,
с временным rootfs и затем с отдельной тестовой Ubuntu. Нужны:

- стабильный A/B запуска программ, работы с файлами и сборки проекта;
- совпадение UID, stat/fstat, прав и ошибок, поведения ссылок и файловых операций;
- проверка процессов, отмены и остановки только тестового процесса;
- для preload: подтверждённая активация, изменения каталогов из другого процесса,
  потоки/fork, Unix-сокеты и сочетание с нашими графическими обвязками;
- возврат к обычному PRoot и отсутствие изменений других окружений.

`host-probe.py` подготовлен для отдельной безопасной smoke-проверки. Он требует
обычный Termux и отказывается работать под tracer (проверен отказ с кодом66).
Этот самостоятельный запуск ещё не выполнялся. Новые вкладки/переключатели,
установка APK, замена среды и публикация в этой задаче не производились.

## Происхождение и воспроизводимость

PRoot: проект PRoot и Termux fork. Патчи: DroidDeck/maxjivi05/xXJSONDeruloXx,
часть унаследована из WinNative, как указано в их PATCHES.md. Сохраняются исходные
лицензии: PRoot GPL-2.0, DroidDeck GPL-3.0, talloc — согласно файлам его исходников.
Наши дополнения здесь — стенд, перенос выбранного набора на точную версию,
контрольная проверка занятой страницы и консервативный исследовательский патч.

Ключевые материалы: `sources.json`, `core-sources.json`, `port-96.json`,
`artifacts.json`, `smoke.json`, `activation-check.out`, `benchmarks.json`,
`equivalence.json`, `current96-equivalence.json`, `collision-results.json`,
`collision-conservative-results.json`, `occupied-trampoline-conservative.patch`.
