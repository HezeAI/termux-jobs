## Ревью и логическая инспекция

Запросы ограничены cached metadata (--no-network/--cacheonly/--no-refresh),
без скрытого refresh/install. Имя/версия/архитектура/источник проверяются перед
shell quoting. DNF не использует latest-limit в выборе; Zypper принимает alias
или display name источника; APK исключает installed-only версии и не показывает
URI-пароли/запросы. Для Alpine в этом адаптере поддержаны HTTP(S)-источники policy.
Операции не используют автоматическое yes/force/обход подписей. --oldpackage
у Zypper разрешает только явно выбранное понижение; менеджер показывает план.
Сохраняются concrete alias, isolated-флаг, guest PATH и защита от выполнения
пакетной команды в Termux после выхода из гостя. Чтение списка не изменяет world;
подтверждённый APK add name=version закрепляет версию — в UI есть предупреждение.
Отмена окна чтения не запускает мутацию, закрытие менеджера гасит его worker.

## Минимальная проверка на устройстве

В каждой из трёх систем открыть пакет → «Выбрать версию», проверить версию и
источник. Для единственного варианта должна быть явная надпись об отсутствии
других версий. В openSUSE можно проверить несколько версий7zip из текущего каталога.
Затем выбрать ненужный тестовый пакет, проверить команду/предупреждения/правильную
среду, запустить в свободной оболочке и проверить native план до подтверждения.
Отменить один выбор без установки. Для Alpine учесть world-ограничение точной версии.
Доступность файла пакета на сервере и совместимость зависимостей определяет
native solver: кэш не гарантирует, что старый файл ещё доступен для скачивания.
