# Расписания задач сервера

В сервере выберите «Задачи → Запустить задачу → По расписанию».
Поддерживаются Python3.8+, Linux flock, Bash и доступный crontab либо работающий
systemd --user. Пакеты, sudo и linger автоматически не устанавливаются/не включаются.
Наличие crontab не доказывает работу cron daemon: это нужно проверить на сервере.
Без linger пользовательский systemd может остановиться после выхода или перезагрузки.
Persistent timer догоняет пропущенный запуск лишь при работающем user manager.

Cron принимает пять числовых полей, списки/диапазоны/шаги. systemd: hourly, daily,
weekly, `*-*-* HH:MM[:SS]` или конкретная дата `YYYY-MM-DD HH:MM[:SS]`.
Показываются серверное время/часовой пояс и CRON_TZ, если задан в crontab.
Запуск неинтерактивный: aliases, PATH и окружение отличаются от терминала.
Не используйте `&`/nohup: отделённые процессы не управляются как обычная задача.

До30 расписаний, максимум1час на запуск. Одно расписание не запускается параллельно
самому себе; разные могут работать одновременно. Хранится состояние и журнал
последнего запуска до2МБ; окно показывает последние32КБ, не историю всех запусков.
Журнал может содержать секреты, выведенные самой командой.

В «Расписания задач» доступны журнал, включение/отключение, изменение времени
и удаление с подтверждением. Отключение отменяет будущие запуски, текущую команду
не останавливает. Удаление выполняющегося расписания запрещено. При ошибке изменения
расписание может остаться выключенным. При обрыве связи проверьте список прежде,
чем повторять создание: удалённая операция могла уже завершиться.

Файлы находятся в `~/.local/share/termux-jobs-schedules-v1` с приватными правами.
Изменяются только собственные записи crontab с UUID-маркером и пользовательские
unit-файлы `termux-jobs-schedule-UUID.*`. Чужие строки сохраняются, перед записью
выполняется повторное чтение. Однако внешние редакторы crontab не используют нашу
блокировку: не редактируйте crontab одновременно другими средствами (нет общего CAS).
Системные службы и задания других пользователей не изменяются.

Расписания независимы от агента и локального профиля: удаление агента/профиля
их не удаляет. Управляйте ими до удаления профиля или подключитесь повторно тем же
SSH-пользователем. Для управления без агента есть кнопка расписаний в сервере.

Доступно с публичного v1.2.0. Проверены локальный runner и протокол с подставными cron/systemctl. Работа настоящего
cron daemon, user manager, запуск после выхода/перезагрузки и Android UI требуют
ручной проверки. Никакие расписания на пользовательском сервере при разработке
не создавались.
