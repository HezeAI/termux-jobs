# Проверка тестовой сборки

Дата: 11 октября 2026 года. APK не устанавливался, реальные Android-сессии
и JNI на устройстве ещё не проверены. Проверка на другом устройстве остаётся
необходимой перед использованием как основного терминала.

## APK

- Файл: `build/apk/termux-fork-0.4-debug-arm64.apk`.
- Копия для пользователя: `/sdcard/Download/TermuxFork-0.4-debug-arm64.apk`.
- Версия: `0.118.3-fork.4`, package `com.termux`, ABI `arm64-v8a`.
- Android 7.0 и выше (minSdk 24), targetSdk 28.
- SHA-256: `4b64290ad3f4a5b29514f8622367d74b45ac1483ee90989ed4a692d48883965e`.
- Подпись APK v2 проверена `apksigner`; сертификат SHA-256:
  `dd37d983cd2496ebe49c7e88ddbc0088f311d38b8a8503e4392c81b48a11a644`.
- Ключ: `.signing/fork-debug.jks`, исключён из Git. Его нужно сохранить для
  обновления этих тестовых сборок. CI без сохранённого ключа создаёт новый ключ,
  поэтому его APK не смогут обновлять эту сборку.

Проверять на ARM64-устройстве без установленного Termux и его плагинов.
Сохранённый идентификатор не позволяет установить форк параллельно с Termux.
APK подписан собственным тестовым ключом, а не ключом официального приложения.

## Изолированная сборка

На ARM64-хосте JNI скомпилирован из оригинальных C/ASM-исходников отдельно,
через Clang и `ld.lld`, с Android API 24 и существующим NDK sysroot,
использованным только для чтения. Отсутствие лишнего RUNPATH, SONAME,
экспортируемые JNI-символы и состав библиотек в APK проверены.

Официальный ARM64 bootstrap проверен по SHA-256:
`c8d702b6f742935001c37cda81b8ac69504a95d5cf28f2899532dd8cd4b057eb`.
Java, ресурсы и DEX собраны Gradle 7.2/JDK 11 с SDK 30/Build Tools 30.0.3.
Gradle успешно собрал и подписал APK. Обычная конфигурация сборки с NDK
в основных исходниках сохранена; её выполнение на x86 CI ещё не проверено.

Пример повторной сборки в текущей среде:

```sh
FORK_AAPT2=/data/data/com.termux/files/usr/bin/aapt2 \
FORK_NATIVE_CLANG=/data/data/com.termux/files/usr/bin/clang \
FORK_NATIVE_LLD=/data/data/com.termux/files/usr/bin/ld.lld \
FORK_NATIVE_SYSROOT=/data/data/com.termux/files/home/Android/Sdk/ndk/28.1.13356709/toolchains/llvm/prebuilt/linux-x86_64/sysroot \
./scripts/build-local-arm64.sh
```

Инструменты, SDK-копия, кеши, временные файлы и отчёты находятся в `.tools/`
и `.verification/` внутри репозитория. APK скопирован в Download по запросу.

## Автоматические тесты

Java-тесты запускаются через `scripts/verify-java.sh` в копии исходников
`.verification/source`, с отключённой сборкой JNI. Они не запускают
TermuxService, реальные оболочки или распаковку bootstrap.

145 тестов исходного эмулятора прошли. Девять тестов WorkspaceStore прошли:
сохранение и чтение, независимые идентификаторы, порядок записи, защита
повреждённого/неизвестного формата, восстановление AtomicFile из резервной
копии, ограничение Unicode-вывода, история Bash и экранирование команды.
Тест навигации прошёл: открытие страниц, создание команды через диалог,
фильтр избранного, возврат на главную и чтение библиотеки после повторного
открытия хранилища. Два исходных теста приложения также прошли.
В версии 0.2 этот тест дополнен выбором команды через звёздочку: текст
вставляется с курсором в конце без создания терминала; «Сохранить ввод»
открывает заполненную форму и сохраняет команду, оставляя ввод на месте.
Всего: 157 тестов, 0 ошибок, 0 пропусков. Повторный запуск завершился
`BUILD SUCCESSFUL`. В terminal-view и termux-shared unit-тестов нет.

## Ручная проверка на другом устройстве

1. Первый запуск: bootstrap распаковывается, Bash открывается, ввод работает.
2. Сохранить команду с категорией и каталогом; отредактировать, дублировать,
   добавить в избранное и запустить.
3. Создать несколько именованных сессий, переключаться вкладками,
   остановить и перезапустить одну сессию.
4. Закрыть приложение, открыть снова, проверить библиотеку, профили,
   историю и повторный запуск стартовой команды по нажатию.
5. Проверить клавиатуру, прокрутку, поворот экрана и панели на своём устройстве.
6. Нажать звёздочку у поля ввода, выбрать сохранённую команду, при необходимости
   отредактировать текст и отправить вручную. Ввести новую команду и сохранить
   её через «Сохранить ввод», проверить её появление в библиотеке.

В версии 0.3 раздел «Команды» полностью предназначен для вставки текста.
Форма содержит название, текст, категорию и избранное. Тест проверяет
вставку из карточки без создания сессии и без отправки.

В версии 0.4 проверены три пункта нижней навигации, журнал на главной,
повторная вставка из журнала и очистка с сохранением библиотеки.
Отдельные тесты проверяют вытеснение до 25 записей, порядок, сохранение,
очистку и совместимость со старым JSON без поля recentCommands.
Журнал фиксирует только отправки из поля ввода приложения; прямой ввод
в TerminalView и история оболочки в этот журнал не импортируются.
