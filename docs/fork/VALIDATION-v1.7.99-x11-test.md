# Частная v1.7.99-x11-test — Kali и VirGL

## Результат

Touch Workspace удалён из меню, IPC-состояния и запуска. Исходник GTK-экрана и
его сборщик удалены; старый исполняемый ресурс и Touch ZIP не включаются в APK
даже при сборке с прежним кэшем. Осталась одна галочка «Стиль Termux-job’s»:
Kali при включении, обычный XFCE при выключении. Размеры, изображения и
обычные жесты Kali не изменены; ZIP побайтово совпадает с v1.7.98.

Старый активный выбор Touch однократно переводится в Kali. При следующем
запуске восстанавливаются прежние автоскрытие панелей, DoubleClickTime и число
рабочих областей, если их значения не менялись вручную. Полная очистка home,
проектов, историй или настроек сессий не выполняется. Удаляются только два
устаревших обычных файла собственных ресурсов из Termux X11 control-каталога;
ссылки и пользовательские каталоги не обходятся. Остаточные события кнопки
клавиатуры Touch игнорируются, запрос старого режима отклоняется до мутации.

VirGL расширен с Termux/Ubuntu/Arch на Debian/Alpine/Fedora/openSUSE/Void.
Нативный Android/Termux сервер остаётся отдельным дочерним процессом каждого
стола с собственным UNIX-сокетом. Mesa устанавливается только в выбранный
гость через его пакетный менеджер; Void использует run вместо login. Проверка
запрашивает полный обязательный набор при отсутствии любого компонента.
Повторная готовая установка не дублирует транзакции. Ошибка установки не
возвращает READY. Композитор для VirGL остаётся отключённым; остальные
renderer-specific правила не изменены. Ubuntu AI/агенты не включены в allowlist.

## Проверка разработчиком после сборки — 2026-10-23

- Void: скриншот 082122 — XFCE/VirGL стартовали, glmark2 2023.01 определил
  virgl ANGLE Adreno830 / Mesa26.2.5, затем первый build/use-vbo=false завершился
  с lost connection/read -1/104, статус250. Сервер и стол остались запущены.
  Причина именно этого GLX/glmark2 разрыва пока не доказана.
- Изолированный headless EGL-пробник использовал установленную Mesa Void через
  её loader и отдельный собственный сервер/сокет в проекте. Очистка framebuffer
  и треугольник прошли через ANGLE GL и ANGLE Vulkan; GL оставил EGL_BAD_ACCESS
  при переключении контекста, Vulkan в этом малом тесте ошибки не оставил.
  Это не подтверждение исправления GLX/glmark2 и не тест скорости. Оба пробных
  сервера остановлены как собственные дочерние процессы; действующие столы
  не перезапускались, пакетные установки не выполнялись.
- Alpine: скриншот 082602 — glxinfo и glxgears не создают drisw/GLX context.
  Установленная libgallium26.1.6 не содержит virpipe; APKBUILD Alpine3.24 также
  исключает virgl из gallium-drivers. Одного наличия mesa-dri-gallium недостаточно.
  Ранее при добавлении VirGL проверка пакетов ошибочно считала это готовностью.
  Для Alpine нужен совместимый musl Mesa client с virpipe и проверка реальной
  возможности драйвера; повторная установка тех же пакетов этого не исправит.
- Read-only инспекция установленных Ubuntu/Debian/Fedora/openSUSE/Void/Arch Mesa
  обнаруживает virpipe; наличие строки само по себе не подтверждает GPU-тесты.

Доказательства: `.verification/void-virgl-diagnosis/` (probe.c, run-probe.py,
client/server GL/Vulkan logs, installed-drivers.json). Обновлённый APK не собирался:
разработчик попросил пока не собирать. Релиз остаётся отложен до исправления
и повторных проверок.

- 6 Python VirGL: отдельные сокеты, отмена одного при работающем другом,

  семи гостевых менеджеров проверяют полный набор, ошибку установки,
  отсутствие READY при недостающих компонентах, отсутствие переустановки
  готового набора и случайной транзакции в другом окружении/host.
- shell syntax, git diff --check; ARM64 release build, packaged DEX runtime audit:
  13552 определения, 31 ранее рассмотренный внешний тип.
- Финальный APK: CRC всех записей, отсутствие дублей, package/version/minSDK/ABI,
  APK Signature v2 и прежний сертификат, SHA-256, отсутствие приватных ключей,
  файлов авторизации и известных приватных маркеров. Проверены JNI 28/1/5,
  неизменность всех прежних native libraries и удаления Touch-ресурсов.

Это проверки исходников/сборки и изолированных процессов. Новая установка
реальных гостевых пакетов, свежий телефон и GUI/GPU новых пяти систем здесь
не проверялись. Совместимость драйвера и ANGLE зависит от устройства/версии Mesa.
Заглушки пакетов не доказывают реальную отрисовку VirGL.

## Минимальная проверка разработчиком

1. После обновления перезапустить Termux-стол. Убедиться, что Touch отсутствует,
   галочка даёт Kali, выключение и повторный запуск возвращают обычный XFCE.
2. В Debian выбрать VirGL → запустить стол → согласиться на установку при
   необходимости. Открыть GPU INFO: нужен virgl/virpipe, а не llvmpipe. Проверить
   GPU, окна, остановку и повторный запуск.
3. Повторить для Alpine, Fedora, openSUSE и Void. При наличии двух запущенных
   столов остановить один и убедиться, что другой продолжает работать.
4. Ошибки установки/запуска передавать из диагностики соответствующей сессии.
