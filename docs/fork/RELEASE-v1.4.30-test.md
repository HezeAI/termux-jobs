# v1.4.30-test — CPU/GPU operating mode and tool error evidence

Engine settings now has Operating mode: CPU / GPU. CPU remains the default, retaining ARM/compatible mode, thread count and configured inference location. GPU hides CPU mode/thread controls without erasing their saved values. Returning to CPU restores them. GPU runs a separate Android/Bionic OpenCL runner; it does not execute inside the Ubuntu/glibc runner. The saved CPU location and selected tool environment remain unchanged. GPU process uses six CPU assistance threads internally; these are not a GPU thread setting.

Initial GPU availability is deliberately limited to catalog Qwen3.5 2B / Snapdragon8EliteSM8750 with matching ARM instructions. Other Qwen/GGUF models are not proven compatible by this experiment. Other models and LiteRT keep their existing acceleration paths. OpenCL driver and supported device must actually initialize; failed startup does not silently pretend to be GPU on CPU. Select CPU to recover. Original CPU libraries/runners are retained; GPU owns its child process, uses the existing IPC/cancellation/close flow and is killed with its parent. Startup can take time for OpenCL initialization. This is a test feature. More memory is used; faster input processing does not imply faster generation. CPU-only synthetic benchmark is rejected in GPU mode rather than mislabelled as GPU. Normal request diagnostics still report GPU runtime, timings and cache.

Tool validation cards now show the original model output, named invalid/duplicate parameter and expected schema for the selected available tool. Old cards without original output explicitly say it was not recorded. Original invalid text is diagnostic data, never promoted into an action; surrounding prose, examples, multiple calls and ambiguous duplicates remain rejected. Model repair receives tool-specific feedback without a duplicate original call in the feedback payload. Authorization and confirmation still apply after parsing.

Deletion guidance distinguishes empty write/truncation from removal. Successful empty writes return an explicit application note that the write did not delete the file. When command is permitted, instructions direct the model to exact quoted rm target and absence verification; read/chat/project-only modes do not gain arbitrary commands. This does not guarantee a small model's correct choice or truthfulness in every response. HTTP guidance covers quoted URLs, actual status/content and curl failures; exit0 alone is not proof of HTTP success.

Compatibility: com.termux / code1136 /1.4.30-test / same certificate. Optional localCompute defaults cpu for existing profiles. No automatic model/history/environment reset, installation or data deletion. Older builds can drop optional settings when rewriting the library. Finish important work before updating; Android can terminate running app processes. No GitHub release authorized for this build. NPU investigation remains a separate future task; required Qualcomm NPU runtime is not added by this update.
