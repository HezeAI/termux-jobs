## Телефонное наблюдение и причина

Пользователь сообщил: в1501 область чатов агентов чёрная, но обычные терминалы
и терминал агентского чата остаются с прежним фоном. Это отрицательная проверка
пункта17, а не приёмка терминального фона. Прежний отчёт1501 дополнен этим результатом.

`checkForFontAndColors` менял палитру и фон decor окна. Однако новый корневой
Activity layout и AgentTerminalScreen имеют графитовый фон поверх decor.
`TerminalRenderer` заливал Canvas только при reverse video. Стандартные ячейки
намеренно пропускают собственную заливку, поэтому обычный терминал оставался
прозрачным и показывал графитовую подложку.

Общий renderer теперь на каждом кадре заливает всю область текущим background;
в reverse video использует прежний foreground. Значение по умолчанию — чёрное.
Явные пользовательские цвета, OSC/ANSI, инверсия, текст, выделение и ввод сохранены.
По дополнительному поручению изменена шапка агентских чатов (см. ниже).
Последующие уточнения composer/библиотек/диктовки перечислены ниже.
Extra keys, PTY, история, авторизация, запуски и управление X11 не изменены.
Нет миграции данных или изменения package/minSDK/targetSDK/разрешений.

## Дополнение — новая шапка агентских чатов

Новое поручение заменило прежнюю неизменность шапки только в агентских чатах.
Порядок: меню, «Чат» с названием и папкой, терминал со значком, перезапуск.
Кнопки имеют отдельную подложку/обводку текущей палитры; заголовок — читаемую
подложку. Промежутки прозрачны. Имя/путь — по одной строке с многоточием;

авторизации, пересчитывает отступ через существующее сохранение якоря чтения.
Первые сообщения при начале истории расположены ниже шапки; ручная прокрутка

## Дополнение — ширина рабочей области

После inflate TermuxActivity.setMargins повторно применял terminal-margin-horizontal
к общему root_relative_layout. Поэтому одного нулевого margin в XML было недостаточно:
сужались и чат, и обычный/агентский терминал, и встроенный X11. В портретном режиме
эффективный внешний горизонтальный margin теперь0; в landscape сохранено прежнее
значение. Configuration callback применяет правило при повороте и возврате.
Файл настроек не переписывается. Вертикальный отступ и fitsSystemWindows/системный
обработчик insets не меняются. Внутренние отступы текста/карточек, включая чёрные
внутренние16dp обычного терминала, сохраняются внутри полноширинной поверхности.

У AgentChatView, AgentTerminalScreen и X11-хоста уже MATCH_PARENT без своих внешних
боковых отступов. AgentTerminalScreen поднимается над прозрачной шапкой чата:
полноэкранные файлы/терминал не должны оставлять её кнопки поверх нового экрана.

X11-код/нативные библиотеки не меняются: RemoteDesktopView.onMeasure использует
новые размеры хоста; onLayout/resize передаёт геометрию. Автоматический X11DisplayMode
сохраняет пропорции, LorieView пересчитывает касания по текущему viewport.
Явные безопасные отступы/ручное разрешение X11 пользователя не сбрасываются.
Стенд проверяет автоматическую геометрию/координаты и цикл portrait/landscape/portrait;
это не проверка настоящих Surface/GPU/IME/cutout на телефоне.

  Четыре агента, отсутствие повтора истории/перерисовки, скрытый экран и disable

  списка ввода системная отмена закрывает окно к исходной сессии, не возвращает
  скрытый список. Отдельной кнопки Back нет; CRUD/поиск/категории сохранены.

Диктовка: текущий маршрут — внешняя Android Activity ACTION_RECOGNIZE_SPEECH.
Проверка package manager телефона только чтением, с --user0: **No activity found**.
query-services на RecognitionService обнаруживает одну службу, но это другой
интерфейс и не доказывает наличие Activity/работу микрофона. Попытки запроса без
--user0 и чтения secure default-service отклонены правами Android; настройка не
определена, не изменена. Данные авторизации и голос не читались/не записывались.

Owner результата раньше зависел от AgentChatUi.handlesComposer (activityStopped/
mIsVisible). Результат до onResume мог отклоняться как результат другого чата.
Owner теперь проверяет текущую выбранную агентскую запись/handle и closed, без
видимости. Повторные результаты, изменение handle/черновика, пустой результат,
отмена и исключения не изменяют текст. Распознанный текст добавляется в конец
через пробел при необходимости; выделение больше не заменяется. Автоотправки нет.
Ошибки показываются заметным диалогом Voice input вместо краткого Toast.

Для внешнего окна приложение не захватывает микрофон само и не добавляет
RECORD_AUDIO. Доступ к микрофону обеспечивает выбранный Android-провайдер;
SecurityException обрабатывается отдельно. Отсутствие Activity обработано явно.
Никакие пакеты/подключения/разрешения телефона не изменялись. Новый внутренний
SpeechRecognizer backend не добавлен; настоящая диктовка на этом телефоне остаётся
недоступной через текущий маршрут до появления совместимого Activity-провайдера.
[Контракт RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent#ACTION_RECOGNIZE_SPEECH),
[жизненный цикл Activity](https://developer.android.com/guide/components/activities/activity-lifecycle).
