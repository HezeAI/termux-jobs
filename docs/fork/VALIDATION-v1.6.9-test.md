# Проверочная v1.6.9-test — пакеты окружений

Пакет com.termux, versionCode1205, Android8+/ARM64. Прежний сертификат:
`dd37d983cd2496ebe49c7e88ddbc0088f311d38b8a8503e4392c81b48a11a644`.
APK `Termux-Jobs-v1.6.9-test-arm64.apk` — 36686789 байт.
SHA-256: `2a2e414d513a6d59951fc3a49e7c7129c7f700bbef69c4c6f34d94a0eddd7417`.

29 целевых JVM-тестов прошли без ошибок (PackageCatalog, WorkspacePackages,
EnvironmentPackages, WorkspaceEnvironments). Проверены форматы шести менеджеров,
отклонение небезопасных имён/DTD XML, сохранение alias и isolated-режима,
явные команды без автоответа yes, неизменяющие каталог запросы, блокировка операции
при отсутствующем/другом маркере окружения. Проверка маркера выполнялась в отдельном
тестовом shell без запуска реального пакетного менеджера.

Сборка и DEX runtime прошли. Проверены целостность ZIP, com.termux, versionName/code,
minSdk26, ARM64, отсутствие debuggable, v2-подпись и совпадение сертификата.
Все assets и native-библиотеки побайтно совпали с1.6.8. В проверенных путях/маркерах
APK не обнаружены приватные ключи, файлы авторизации и пользовательская библиотека.
Это проверка известных признаков, не доказательство отсутствия любых возможных секретов.

Ревью: операции валидируют/цитируют имя пакета, не добавляют force/no-confirm;
новая сессия сохраняет точный alias/isolation; текущая сессия сверяет handle и alias.
Маркер предотвращает случайный запуск в хосте после выхода из гостя. Чтение каталога
идёт отдельным файловым транспортом в том же экземпляре. Старые Termux/Ubuntu
сохраняют APT, окружения агентов и серверные assets не менялись.

Логическая инспекция охватила определение менеджера, вкладки/описания, подтверждение,
запуск в текущей/новой сессии, закрытие окна и отсечение устаревших результатов загрузки.
Поддержка выбора версии остаётся APT-only. Pacman явно предупреждает о полном
обновлении системы. Дообновленческие proot-сессии без маркера должны использовать
новую сессию для операций.

Обновление с1.6.8/code1204: идентичность пакета/сертификата сохранена, код повышен,
формат библиотеки8 не менялся, очистка данных не предусмотрена. Реальную установку
поверх, отображение/каталоги/установку/удаление пакетов нужно проверить разработчику
на устройстве. Базовые запуски шести окружений подтверждены ранее в1.6.8;
это не подтверждает новые пакетные операции. Бэкапы — следующий отдельный этап:
сравнение пакетов пока APT/dpkg, восстановленный Void без OCI-манифеста ещё не проверен.
GitHub в этой задаче не публиковался; старые APK отката имеют меньший код.

## Проверки на устройстве и обнаруженная регрессия

Разработчик подтвердил Debian: список78 установленных/68276 доступных, успешный
apt-get update и установку tree2.2.1-1; tree --version вернул ожидаемую версию.
Скриншоты от19 октября18:33 показали регрессию Alpine: определён APT, команда
apt-get update вызвала защитный отказ Termux. В Alpine отсутствуют apt-get и
dpkg-query, но proot добавляет Termux bin в конец PATH. Поэтому поиск менеджера
ложно находил хостовый APT прежде гостевого APK. Эта сборка не считается
проверенной для остальных менеджеров; исправление подготовлено в1.6.10-test.
