# Очистка хранилища — v1.7.5

Шестерёнка → «Очистить хранилище», сразу под «Настройки приложения».
Это обзор состава с размерами, затем явный выбор для удаления. Ничего заранее
не отмечено. Общая память телефона не сканируется целиком и не очищается.

## Данные приложения

- Команды, заметки, сохранённые пресеты запуска и недавние команды показаны
  отдельно: количество и оценка объёма JSON. Раздел открывает выбор конкретных
  записей. Несохранённые сессии и базовый Terminal не удаляются как пресеты.
- Перед применением сравнивается полный снимок соответствующего списка;
  изменившийся список нужно открыть заново. Работающий выбранный пресет нельзя
  удалить. Меняется только нужная коллекция WorkspaceStore, schema8 сохраняется.
  Сообщение об успехе появляется после завершения обычной AtomicFile-записи.
  Системная ошибка записи показывается существующим обработчиком библиотеки.
- Сохранённые истории оболочек приложения показаны отдельным разделом по ID
  сессии: только выбранные папки workspace-sessions, закрытые сессии. Собственные
  разговоры CLI этим не удаляются. Их данные могут также находиться в HOME.
- Отдельный переход в браузер историй Codex использует штатный thread/delete,
  а не архивирование. Только при входе из очистки для его окон запрещён
  outside/back dismiss, а перед удалением добавлена обязательная галочка.
  Этот браузер не заявляется универсальным каталогом разговоров других CLI.

## HOME, PREFIX и окружения

Каждый обнаруженный Termux/Linux HOME и системная часть окружения показаны
отдельно. Обзор читает размеры без следования символическим ссылкам и показывает
состав верхнего уровня. В гостях отдельно показаны /root и /home при наличии.
PREFIX Termux не включает хранилище proot-distro, поскольку окружения перечислены
отдельно. Кэши и архивы могут входить в размер HOME/системы; размеры разделов нельзя
безусловно складывать. Недоступные деревья помечены, размер является оценкой.
Полный обзор читает файловую систему, поэтому на большой среде занимает время;
предусмотрены кружок в кнопке «Обновить», однострочный прогресс и отмена.
Используется тот же WorkspaceBackupScanHeader, что и в бэкапе: список/терминал
не перестраиваются на каждом файле. После завершения заменяется состав окна.
«Обновить» запускает новый анализ; повторный анализ сбрасывает выбор.
Фонового постоянного сканирования нет.

В HOME можно выбрать отдельные файлы и папки верхнего уровня. Выбранная папка
удаляется со всем содержимым, включая проекты, настройки и авторизацию; её путь
есть в окне. Сам корень HOME сохраняется. Ссылки удаляются как ссылки, их цели
(в том числе общая память) не затрагиваются. Специальные файлы блокируют подготовку
соответствующего плана. Недоступные записи недоступны для выбора.
После выбора строится свежий снимок. С версии1.7.66 список файлов и каталогов
HOME/историй записывается построчно в приватные файлы: прежние пределы
60000 записей/8MiB не ограничивают этот список. JSON-план содержит только
метаданные этих файлов и сохраняет предел8MiB. Чтение и обратный обход
каталогов выполняются блоками, без загрузки всего снимка в память. Для
старых операций очистки кэша/отчётов/архивов ограничения пока сохранены.
После подготовки показывается отдельное подтверждение выбранного удаления.
При выполнении перед удалением проверяются идентичности временных списков.
Никаких rmtree по произвольному пути, следования в /sdcard или удаления новых
файлов, появившихся после снимка, нет. При подготовке сверяются прежние identity
выбранных элементов, при выполнении повторно сверяется весь снимок группы.

**PREFIX/системная часть доступны для просмотра, но не для удаления целиком.**
Это работающий runtime, Python и база установленных пакетов. Удаление обошло бы
пакетный менеджер и могло лишить приложение возможности выполнять очистку/запуск.
Для отдельных установленных программ остаётся «Установка пакетов».
Целиком Linux-окружение теперь можно выбрать галочкой в общем списке или удалить
кнопкой «Удалить это окружение целиком» из его системного состава. Это относится
к исходным и восстановленным современным контейнерам: HOME, проекты, программы,
авторизация и настройки внутри выбранной среды удаляются вместе.

Используется только штатный proot-distro remove alias, без shell/force/kill или
резервного rmtree. Допускаются только заново выведенные существующие aliases
containers/<alias>/rootfs, без ссылок в корне; inode корня и контейнера сверяются
с планом. Менеджер должен поддерживать exclusive nonblocking remove locks и
shared login locks. Иначе выбор удаления целой среды недоступен. Legacy layouts
не получают небезопасного обхода. Native lock самостоятельно отказывает, если
среда используется в другой CLI-сессии. Перед передачей native remove приложение
тоже дважды проверяет свои открытые сессии; текущую рабочую Ubuntu удалить нельзя,
пока она используется. Отдельный кэш/архив внутри уже выбранной целиком среды
нельзя выбрать вместе с ней: пересекающийся выбор требует уточнения.

Пресеты запуска и архивы вне удаляемого контейнера сохраняются. Среду можно
установить заново из пресета. Это не обещает восстановление удалённых файлов.
После явного подтверждения начинается штатное удаление; отмены во время операции,
содержащей окружения целиком, нет, о чём предупреждает итоговое окно. Android
может завершить процесс извне: результат тогда нужно перечитать повторным
анализом; атомарное удаление всего контейнера или откат не обещаются.
Полного сброса самого PREFIX Termux из работающего приложения нет.

## Кэши, отчёты и архивы

- Загруженные архивы пакетов Termux/APT и конкретных современных proot-окружений:
  APT, APK, DNF, Zypper, XBPS, Pacman. Индексы и базы установленных пакетов,
  установленные программы и активные partial-загрузки APT здесь не очищаются.
- Сохранённые приватные workspace-diagnostics/*.txt, не текущий журнал в памяти.
- Распознанные каталоги бэкапа Termux Job’s в выбранной папке (по умолчанию
  Download). Другую папку выбирает наш файловый менеджер; при отсутствии доступа
  предложены запрос Android-разрешения и повторный анализ.
- Незавершённые новые бэкапы — только с приватной записью происхождения,
  совпадающими путём/dev/inode и INCOMPLETE. Старые неопознанные папки не предлагаются.
- Восстановленные окружения входят в общий выбор удаления целых сред.
  Отдельных дублирующих пунктов удаления в бэкапе и очистке больше нет.

Выбранный архив удаляется целой папкой с копиями данных; оригиналы за её пределами
сохраняются. Поддержаны распознанные каталоги нашего формата, не любые чужие TAR.
Android cache и произвольные файлы вне перечисленных компонентов не очищаются.

## Подтверждение и отмена

В списке указаны размеры и число файлов. «Продолжить» доступно после выбора.
Далее итоговый список и обязательная новая, изначально снятая галочка
«Данные могут быть потеряны навсегда». Без неё кнопка «Удалить» неактивна.
Python worker также требует acknowledged=true и непустой выбор. Для удаления
записей библиотеки используется та же форма согласия без файлового worker.

Выбор, подтверждение и процесс очистки не закрываются тапом за рамками или
системной кнопкой «Назад». До запуска удаления есть «Отмена». Для сканирования
и удаления только отдельных файлов отмена доступна и во время операции. Во время очистки отмена прекращает
дальнейшие операции, но уже удалённые файлы не восстанавливает. После ошибки
возможен частичный результат; отчёт показывает выполненное и пропуски.
Согласие на удаление целых окружений тоже обязательно; принудительная отмена
native remove после запуска не введена. Результат отдельно перечисляет удалённые
окружения, не выдавая их размер за точный подсчёт отдельных unlink-файлов.

## Защита от изменений и занятости

В приватном плане сохранены только найденные цели и их идентичность. Перед
удалением они повторно проверяются; истёкший план требует нового анализа.
Обход и удаление используют directory fd и O_NOFOLLOW, не следуют ссылкам;
нет рекурсивного удаления произвольного пути из UI-запроса.
Для кэша цели повторно сверяются с известными каталогами конкретного экземпляра.

Связанные открытые сессии проверяются перед подтверждением и запуском. Для
незакрываемого базового Terminal проверяется отсутствие foreground-команды;
неизвестное состояние блокирует очистку. Worker дополнительно берёт native
nonblocking container lock (proot) или POSIX locks APT/dpkg (Termux). Если
поддерживаемая блокировка недоступна или занята, группа не очищается. Ни одна
пользовательская сессия не останавливается автоматически.

Проверки inode/mtime не являются sandbox против программы с тем же Android UID.
Завершите задачи, изменяющие выбранные данные. Размер — сумма логических размеров
выбранных файлов; реальное освобождение места может отличаться из-за ссылок,
открытых файлов и особенностей файловой системы.

Очистка и бэкап используют один BUSY worker: параллельная операция не запускается.
Результаты анализа/служебные receipts хранятся приватно; фонового периодического
сканирования и отправки данных нет.

Временные списки имеют случайные имена, права0600, открываются без перехода
по ссылкам и удерживаются открытыми до конца проверки/удаления. Изменение
пользовательского файла после сканирования блокирует удаление до первого unlink.
Отмена/ошибка подготовки убирает созданные списки. После исполнения план и
списки удаляются; брошенные файлы старше суток убираются при записи нового плана.
Для большого снимка требуется свободное место под список имён/идентичностей;
содержимое пользовательских файлов не копируется. Пользовательское удаление
40ГБ не выполнялось при разработке — проверялся разреженный тестовый файл
и более60000 настоящих записей внутри временной папки репозитория.
