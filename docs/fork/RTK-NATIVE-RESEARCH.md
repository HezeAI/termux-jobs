# Штатный RTK 1.1.0 OSS — исследование 2026-11-08

Исследование завершено до изменения приложения. Материалы: `.verification/rtk-native-research/`.
Рабочие чаты, авторизация и сохранённые правила не менялись. Реальные CLI использовали
фиктивный провайдер, изолированный HOME и kernel network guard. Это не реальные модели.
Исходники RTK: tag v1.1.0 /753a3b0e939f2e4490fc24e3a1984010f40a103c;
ARM64 binary SHA d4f0134696665b772dee21c8f8d8f58318ed560dae416d6048249765945d920a.

## Устройство и отличие от обычного режима

Штатный PreToolUse вызывает `rtk hook claude` / `rtk hook codex` и получает
updatedInput. Команды выбирает registry самого RTK; неподдерживаемые остаются обычными.
Добавляются штатные Git/поиск/чтение, сборки Gradle, языковые тесты, Docker/Kubernetes
и остальные возможности OSS-версии, включая доверенные пользовательские фильтры.
Это не обещание сокращения любого вывода. Engine edition не входит в OSS.
Обычный режим сохраняет наш ограниченный список, исходную команду перед фильтром stdout
и собственные originals/байтовую статистику. В расширенном выполняется `rtk …`.
RTK init глобально меняет инструкции и hooks: для per-chat интеграции его запускать
в рабочем HOME нельзя. Нужны session-scoped hooks, делегирующие RTK без нового списка.
Проверенный scoped dispatcher выбирает только off/basic/advanced; правила RTK не заменяет.

## Точные проверенные права

- Codex0.166.0, danger-full-access + approval=never: forbid [git,diff] не блокирует
  rtk git diff; forbid [rtk,git,diff] блокирует. При выключении original forbid снова
  блокирует. Сохранённый файл правил не изменился.
- Codex0.166.0, danger-full-access + approval=untrusted: native decline блокирует
  преобразованную команду. Не означает проверку всех вариантов approval.
- Claude2.1.296, SDK/manual (native default): native can_use_tool decline сохраняется.
- Claude2.1.296, CLI/default с --allowedTools Bash: файловый deny Bash(git diff*)
  RTK читает и не преобразует; native deny остаётся. Только --disallowedTools без
  файлового deny не учитывается RTK и не блокирует преобразованную команду.
- Claude/default: файловый ask Bash(git diff*) + --allowedTools Bash. БезRTK требуется
  разрешение; с RTK команда проходит. Это конкретный конфликт ask и общего allow,
  а не отключение всех файловых ограничений.
- Auto/acceptEdits/plan/Bypass, Codex on-request и успешный sandboxed запуск в этом
  исследовании не подтверждены. Ранее sandbox fixtures упёрлись в bubblewrap mounts.
  Обязательные ограничения CLI не обходить; root-запрет Claude Bypass сохраняется.

Предупреждение Codex:
«Некоторые запреты по префиксу исходной команды могут не срабатывать после преобразования в RTK. В проверенном режиме untrusted подтверждения сохраняются».
Предупреждение Claude:
«Некоторые запреты и правила подтверждения Bash-команд могут не срабатывать после преобразования в RTK. Это не означает отключение всех файловых ограничений».
Кнопки: «Отмена» / «Включить RTK штатный».
Не менять persisted rules, approval или sandbox. Серым делать только редакторы
несовместимых исходных Bash/prefix правил; показывать текущее значение и
«Для изменения отключите RTK штатный». Не выключать общую проверку разрешений.

## Изоляция и восстановление

pair-assertions.json: четыре пары /24 хода. Для каждого агента два параллельных
процесса разделяли HOME, рабочую папку и бинарник RTK. У A цикл true/false/true,
у B false/false/false. A сокращает только в двух включённых шагах, B не меняется.
Codex original deny срабатывает у A в выключенном шаге, у B во всех трёх.
RTK_DB_PATH и RTK_RECALL_DB различаются по profile UUID, состояние отдельно.
Первый Codex pair не засчитан: одновременная миграция новой SQLite native state
сорвала запуск одного процесса. После отдельной инициализации базы оба прошли;
тест теперь проверяет завершённые RPC и реальные результаты, а не только exit0.

Последнее решение пользователя: восстановление ВКЛЮЧЕНО. Не задавать RTK_RECALL=0
или retriever.mode=disabled. Старые probes с отключением — только исследование
возможности, не итоговая конфигурация. В финальных pair recovery включено.
Проверено: у A штатная recall.db содержит запись, у B её нет. Модели передаётся
сокращённый результат с `rtk recall <hash>`; скрытая строка399 отсутствует.
Отдельный `rtk recall --full <hash>` возвращает и первую, и последнюю строки.
Простой recall возвращает пропущенную часть; --full нужен для всего сохранённого.
Полный журнал автоматически не добавляется в model input.
Штатные пределы: 200 записей, 30 дней, 10MiB на запись; большие результаты могут
сохраняться частично. Не обещать бесконечное хранение полного вывода.
RTK history.db содержит estimated tokens, не реальные байты и не лимит подписки.
Расширенную статистику нельзя подписывать как измеренную экономию всего контекста.

## Gemini и OpenCode

Gemini0.64.0 имеет BeforeTool и hookSpecificOutput.tool_input. RTK hook gemini
проверен на JSON fixtures; полноценный native chat/model путь ещё не проверен.
Штатный init Gemini глобальный: использовать только scoped регистрацию/dispatcher.
OpenCode2.0.28-jobs1 совместим по заявленной версии с upstream plugin2.x execute.before.
RTK plugin вызывает stock hook opencode; JSON rules tests показали отказ от rewrite
при изменении файлового verdict deny/ask/allow. Первый fixture ошибочно использовал
XDG_CONFIG_HOME: RTK читает ~/.config/opencode либо OPENCODE_CONFIG. Исправленный прошёл.
В приложении есть live session permissions через API; stock RTK не получает их из
этого API. Нужна отдельная сверка. Подключение OpenCode пока не подтверждено.

## Реализация следующего этапа

Две взаимоисключающие галочки: «RTK штатный» слева, «RTK Lite» справа.
Сохранить обычный механизм. Расширенный отправляет native hook payload целиком
в stock RTK, без собственного списка и изменения сохранённых прав. Согласие отдельно.
У каждого чата свои state, tracking и recall; один binary на Ubuntu AI.
Не менять общий HOME/XDG всего агента ради RTK. Scoped RTK launcher задаёт только
свои пути для дочернего RTK, сохраняет штатный PATH/конфигурацию остальных процессов.
Отключение прекращает автоматический rewrite, не удаляет компонент или вывод.
Проверка UI/телефона, реальные модели и другие права остаются отдельными этапами.
