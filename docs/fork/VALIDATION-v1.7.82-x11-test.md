# Проверки v1.7.82-x11-test / code1297

Частная сборка для проверки Void. GitHub-публикации нет.

## Подтверждённая причина

В отчётеv1.7.81 установка X11 Void не дошла до запуска стола: XBPS завершился с кодом9, причина reposync и подписи пакета — No route to host. Прямая попытка войти во второй proot из текущей Ubuntu отклонена штатной защитой вложенного запуска. Защита не обходилась, работающие сессии не менялись.

Для изолированной проверки запущен существующий xbps-fetch и glibc/библиотеки из rootfs Void через его ld-linux, с выводом только в .verification/void-network. Это реальный клиент XBPS, но не полноценная сессия Void: DNS/CA-пути остаются текущей Ubuntu. resolv.conf Ubuntu и Void при чтении совпали. Тесты не устанавливают пакеты.

По умолчанию XBPS разрешил repo-default.voidlinux.org в IPv6 2a01:4f9:3a:17d7::2 и получил No route to host, код1. При FORCE_IPV4=1 тот же URL подписи libICE-1.1.2_1 скачался, код0,512байт, TLSv1.3 и проверка имени/сертификата включены. Отдельный TCP-пробник подтвердил: AF_INET успешно, AF_INET6 errno113. Это воспроизводит сетевой сбой текущего соединения, а не доказывает отсутствие IPv6 на всех телефонах/сетях.

Штатная переменная описана в руководстве Void:
https://man.voidlinux.org/xbps-fetch.1#ENVIRONMENT

Свидетельства: .verification/void-network/{xbps-loader-probes.json,socket-probes.json,summary.json}. Системные настройки и rootfs не изменялись; загружена только подпись512байт в каталог проекта.

## Изменение

При вызове XBPS приложением задаётся FORCE_IPV4=1 и снимается конфликтующий FORCE_IPV6 только у дочерней команды:

- x11-native-desktop.sh: проверки настроенности пакетов, обновление индекса и установка стола Void через локальную функцию с subshell.
- x11-native-programs.py: run/output для xbps-query/install/remove/fetch получают отдельную копию env; apk/apt/dnf/zypper/python и родительский os.environ не меняются.
- EnvironmentPackages.java: список/обновления/описание пакета, refresh/install/upgrade/remove XBPS выполняются в отдельном subshell. PATH выбранного гостя и защита имён пакетов сохранены.
- X11StartupLog: No route to host / Network is unreachable получают фиксированную категорию NETWORK_ROUTE_UNAVAILABLE.

Настройки DNS, зеркала, сертификаты, системный IPv6, среда XFCE и ручные команды пользователя не переписываются. Механизм запуска/остановки процессов и продолжение пакетных операций не менялись. Проверки TLS/GPG и зависимостей не отключались. Удалённый предварительный загрузчик окружений изv1.7.81 не возвращается.

## Ограничения и следующий тест

Полная установка XFCE/программ Void этой сборкой на устройстве ещё не проверена. Минимум: обновить APK и повторить установку X11 Void; затем проверить обновление каталога и одну небольшую программу. При отказе сохранить Диагностика сессии → X11 сразу после ошибки. Тест клиента вне полноценного входа Void ограничивает вывод; успешная подпись не доказывает загрузку каждого пакета.

Принудительный IPv4 требует работоспособного IPv4-маршрута; IPv6-only сеть этой сборкой не проверена. Исправление специально ограничено управляемыми командами XBPS, остальные окружения и программы сохраняют прежний выбор сети.

Пакет/сертификат сохранены, versionCode1297 выше1296. Форматы пользовательских данных не меняются, сбросов/миграции нет. Установленные окружения/процессы в ходе разработки не изменялись.
