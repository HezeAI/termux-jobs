# v2.0 — launching an agent through your own server

The optional **connection command** field is intended for your own server-based
launch route: for example, an SSH tunnel and proxy established by your own
launcher script. It stores the **absolute executable script path inside the
selected environment**, not an IP address, password, token or arbitrary shell
command. The launcher receives the agent command/arguments and must execute
those arguments after preparing the connection. An empty field keeps ordinary
startup. Apply changes by restarting that agent with the intended existing chat
selected; running chats are not automatically rerouted. The app includes no
personal proxy/server credentials or preconfigured public proxy.

The rest of this document records the implementation and earlier private checks.

# Необязательный запускатель подключения агента

Начиная с частной v1.7.92-x11-test в настройках сессии/пресета AI Agents,
выше расширенного дебаг-журнала, есть «Команда подключения (необязательно)».
Поле доступно агентам в Ubuntu/Ubuntu AI; старые Codex Termux-профили его
не используют. Пустое поле оставляет прежний запуск без изменений.

Это **абсолютный путь к исполняемому файлу выбранной Ubuntu**, без кавычек,
аргументов и shell-выражений. При запуске ему передаются программа и аргументы
всего штатного блока подготовки/запуска агента. Например:

```sh
#!/bin/sh
# Здесь можно проверить соединение, выполнить подготовку,
# задать переменные только для дочернего процесса.
exec "$@"
```

Запускатель — доверенный пользовательский код с правами процесса Ubuntu,
как команды запуска. Не следует выбирать непроверенные файлы. Аргументы
из приложения экранируются; содержимое пути не интерпретируется как команда.
Путь сохраняется в профиле и его резервной копии, поэтому секреты в него
помещать нельзя. Сам скрипт, ключи, адреса серверов и авторизация в APK не входят.
Если файл отсутствует, не исполняется или возвращает ошибку, приложение
не повторяет запуск автоматически без него.

Сохранение меняет профиль, а не окружение работающего процесса. Для применения
нужно перезапустить соответствующую сессию. В Codex при сохранении сохраняется
доступная привязка к текущему материализованному чату, если пользователь
не выбрал другой. Перед перезапуском проверьте выбор текущего чата вместо
«Новый чат». Настройка не перезапускает соседние сессии и не меняет shell-профили.
Для отмены очистите поле и перезапустите ту же сессию с тем же чатом.

Обработка поля общая для Ubuntu-агентов. Поддержка конкретного сетевого прокси
зависит от CLI. Сетевая проверка проведена только для Codex; совместимость
Gemini/Claude/OpenCode с этим прокси не заявляется.

## Изолированный SSH/GeoHide-пример этого телефона

Исходники: scripts/codex-geohide/. Личная конфигурация и запускатели находятся
в ignored .tools/codex-geohide/; в APK не упаковываются. В новое поле указывается
путь к agent-via-selectel из этой папки. Подробные команды, результаты реального
потокового запроса и разрыва SSH, отключение и откат описаны в её README.txt.
Авторизация Codex остаётся на телефоне; relay передаёт непрозрачный TLS.
Серверный proxy слушает только loopback. Общий /etc/hosts не меняется.

Подготовленный скрипт Termux:Boot не активирован. При использовании поля
туннель запускается по требованию, а собственный менеджер восстанавливает SSH.
Новый вход в аккаунт, фактический refresh истёкшего токена и устойчивость к
выгрузке Android требуют отдельной проверки; не имитируются перезапуском
пользовательских сессий.

## Совместимость

Добавлено необязательное строковое поле agentConnectionCommand в прежнюю
схему хранилища. Старые записи читаются с пустым значением. Данные не очищаются.
Старый APK игнорирует это поле: при откате запуск снова станет обычным.
Автоматического переноса пользовательских скриптов/ключей между Ubuntu нет.
