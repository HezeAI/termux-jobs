# Проверка v1.7.98-x11-test / code1313

Разработчик показал след старых положений Thunar в Touch Workspace: во время
движения он появлялся, после отпускания исчезал. Затем выбран обычный способ
управления мышью, с сохранением оформления Touch. Оба изменения входят сюда.

## Управление

Удалено подключение X11DirectTouch и его код из рабочего APK. Пальцы теперь
всегда идут в прежний X11Touchpad, как в обычном XFCE: относительное движение
курсора, тап, hold+drag, прокрутка двумя пальцами и двухпальцевый правый щелчок.
Мышь/перо не меняются. Галочка Touch отвечает за оформление, не за смену ввода.
Обновлена подсказка RU/EN, JSON/Binder и сохранённые настройки не мигрируются.

## След при движении

Read-only проверка показала xfwm4 --compositor=off. GTK3 создаёт X11-окна с
background=None; системное восстановление фонового изображения откладывается
до рисования клиента. Это соответствует наблюдению, но скриншот сам по себе
не устанавливает единственную причину артефакта.

В собственное GTK-окно Touch добавлен один background pixmap. Снимок рисуется
из своих виджетов через gtk_widget_draw поверх непрозрачной основы, без чтения
пикселей экрана/чужих окон. X11 получает фон самого окна, native-дети с той же
глубиной наследуют его. Он восстанавливает открывающиеся участки без ожидания
очередной отрисовки GTK. Кэш обновляется по изменениям текста, прокрутки,
геометрии и композитора после собственного paint. Постоянного таймера нет.
С композитором ветка не используется; его политика и драйверы не меняются.

Pixmap имеет предел4096×4096 с учётом scale. Старый освобождается после замены,
при ошибке новая запись откатывается и ресурс освобождается; X11 errors
перехватываются в локальной GTK-связи. При закрытии освобождается собственный
pixmap, при гибели процесса ресурсы X11 освобождает сервер. Чужие window/root
attributes и процессы не изменяются.

Первичные источники:
- https://docs.gtk.org/gdk3/method.Window.set_background_pattern.html
- https://github.com/GNOME/gtk/blob/gtk-3-24/gdk/x11/gdkwindow-x11.c
- https://github.com/xfce-mirror/xfwm4/blob/master/src/moveresize.c

## Проверки и границы доказательств

- 71 JVM: прежние жесты9, X11Integration34, WorkspaceDesktopStyle7,
  DesktopKeyboardState11, FocusStream5, DesktopProcessAsset3, DesktopSessionBar2.
  Они проверяют отмену/удержанные кнопки, относительное перемещение и отсутствие
  ложного drag, прокрутку/правую кнопку, границы окружений и сохранение настроек.
  Javap скомпилированного LorieView подтверждает finger→X11Touchpad.event.
- Native C собран с Wall/Wextra/Werror, реальный Bionic executable загружает
  GTK/Xlib/Cairo и проходит runtime self-test. Offscreen/Broadway-сборка того же
  кода отрисовала собственные карточки и фон. Production background_render
  дважды очищал разные старые цветные пиксели: итоговые PNG побайтно совпали,
  SHA256:e3662c3f67c3c1dbe4cbb671b795af397fe31b9e5480c1b0726a7e939643bfc8.
  Оба изображения просмотрены. Это проверка собственного снимка, не живого
  server-side pixmap и не устранения следа на Android.
- Ревью/логическая инспекция: invalidation→снимок своих виджетов→XSetBackground
  собственного окна→замена/освобождение, границы visual/depth/scale, compositor
  on/off и ошибки. Постоянных screenshot/tick/scan циклов нет. Удалён отдельный
  finger-адаптер; suspend/cancel прежнего X11Touchpad остаётся без изменений.
  Остановка guardian и чужие сессии не меняются.
- Release build и проверка DEX runtime прошли:13557 definitions, обязательные
  типы найдены,31 прежний unresolved имеют review notes. В DEX нет
  X11DirectTouch. JNI-контракты28/1/5 совпали, libXlorie и все прежние native
  библиотеки неизменны. В assets изменён только собственный Touch executable
  (48072 байт); оба ZIP оформления неизменны с v1.7.97.
  CRC, дубликаты ZIP entries, package/version/ABI/minSDK, подпись/v2 и SHA прошли.
  Приватные ключи/настройки/адрес Selectel не включены.
