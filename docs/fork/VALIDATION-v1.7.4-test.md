## Ревью и логическая инспекция

Удаление целой среды использует только alias из заново выведенных modern
containers/<alias>/rootfs без ссылок; root/container dev+inode совпадают с планом.
Поддержка штатных shared login/exclusive nonblocking remove locks обязательна;
legacy не получает обход. UI проверяет занятость до согласия и перед исполнением;
внешние CLI блокирует нативный менеджер. Он сам владеет exclusive lock, приложение
не берёт конфликтующую внешнюю блокировку и не останавливает сессии.

Пресеты и внешние архивы сохраняются, произвольных команд из плана нет. На ошибке
нет rmtree/force/retry с обходом защиты. Результат отдельно перечисляет реально
подтверждённые удалённые aliases и ошибки; точное число отдельных unlink внутри
native операции не выдумывается. Не заявляется атомарность всего контейнера:
частичное удаление при сбое возможно. Проверки inode/пути не являются sandbox
против произвольного процесса с тем же UID.

Если выбор содержит whole environment, после подтверждения worker не предлагает
отмену: убийство штатного remove могло бы оставить частично удалённую среду.
Предупреждение есть до запуска. Для сканирования и отдельных файлов отмена
сохраняется. Восстановленные копии находятся среди всех сред; отдельный дублирующий
пункт из cleanup UI убран. PREFIX самого Termux всё ещё только для просмотра.

Сканирование использует тот же WorkspaceBackupScanHeader, что в бэкапе. Тело и
подтверждение временно отключаются; во время поступления progress меняются только
spinner/строка, терминальные вкладки не перестраиваются. Новое содержимое строится
после DONE. Отмена закрывает owned scanner, поздние callbacks не применяются;
ошибка разрешает повторное чтение. Новый анализ сбрасывает выбор, план свежий.

## Минимальная проверка разработчиком

Проверить spinner справа от заголовка, одну строку текущего пути, Отмену во время
анализа и повторное обновление. На ненужной закрытой тестовой среде проверить
галочку целого окружения и кнопку из его системного состава. Перед удалением
проверить имя и обязательное согласие, предупреждение об отсутствии отмены.
Сначала проверить отказ для открытой среды без остановки её сессий. После
реального удаления обновить список и проверить сохранность соседних сред,
пресетов и внешнего архива. Рабочую Ubuntu разработки для такого теста не выбирать.
Жесты/DPI/Android-разрешения и native удаление на устройстве ещё требуют этой
проверки; UI-моки не подтверждают их. Исторические проверки прежних функций —
VALIDATION-v1.7.3-test.md и VALIDATION-v1.7.2-test.md.
