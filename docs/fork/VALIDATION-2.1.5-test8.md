## Доступность распознавания

Read-only package manager телефона повторно: RECOGNIZE_SPEECH — No activity found;
RecognitionService — com.anthropic.claude/.bell.assist.ClaudeRecognitionService.
Это подтверждает отсутствие внешнего окна и наличие зарегистрированной службы,
но не язык, сеть или работу настоящего микрофона. Запрос dumpsys не дал подходящих
метаданных. Затем прочитан только AndroidManifest.xml установленного APK Claude:
служба exported=true, permission=android.permission.BIND_RECOGNITION_SERVICE,
intent action=android.speech.RecognitionService. Авторизация не читалась.
Этот результат подтвердил критерий отбора службы; первоначальная строка фильтра
BIND_SPEECH_RECOGNITION_SERVICE была ошибочной и исправлена до выдачи.
Наличие пригодной декларации не доказывает успешный bind/распознавание.
Доказательства: `.verification/ui-1503/speech-*.txt`, service-metadata.json и installed-speech-service.json.

Прежний маршрут не пробовал службу. Новый fallback предлагает пользователю
службы с enabled/exported/BIND_RECOGNITION_SERVICE. Выбор не меняет
системного провайдера. RECORD_AUDIO запрашивается только после выбора службы.
Отказ сохраняет текст; результат добавляется только к исходному handle и
неизменённому черновику. Поздние callbacks отменённой попытки отсеиваются epoch.
Сырой звук не сохраняется приложением и не передаётся адаптеру агента.
Выбранный системный провайдер может использовать сеть согласно своим условиям.

Если подходящих служб нет, сообщение предлагает включить голосовой ввод в
Android либо установить совместимый Android SpeechRecognizer; есть диктовка
клавиатуры. Ничего автоматически не устанавливается. Предупреждение само по
себе не засчитывается как работающая диктовка.
Штатный контракт: [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer).

## Первоначальные результаты

Первый прогон сохранил отказы старых ожиданий Chat, немедленного закрытия
AgentTerminalScreen и поиска «Среда запуска». Исправления fixtures используют
новый agent-title и отдельный project-screen; создание старого пресета сохраняет
свой выбор. Настройки существующей записи этого выбора не получают.
Журналы и исходные XML: `.verification/ui-1503/first-results`, tests.log.
Повтор:55 тестов,2 отказа (header/service fixture). В искусственном ServiceInfo
сначала был applicationInfo самого приложения: PM нормализовал package в com.termux.
Fixture исправлена на независимый test.provider. Затем ошибка проверки отмены:
Dialog.cancel поставил callback в очередь, а fixture сразу прислала результат;
добавлена обработка main looper перед поздним callback.

Шапка потребовала отдельной поправки: измерение высоты кнопки через layout listener
давало первый кадр53px против131px плашки при большом шрифте. Теперь высоты
согласованы в onMeasure за один layout. Координаты вложенных элементов проверяются
в координатах общего родителя; detached fixture не имеет window coordinates.
Исходные XML/логи сохранены в retry-results/final-initial-results. Финальный повтор ниже.

Первый APK gate остановился на старом утверждении «нет RECORD_AUDIO». Оно заменено
проверкой ожидаемого разрешения нового SpeechRecognizer-маршрута. Затем проверка
не нашла скопированный agreed-template-inputs.json; восстановлен согласованный
manifest из1502, без изменения шаблонов. Повтор прошёл, промежуточный APK не выдавался.
После правки высоты он сохранён в test-2.1.5-test8-before-height; финальный gate повторён.
