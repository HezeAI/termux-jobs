# AI Agents — v1.0.18

**Экспериментальная интеграция.** Поддержка в меню не означает, что все аккаунты,
модели, способы входа и восстановление истории проверены на реальном устройстве.

## Запуск и окружение

Создать сессию → Среда запуска → AI Agents → агент. Задайте проект/папку и
поддерживаемый вариант истории: новый чат, выбор чата или конкретный ID.
Codex сохраняет выбор Termux/Ubuntu; OpenCode, Claude Code и Gemini CLI — Ubuntu.
Саму Ubuntu необходимо заранее установить через proot-distro. «Создать и запустить»
проверяет/готовит частные компоненты агента, затем запускает его в этой вкладке.
Системные пакеты, shell-профили, Node/Codex/Bridge не обновляются адаптерами.

| Агент | История/управление | Что не подтверждено полностью |
| --- | --- | --- |
| Codex | Прежние проекты/ID, native права, модель/поведение/лимиты | Полная матрица моделей/окружений/устройств |
| OpenCode2.0.28 | Native server/mini, подключения, модель через reopen того же чата, автоматическое продолжение | Мерцание/resize не исправлены; не все провайдеры проверены |
| Claude Code2.1.296 | Native runtime, новый/выбор/ID, модель и native режимы | Реальные OAuth/аккаунт, ответы, история на телефоне |
| Gemini CLI0.64.0 | Новый/выбор/ID, модель/режим, явный способ входа | Успешный API-ответ/квота и вся история; личный Google OAuth отключён |

Смена модели OpenCode с переоткрытием текущей истории подтверждена пользователем.
Пробные terminal screen/resize/frontend механизмы v1.0.10–12 отменены вv1.0.13;
native адаптер сохранён. Автопродолжение истории возвращено вv1.0.15, отдельное
ручное «Сохранить чат сессии» отсутствует. Смотрите KNOWN-ISSUES.md, OC-001.

## Авторизация, режимы и данные

Аккаунты и подписки пользователь подключает штатно в CLI/браузере. OpenCode имеет
отдельные подключения аккаунтов/провайдеров. У CLI независимые runtime/данные;
адаптер другого агента не переносит Codex auth/history. «Полный доступ» не даёт
Android root. Режимы разных CLI имеют разные значения: читайте пояснение выбора.
Закрытие вкладки останавливает её процесс; сохранённый чат не является снимком
живой программы. Историей управляет соответствующий CLI, не bash transcript.

Google прекратил обслуживать личные Free/Pro/Ultra аккаунты через Gemini CLI
18июня2026: [официальное объявление](https://github.com/google-gemini/gemini-cli/discussions/28017).
API-key и организационные пути имеют отдельные условия. Фиксация auth policy и
её приватный путь устраняют локальное переключение/игнорирование настройки, но
не снимают серверное ограничение. Новым пользователям не обещается бесплатный
личный OAuth. Antigravity не включён; исследование: ANTIGRAVITY-PROBE.md.

## Диагностика

Долгий тап названия сессии → диагностика. Базовый сбор независим от окна и
работает автоматически; extendedDebug в сессиях/пресетах применяется при запуске.
Gemini получает native --debug, другие агенты — расширенную шкалу активности и
наблюдаемые коды, без неподдерживаемых флагов и обещаний полного HTTP trace.
В отчёте нет raw transcript, ввода/диалога, custom commands, URL/env или токенов.
Пауза/продолжение, приватный отчёт и Download описаны в [USAGE](USAGE.md).

## Создание

Новая сессия → Среда запуска → AI Agents → Агент.
Обычные среды теперь называются Termux и Ubuntu; «Как раньше» отсутствует в
новом выборе, но сохранённые legacy-профили продолжают читаться и запускаться.
После редактирования такого профиля можно явно выбрать Termux.

Codex сохраняет прежние Termux/Ubuntu, права, историю/ID и карточку модели,
поведения и лимитов. Авторизация берётся из выбранной среды. При необходимости
вход выполняется штатно в терминале/браузере. OpenCode не читает и не меняет
авторизацию `.codex`.

OpenCode в этой сборке запускается только в Ubuntu. При «Создать и запустить»
в той же вкладке проверяются компоненты, при необходимости устанавливаются и
затем запускается агент. Если компоненты уже готовы, загрузка не повторяется.
Нужна заранее установленная Ubuntu через proot-distro: сам дистрибутив этот шаг
не устанавливает.

Существующий Node.js 20+ можно использовать без замены. Если подходящего Node нет,
скачивается отдельный Node.js 22.22.1 ARM64 в
`~/.local/share/termux-jobs/agents/node-v22.22.1-linux-arm64`.
OpenCode v2.0.28 при необходимости ставится в `~/.local/share/termux-jobs/agents/bin`.
Npm теперь не требуется. Пути добавляются только в процессы этой интеграции:
системный Node.js, shell startup-файлы, Codex и Bridge не меняются.
При отсутствии curl/tar/xz/sha256sum/flock в выбранной Ubuntu bootstrap использует
APT только для этих вспомогательных пакетов; не делает upgrade/dist-upgrade.
Архивы закреплены SHA-256, временные файлы изолированы, установка защищена flock.
При ошибке/таймауте следующий запуск агента не выполняется; вкладка остаётся
с сообщением об ошибке. Скачивание требует интернет и свободное место.

Если до первого запуска каталог моделей/подключения недоступен, создайте сессию
с моделью по умолчанию для установки компонентов, затем повторите настройку.

## Подключения и модели

Общие настройки приложения → **Аккаунты и API-ключи**. Выбор подключения доступен
также в форме сессии. «Основное подключение» и новые именованные подключения имеют независимые
каталоги config/data/cache/state OpenCode. Нет глобального переключателя,
меняющего провайдера всех терминалов. Одна связь может содержать несколько
провайдеров: Google Gemini, OpenAI, Anthropic Claude и OpenRouter.

Ключ вводится в скрытом поле с отключённым сохранением состояния Android View.
Запрос передаётся локальному адаптеру через stdin, не аргументы команды.
Секрет хранится средствами OpenCode в приватной файловой области приложения;
это не Android Keystore и не защита от другого процесса с полным доступом к этой
области. Сохранение ключа не означает проверку оплаты, баланса или работоспособности
ключа. Оно не выполняет запрос к модели. OAuth провайдеров OpenCode и нестандартный
API baseURL в первом этапе не реализованы; штатный OAuth Codex сохранён.

Каталог моделей читается из API OpenCode. Название/ID, провайдер, доступные варианты
поведения передаются в Android UI; настройки, ключи и заголовки API отбрасываются.
Можно искать модель или ввести `provider/model`, затем подтвердить выбор.
Каталог не гарантирует доступ аккаунта. В новой сессии сохраняется и выбранный
вариант поведения; в работающей сессии изменения применяются после подтверждения.

Режимы Build/Plan и права теперь независимы. Build ориентирован на реализацию
задач/правки/команды; Plan — на анализ и подготовку плана. Под режимом и в его
списке есть объяснения. Plan при полном доступе не гарантирует запрет правок.

Уровни доступа:

- Полный доступ: allow без подтверждений в пределах видимых Ubuntu файлов;
  не даёт root Android и не создаёт ОС-песочницу.
- С подтверждениями: ask, исходный режим старых профилей. «Разрешать всегда» в
  самом OpenCode может сохранять project-scoped разрешение; не все действия
  после этого будут спрашиваться снова.
- Только чтение: deny всего, затем allow чтения, glob/grep, вопросов и проверки
  внешних директорий. Shell, edit/write/patch, subagent, MCP и неизвестные действия
  запрещены. Эти ограничения зависят от инструментов OpenCode, не от файловой ОС-sandbox.

Новая сессия получает выбранные permissions; resume обновляет permissions только
этого чата. Смена доступа работающего профиля блокируется — сначала закройте вкладку.
Выбор полного доступа требует отдельного подтверждения в форме. Субагенты и
плагины не должны считаться ОС-изолированными. Организационные политики OpenCode
могут дополнительно запрещать действия. Штатные permission-диалоги остаются в mini.

Строка модели в верхнем меню обновляется по проверенному серверному ответу после
применения. Модель и variant сохраняются одновременно; поздний первоначальный
status не перезаписывает новый выбор. Запрос модели/permissions не делает inference.

## История

Новые чаты создаёт API самого OpenCode без вручную заданного ID. Приватная
ссылка между профилем приложения и native ID сохраняется для повторного запуска
и получения истории. В v1.0.5 вручную созданные ID приводили к 403 бесплатного
провайдера. Для проверки бесплатной модели в v1.0.6 создайте новый чат. Старые
записи не удаляются и не переписываются; их ID и прежняя история остаются.

Новый чат / Выбрать чат / Ввести ID относятся к выбранному подключению OpenCode.
Истории Codex и OpenCode независимы. Дублирование профиля создаёт новый чат.
Сохранение вкладки проверяет существование истории и запоминает её ID. Если история
ещё не создана/недоступна, приложение предлагает сохранить только настройки для
нового чата. При продолжении несуществующего ID адаптер останавливается: он не
подменяет продолжение созданием нового диалога.

OpenCode сохраняет свой каталог чата в истории. Эта сборка не переносит существующий
чат в другой проект при resume; для нового каталога следует создать новый чат.
Закрытие вкладки не удаляет базу OpenCode. Список истории пока ограничен первыми
500 записями и не имеет полной пагинации. История интерактивной Bash и история
агента по-прежнему разные сущности.

## Управление и границы

OpenCode mini подключается к собственному локальному серверу каждой вкладки,
с привязкой к 127.0.0.1 и случайным паролем. UI общается через приватный Unix socket.
Общий фоновый сервис OpenCode не используется. Закрытие/рестарт вкладки сначала
отправляют stop её адаптеру. Адаптер останавливает только созданные им процессы.
При выходе клиента, сигналах и смене родителя предусмотрено завершение сервера.
Принудительное убийство самого адаптера SIGKILL/OOM и Android lifecycle требуют
отдельной проверки на устройстве; восстановление живого процесса не обещается.

Карточка OpenCode позволяет прочитать фактическую модель и изменить модель/поведение.
Лимиты OpenCode не вычисляются и не выдаются за данные Codex. Каталог/чтение истории
и статуса не являются inference; проверка v1.0.6 включала три коротких запроса только бесплатной модели без личных ключей: штатный CLI и исправленный адаптер ответили, прежний адаптер получил 403.
Установка и получение каталога могут использовать интернет для обычных загрузок.

Совместимость закреплена на OpenCode v2.0.28: API v2 экспериментальный; другая версия
не принимается без проверки. Текущий APK остаётся com.termux с прежним сертификатом.
Приложение не содержит пользовательских ключей, токенов или комплектного аккаунта.

## Откат

Отдельный APK **Termux-Jobs-v1.0.4-rollback-code1100.apk** содержит прежние исходники
v1.0.4 с увеличенным versionCode. Новая проверочная сборка: 1.0.10 / 1047.
Откат устанавливается поверх, без удаления приложения и данных. Он возвращает старый
интерфейс/поведение приложения, но не отменяет установленные Linux-пакеты и не
перематывает пользовательские файлы.

Формат библиотеки остаётся v8, добавлены необязательные поля. Старый reader читает
обычные данные и видит OpenCode-профиль как Ubuntu/Bash без команды запуска агента.
При записи старый интерфейс может отбросить дополнительные AI-поля профилей;
соединения и базы OpenCode отдельно остаются на диске. После возвращения новой версии
нужно выбрать агент и чат заново. `.codex` и его история при откате не удаляются.

После установки резервного кода 1100 следующая сборка для обновления должна иметь
versionCode **выше 1100**. Очистка данных/удаление приложения для отката не нужны.
Установка APK может завершить текущие терминальные процессы; history/resume не
сохраняет память произвольного процесса Bash.

## Смена модели OpenCode в v1.0.9

Выберите модель и поведение в верхнем меню, затем подтвердите **Переоткрыть**.
Приложение заменяет только принадлежащий этой вкладке mini frontend: тот же сервер,
connection, native ID и база истории остаются. Mini читает новый выбор с сервера
при запуске и показывает историю через штатный replay. Это история чата, а не
снимок памяти произвольного процесса терминала.

Проверка `/api/session/active` и inbox блокирует смену при активной foreground-работе
или очереди; после выхода mini состояние проверяется ещё раз. При гонке с отправкой
модель не меняется, интерфейс открывается снова. Фоновые задания OpenCode не обещаются
учтёнными этим foreground API. Во время операции поле управления временно недоступно;
ошибка не выдаётся за успешную смену. Неотправленный текст внутри mini может потеряться.
Поле ввода Android и соседние вкладки не меняются. Закрытие приложения/вкладки во время
переоткрытия отменяет дальнейший запуск frontend.

Мерцание вывода в этой версии не исправлено. «Пресеты запуска» — новое название
сохранённых профилей; «Добавить в пресеты запуска» не создаёт снимок живого Bash.

## Отображение OpenCode в v1.0.10

Штатный native replay истории оставлен: адаптер и бинарник OpenCode не переписаны.
Флаг mini --replay не менялся. На Android история в этой вкладке выводится вместе с
завершёнными DEC 2026 кадрами. После смены размера краткая серия вывода объединяется,
чтобы не показывать промежуточный reset и частично восстановленный чат. Это временный
RAM буфер вывода, не запись снимков/истории приложения на диск и не изменение контекста
агента. Во время такой серии отображение может отстать от процесса до 1,2 секунды;
ввод и выполнение команд не задерживаются этим механизмом.

Таймаут и ограничения объёма предотвращают бесконечное ожидание незавершённого кадра.
У обычных/Codex сессий фильтр выключен. Автовозврат просмотра вниз при новом выводе
оставлен. На телефоне проверьте пустой новый чат, поток ответа и переключение вкладок
с открытием/закрытием клавиатуры; тесты транспорта не заменяют такую проверку.

**Известная проблема:** пользователь проверил v1.0.10 — мерцание/рывки OpenCode
остались. Причина пока не установлена, работа отложена по его просьбе.
[OC-001 — важно исправить](KNOWN-ISSUES.md).

## Проверочная v1.0.11

OpenCode подключает размеры PTY после размещения новой карточки/поля ввода перед
первым кадром, чтобы не использовать промежуточную геометрию предыдущей вкладки.
Дополнительный resize buffer350–1200ms выключен. DEC2026 frame buffer и native
replay остаются. История, модель, доступ и данные соединений не менялись.
Постоянное --no-replay не включалось: оно убирает отображение сохранённой истории.
Это эксперимент, а не подтверждённое устранение мерцания на устройстве.

## Проверочная v1.0.12

Для mini используется отдельная сборка OpenCode v2.0.28/jobs1 из APK. Native
--replay при входе/смене модели остаётся, replayOnResize отключается отдельным
opt-in параметром host. Поэтому IME/переключение вкладок не должны заново выводить
всю историю. Официальный server/runtime и данные подключений не заменяются.
Тестовый native чат сохранил историю и модель через шесть resize без повторного
replay; реальное поведение телефона ещё проверяет пользователь.
[Устройство и сборка frontend](OPENCODE-MINI.md).

## Историческая локальная v1.0.13: возврат и ручное сохранение

Работа OpenCode возвращена к v1.0.9. Штатный mini --replay используется при
запуске/смене модели; DEC2026 buffers, resize batching/deferred attach и frontend
jobs1 отменены. Исторические разделы выше описывают предыдущие эксперименты.
Нынешние навигация, иконки, пакеты и названия пресетов сохранены.

Долгий тап по OpenCode-сессии → **Сохранить чат сессии**. Приложение через активный
локальный socket получает native ID, сохраняет привязку и пресет. Старый/закрытый
или ещё не подключённый процесс не может сохранить случайный ID. Запрос не
запускает отдельный сервер и не отправляет сообщения модели.

**Добавить в пресеты запуска** сохраняет настройки; без ручной привязки очередной
запуск начинает новый чат. Выбранный вручную существующий чат открывается один раз;
чтобы возвращаться к нему постоянно, используйте новый пункт долгого тапа.
Выбор «Новый чат»/другого чата/подключения в настройках снимает прежнюю привязку.
Копия пресета получает независимый чат. Ручное сохранение заменяет привязку только
этого пресета; прошлые native чаты не удаляются.

После обновления старые автоматически принятые чаты не считаются вручную сохранёнными.
Их ID/сообщения остаются в OpenCode; при необходимости выберите чат и сохраните его
новой кнопкой. Формат workspace v8 остаётся, добавлено optional aiSavedThread;
старые читатели его игнорируют. Нативная база сообщений по-прежнему пополняется
самим OpenCode. Кнопка управляет продолжением, а не записью/удалением сообщений.
Повторный native replay при resize может оставаться как в baseline; отсутствие
ручной привязки не является исправлением мерцания/автопрокрутки.


## Локальная v1.0.14: Claude Code

Создать сессию → AI Agents → Claude Code. Рабочий каталог относится к Ubuntu;
через кнопку папки выбирается Ubuntu-каталог. При «Создать и запустить»
проверяется/скачивается официальный `@anthropic-ai/claude-code-linux-arm64`
2.1.296. Нужны сеть и свободное место: бинарник около 257 MB плюс временный
архив; при отсутствии Node >=20 дополнительно скачивается частный Node 22.22.1
для контроллера. Сам официальный CLI не требует Node. Системные пакеты, Codex
и OpenCode при установке не заменяются. Повреждённый существующий runtime
сохраняется и запуск завершается ошибкой, не ремонтируется автоматически.

- **Новый чат**: новый UUID на каждый запуск (`--session-id`).
- **Выбрать чат**: штатный список Claude в терминале (`--resume` без ID).
  Это не список Android-диалога, как у Codex.
- **Ввести ID чата**: UUID для `--resume UUID`; существование проверяет CLI.
- Модель: по умолчанию либо Sonnet/Opus/Haiku; доступ определяется аккаунтом.
- **Подтверждать действия** (`manual`): разрешения запрашивает Claude.
- **Разрешать редактирование** (`acceptEdits`): автоматически принимаются
  правки и обычные файловые команды; это не подтверждение любых действий.
- **Планирование** (`plan`): режим анализа/плана Claude, не OS-песочница.
  `bypassPermissions` не предлагается: обход ограничений proot/root не добавлен.

Авторизация выполняется штатным CLI. Нужна поддерживаемая платная подписка Claude
или API с оплатой; ChatGPT Plus не подходит. При заданном `ANTHROPIC_API_KEY`
CLI может использовать API-биллинг вместо подписки. Приложение не хранит новый
токен в библиотеке пресетов, не пересылает авторизацию Codex и не печатает секреты.
История и политика её хранения управляются Claude (`~/.claude` по умолчанию),
закрытие вкладки приложения само эти файлы не удаляет. Очистка данных/удаление
Android-приложения требует отдельной резервной копии. Пресет хранит параметры,
не весь разговор. При «Новый чат» сохранённый пресет снова создаёт новый диалог;
для возврата выберите чат либо укажите UUID. Дубликат пресета начинает новый чат.

Плашка показывает только **параметры при запуске**. После `/model` не выдаёт их
за актуальную модель. Нажатие объясняет `/status`, `/model`, `/permissions`, `/login`.
Живое управление и лимиты, аналогичные карточке Codex, пока не интегрированы.
Изменения модели/режима в настройках запущенной сессии требуют закрытия и запуска.

### Разделение агентов

- Claude runtime: `~/.local/share/termux-jobs/claude-code`, приложение `.claude-control`.
- OpenCode runtime/подключения и Codex app-server остаются прежними.
- Контроллер Claude использует отдельный Unix socket с уникальным UUID запуска,
  права 0600, разрешён только запрос остановки принадлежащего ему дочернего CLI.
  При закрытии сначала SIGTERM, через 3 секунды SIGKILL только этому дочернему
  процессу, если он ещё жив. Никаких `pkill`, сигналов по имени агента или обхода дерева.
- Истории/аккаунты/контроллеры разделены, но Ubuntu и файлы выбранного проекта
  общие. Это не контейнерная изоляция: агент с доступом может редактировать общие
  файлы или выполнять команды. Для параллельных правок используйте разные копии/
  worktree. Отдельно запущенные самим агентом фоновые задания не объявлены
  гарантированно завершёнными вместе с CLI.

Optional Claude fields сохраняются в format v8; старые читатели игнорируют их и
видят Ubuntu-профиль без команды запуска. Это сохраняет читаемость библиотеки
при откате, но старая сборка не может запускать Claude-пресет как Claude.
Работу входа/пикера/клавиатуры/реального продолжения следует проверить на телефоне.
Официально поддерживается Linux ARM64, Android/proot отдельно не гарантирован.

Источники: [установка](https://code.claude.com/docs/en/setup),
[CLI](https://code.claude.com/docs/en/cli-reference),
[разрешения](https://code.claude.com/docs/en/permissions),
[подписка](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan).


## Локальная v1.0.15: Gemini CLI и автоматическая история OpenCode

Создать сессию → AI Agents → Gemini CLI. Работает в Ubuntu, каталог можно выбрать
кнопкой папки. Официальный npm-пакет 0.64.0 скачивается целиком (bundle + chunks),
проверяется SHA256 и запускается отдельным Node22.22.1. Это частная установка в
`~/.local/share/termux-jobs/gemini-cli`, не `npm install -g`. Компоненты, собственный
Unix-контроллер `.gemini-control` и process-stop отделены от остальных агентов.
Никакого копирования аккаунтов/токенов других агентов. Ubuntu и проекты общие,
разделение runtime не ограничивает возможности агента с доступом к общим файлам.

Для первичной проверки выберите **Login with Google** в штатном CLI и используйте
личный Google-аккаунт. Доступный бесплатный уровень зависит от региона/аккаунта.
Приложение не включает API-биллинг и не покупает подписку; выбор API-ключа или
Vertex AI — отдельные способы авторизации с собственными тарифами. Google может
запросить собственные проверки; их отсутствие не обещается. Не нужно оплачивать
Pro ради первой проверки CLI. Доступность моделей проверяет сервис.

- **Новый чат:** новый UUID при каждом запуске профиля в этом режиме.
- **Выбрать чат:** CLI открывает штатный `/resume` через initial interactive
  slash command после входа. Это список в терминале, не Android-dialog.
- **Ввести ID чата:** `--resume UUID`. Пикер/UUID относятся к выбранному проекту:
  для продолжения укажите прежнюю папку. Если разговор нужен в другой папке,
  автоматический перенос истории приложение не выполняет.
- Модель: по умолчанию, Auto/Flash/Pro (`--model` aliases).
- Разрешения: `default` подтверждает действия; `auto_edit` автоматически разрешает
  инструменты редактирования; `plan` предназначен для анализа/плана. Это штатные
  режимы Gemini, не отдельная OS-песочница. YOLO не предлагается в этом интерфейсе.
- Плашка показывает **при запуске**; живое состояние модели/лимитов не заявлено.
  В терминале: `/model`, `/stats`, `/auth`, `/resume`.
- История сохраняется Gemini в его `.gemini` и привязана к проекту. Native политика
  хранения может очищать старые чаты; используйте `/settings` для её настройки.
  Пресет приложения хранит параметры, не копию всех сообщений.

Внешний контроллер запускает один собственный CLI с `GEMINI_CLI_NO_RELAUNCH=1`,
чтобы штатный launcher не оставлял неуправляемого потомка. Код199 вызывает повторный
запуск собственного child под тем же socket, максимум5 быстрых повторов. Тип
авторизации переносится через штатный IPC auth-selected-type, не сам токен.
Stop/parent-loss блокирует restart; SIGTERM и через3s SIGKILL адресованы только
собственному child. Отдельные намеренно фоновые задания не объявлены гарантированно
остановленными вместе с CLI. Пользовательские/другие агентские процессы не сканируются.

Описания доступа теперь у всех четырёх агентов: в списке выбора и под текущим
режимом. Codex sandbox/approval flags, Claude permission-mode и OpenCode permission
rules не менялись. Plan/ограничения инструментов не выдаются за OS-изоляцию;
Codex sandbox поддерживается лишь там, где его может обеспечить Android/proot.

### OpenCode: изменение v1.0.15 по просьбе пользователя

Ручной пункт «Сохранить чат сессии» убран вместе с обработчиком. История продолжает
записываться самим OpenCode, а профиль сохраняет стабильный thread/alias между
запусками; адаптер сопоставляет alias с native chat ID и продолжает существующий
диалог. Сохранённый пресет той же сессии сохраняет эту привязку. Даже profile.aiChat
new больше не получает случайный alias при каждом запуске: это имя первого запуска,
а не команда забыть историю. Явный выбор «Новый чат», другой connection или копия
профиля создают независимый alias. Старые ручные aiSavedThread поддерживаются для
совместимости; старые resume-профили больше не сбрасываются на new при чтении.
При удалении несохранённого профиля его параметры исчезают как прежде, но native
OpenCode history не удаляется: нужный чат можно выбрать через историю подключения.
Терминальные буферы/screen/resize-функции и официальный mini v1.0.9 не менялись.

## Локальная v1.0.16: явный способ входа Gemini

В форме Gemini теперь **Вход Gemini: Google-аккаунт / API-ключ / Выбрать в терминале**.
Новые профили предлагают Google, существующие без поля geminiAuth читаются как auto
и сохраняют прежнюю работу. Для исправленного сценария закройте работающую Gemini
и выберите Google в её настройках либо создайте новую Gemini-сессию с Google.
Смена этого поля у работающего процесса требует закрытия, не применяется скрыто.

В фиксированных режимах контроллер создаёт только на время собственного запуска
приватный файл с native security.auth.selectedType/enforcedType. Google →
oauth-personal, API → gemini-api-key. GEMINI_CLI_SYSTEM_SETTINGS_PATH указывает
на этот файл только в окружении собственного child, не глобально. Node IPC/повторные
restart199 сохраняют выбранное ограничение. ~/.gemini/settings.json контроллер
не переписывает, токены не копирует/не выводит, клавиши/Enter не синтезирует и не
отбрасывает. Обычные настройки/авторизация самим CLI по-прежнему штатные.

Если обнаружены внешние GEMINI_CLI_SYSTEM_SETTINGS_PATH/DEFAULTS_PATH или
/etc/gemini-cli, фиксированный режим отказывает с пояснением использовать штатный
режим: существующие системные политики не заменяются и не обходятся. Режим auto
оставляет native environment/переключение авторизации как прежде.

На телефоне v1.0.15 после Google наблюдался переход к API. В read-only проверке
текущая настройка была gemini-api-key. В чистом native probe обычный и bracketed
ввод синтетического неверного кода оставляли oauth-personal — исходная причина
перескока не доказана; не заявляем причиной клавиатуру/очередь ввода. При новом
фиксированном Google native probe с заведомо старым API-преференсом дошёл до OAuth
code prompt, не изменив старый settings-файл и не показывая API-поле. Реальную
авторизацию пользователя/Google eligibility нужно проверить после установки.

Штатные settings описаны в [документации Gemini](https://geminicli.com/docs/reference/configuration/).
Остальные агенты, разрешения, история OpenCode и терминальный ввод не менялись.


## Локальная v1.0.17: приватный путь Gemini auth

Policy теперь создаётся под `~/.local/share/termux-jobs/gemini-cli/auth`

## Локальная v1.0.18: диагностический журнал

Базовый сбор запуска/выхода и наблюдаемых error-кодов работает независимо от окна
диагностики, включая service callback без Activity. На создании сессий/пресетов
доступен optional v8 extendedDebug (старым=false), наследуется копией пресета.
Для Gemini включает native --debug с запуска; другим агентам этот флаг не передаётся.
Расширенный режим остальных агентов добавляет шкалу активности вывода, но не
внутренние сетевые трассы. Коды из terminal output могут быть цитатой; статус
TERMINAL_SIGNAL — наблюдение, не доказанный сбой API. Секреты и диалоги не копируются.
Остановка коллектора не меняет native verbosity и не останавливает процессы.
Инструкции экспорта/ограничения памяти см. USAGE.md и VALIDATION-v1.0.18.md.

Текущий статус доступа Gemini: официальный Google individual OAuth отключён с
2026-06-18, в том числе для Pro/Ultra, согласно объявлению разработчиков:
https://github.com/google-gemini/gemini-cli/discussions/28017 .
Наличие пункта Google и прохождение OAuth code prompt не доказывают доступ к модели.
API key остаётся отдельным путём; успешный ответ/квота аккаунта пользователем пока
не подтверждены. Ранние описания бесплатного Google-входа в локальных v15/v16
являются историческими, не текущим обещанием доступности.
Antigravity1.3.4 исследован изолированно: version/help прошли с Go options,
сервер стартовал, PTY интерфейс не появился; пока не интегрирован (ANTIGRAVITY-PROBE.md).
