# Проверка v1.7.88-x11-test / code1303

Частная сборка с библиотекой Bionic-драйверов только для Wrapper в Termux.

## Поведение и совместимость

- Под строкой Wrapper появляется карточка с именем выбранного драйвера.
  Нажатие открывает список импортированных версий, текущая подсвечена.
  Папка справа от рендера импортирует ZIP через прежний менеджер/Android permissions.
- Карточка и папка видны только при Wrapper. CPU/Turnip+Zink/VirGL скрывают их,
  сохраняя импортированные версии и прежний выбор. На других окружениях Wrapper
  по-прежнему недоступен. При запущенном столе обе кнопки недоступны.
- Каждый импорт хранит library.json с ID/именем/хешами/минимальным API. Предыдущие
  версии не удаляются. Повтор того же ZIP переиспользует каталог по SHA256.
  Оригинальные архивы в памяти телефона не нужны для последующего выбора.
- Catalog читает локальные метаданные; select повторно сверяет хеши выбранных
  .so и атомарно публикует current.json. Ни архив, ни сеть при выборе не нужны.
  Ошибка/отмена до публикации сохраняют текущий выбор; late cancel может оставить
  уже завершённую публикацию. Повреждённая версия не активируется.
- Import/catalog/select используют прежний exclusive nonblocking flock. Запущенный
  стол удерживает shared flock: гонка UI/службы не позволит менять используемый
  набор. Процессы и механизм остановки не менялись. Native драйверы остаются
  доверенным исполняемым кодом с правами приложения, не отдельной песочницей.
- Текущий драйвер v1.7.87 без library.json подхватывается при открытии списка или
  перед следующим импортом. При просмотре current.json не переписывается.
  Сохранённый Wrapper/Loader и сам путь рендера не пересобираются/не скачиваются.
  Версии, уже удалённые прежней v1.7.87 при новых импортах, восстановить нельзя.

Пакет/сертификат сохранены; versionCode1303 выше1302. Очистки данных нет.
Для отката сохранены APK v1.7.86 и v1.7.87 без преждевременного повышения кода.
При будущем откате на v1.7.87 её старый новый импорт снова будет удалять прочие
версии; старый запуск использует только current.json. v1.7.86 читает неизвестный
Wrapper как CPU и не удаляет приватную библиотеку. Полный откат на устройстве
не проверялся, эти особенности должны остаться в описании при его подготовке.

## Проверки

- 18 Python-тестов: новые offline select/catalog, сохранение двух версий, дедупликация,
  миграция выбранного драйвера v87, отсутствие ZIP/скачивания при выборе, неизвестный
  ID/обход пути, повреждение .so/metadata, minApi, ссылки, active flock, отмена;
  прежние импорт ZIP, runtime integrity/cache и отказ от Wrapper для guest.
- 37 JVM-тестов:6 Wrapper,9 GPU,22 desktop preparation. Карточка с именем,
  скрытие в остальных режимах/окружениях, недоступность при старте, список/
  несовместимый API, выбор текущего без native job, сохранение GPU-предпочтений.
- Настоящая прежняя копия Turnip Gen8 V38 из изолированного fixture v87 принята
  в каталог и выбрана без ZIP; bytes current.json при просмотре сохранились.
  Установленное окружение/драйвер/пользовательский ZIP не менялись.
- Release build успешен:13536 DEX definitions,31 оставшийся тип с прежними
  review notes. Package/ZIP/ABI/minSDK/version/signature/JNI проверены.
- Native binaries идентичны v1.7.87; единственный изменившийся asset —
  x11-wrapper.py. Источник Wrapper/Loader, x11-desktop.sh и другие окружения
  не менялись. Новых assets нет. Личные драйверы/архивы/токены/ключи не включены.

## Проверки разработчиком и пробелы

На v1.7.87 Screenshot_20261022_191833.jpg показывает загрузку custom V38,
Adreno830/MESA_TURNIP, Zink, Accelerated yes, OpenGL3.2/ES2.0. Разработчик
сообщил о glmark2 около3000, одинаковые условия/финальный Score не подтверждены.
Это проверка прежнего запуска Wrapper, не GUI-проверка новой библиотеки.

Parole успешно установлен после transient low-speed timeout зеркала; программных
изменений Arch/пакетного менеджера/сети по этому сообщению не делалось.

На v1.7.88 нужно проверить появление старого V38 без импорта, добавление второй
реальной версии, переключение между ними, сохранение после перезапуска приложения,
скрытие карточки при CPU и фактический новый renderer после старта. Свежая установка,
storage permission UI, keyboard/gestures и реальные GPU переключения этой версии
ещё не подтверждены устройством. JVM/fixture проверки этого не доказывают.
