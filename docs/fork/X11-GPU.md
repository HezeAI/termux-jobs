## v2.0.1: window overlap and renderer preparation

The pinned native core remains unmodified. Non-composited GPU targets now pass
`-disable-gpu-present`: Termux Wrapper, all eight VirGL targets and Linux-guest
Turnip. This bypasses native GPU copy offload that ignores window clipping;
applications still render on the selected GPU. CPU desktops and composited
Termux Turnip retain their existing presentation settings. Copying can cost
more CPU; overlapping windows and real performance require device verification.
No compositor, Mesa, ICD or ANGLE backend is changed by this mitigation.

Desktop check/installation also reports authoritative renderer readiness,
separately from desktop readiness. File markers are only preparation hints;
stale/missing components offer the selected renderer's consented setup instead
of treating a damaged renderer as ready or reinstalling XFCE. Launch retains its
own fail-closed check. Consented Turnip repair verifies downloads in a new stage
before replacing only the selected application cache; system Mesa and other
rootfs/cache targets remain untouched. Failed download/verification retains the
previous cache. Symlink cache roots are refused.

Historical development notes follow.

## Частная v1.7.99: VirGL для всех восьми рабочих столов

VirGL теперь выбирается также в Debian, Alpine, Fedora, openSUSE и Void.
Termux, Ubuntu и Arch сохраняют этот вариант. У агентов и Ubuntu AI его нет.
Выбор до запуска не устанавливает компоненты; при переключении на стол
недостающие компоненты предлагается установить с прежним подтверждением,
прогрессом и отменой. Рендер работающего стола менять нельзя.

Это локальный процесс `virgl_test_server_android` в Android/Termux, без
удалённого сервера и без сетевого доступа для отрисовки. Каждый стол получает
отдельный UNIX-сокет в собственном каталоге 0700 и свой дочерний процесс.
Сервер использует Android EGL через ANGLE; Mesa гостя работает через virpipe.
На стороне Android переменные гостевых драйверов удаляются. Гость получает
только свой сокет через существующее монтирование своего control-каталога.
Завершение/ошибка сервера завершает только его стол через существующий guardian;
PID других столов не ищутся и не используются. Композитор VirGL отключён.

Termux устанавливает `virglrenderer-android angle-android mesa libc++` из своих
репозиториев, только если их проверка не прошла. В выбранной системе:

| Окружение | Пакеты Mesa |
|---|---|
| Ubuntu, Debian | libgl1-mesa-dri libglx-mesa0 libegl-mesa0 |
| Alpine | mesa-dri-gallium mesa-gl mesa-egl |
| Fedora | mesa-dri-drivers mesa-libGL mesa-libEGL |
| openSUSE | Mesa-dri Mesa-libGL1 Mesa-libEGL1 |
| Void | mesa-dri libglvnd |
| Arch | mesa libglvnd, через pacman -Syu |

Пакетный менеджер получает полный набор при отсутствии любого компонента;
готовые компоненты повторно не устанавливаются. Ошибка транзакции/проверки
не выдаёт READY. Void использует `proot-distro run --work-dir /root`, поскольку
в исходном образе shell из passwd может отсутствовать. Общие hosts, системные
библиотеки Android и выбор рендера других систем не меняются.

Имена пакетов сверены с [Alpine aports](https://github.com/alpinelinux/aports/blob/3.22-stable/main/mesa/APKBUILD),
[Fedora Mesa](https://packages.fedoraproject.org/pkgs/mesa/mesa-dri-drivers/)
и [Void template](https://github.com/void-linux/void-packages/blob/master/srcpkgs/mesa/template).
Наличие пакетов не доказывает GPU-совместимость конкретной версии Mesa,
ANGLE и устройства. Новые пять вариантов требуют проверки на телефоне:
запуск стола, GPU INFO (virgl/virpipe вместо llvmpipe), GPU, остановка и
повторный запуск. Проверки не следует заменять баллом glmark2 от другого рендера.

## Частная v1.7.87: Wrapper только для Termux

Рабочая v1.7.86/code1301 закреплена отдельно в build/baselines/v1.7.86;
разработчик подтвердил исправление зависания Thunar Arch. Резервная версия

В Termux добавлен четвёртый рендер Wrapper · Bionic (тест). Выбор возвращает
в меню рабочего стола и ничего не скачивает/запускает. Справа появляется папка:
наш файловый менеджер открывает память телефона после проверки Android-доступа.
ZIP драйвера (meta.json/driver.json + ARM64 Bionic .so, до64МБ) импортируется
в отдельный приватный cache; не устанавливается из sdcard. Перед импортом
есть предупреждение о выполнении доверенного native-кода с правами приложения.
Формат/хеш не являются доказательством безопасности или поддержки GPU.

На запуске после обычной проверки/подтверждённой установки XFCE готовится
опциональный Wrapper Lee Gao0.0.5r5 и generic Vulkan Loader1.4.365 (~3.43МБ),
отдельно от прежнего Mesa/Turnip-кэша. Используется готовая Termux-упаковка
sabamdarif; libvulkan_wrapper.so совпадает поSHA256 с релизом самого Lee Gao.
Это собственная интеграция запуска/импорта, не самостоятельное авторство Mesa
и не утверждение воспроизводимой сборки upstream binary. Источники/хеши:
third-party/bionic-wrapper/provenance.json, X11-GPU.md и notice в assets.
Venus, VM, удалённый сервер и Wine не добавляются.

Рендер: Termux Mesa/Zink -> Wrapper -> AdrenoTools -> выбранный Bionic Turnip.
Только дочернее дерево Termux XFCE получает переменные/приватный loader.
Недостающие явные Termux-зависимости запрашиваются лишь при Wrapper и только
после согласия на установку. Выбор/импорт запрещены при работающем столе.
Ранее выбранный импорт сохраняется при ошибке нового ZIP; успешная замена
удаляет старую управляемую копию. Runtime загружается по закреплённомуSHA256,
проверяется повторно перед стартом; нет молчаливого отката на CPU/другой драйвер
на уровне приложения. Эффективный GPU/драйвер нужно проверить glxinfo/glmark2;
сам upstream AdrenoTools может отказать в подмене на конкретной прошивке.

Ubuntu/Debian/Alpine/Fedora/openSUSE/Void/Arch: по-прежнему три выбора,
Wrapper отвергается Java-службой, DesktopProcess и shell до запуска guest.

## Компоненты

С v1.7.65 выбор CPU/GPU только сохраняет предпочтение, в том числе до установки
рабочего стола. Проверка/установка стола и подготовка сохранённого рендера
начинаются по «Переключиться на рабочий стол». Подтверждение загрузки драйвера,
прогресс и отмена входят в эту подготовку; после успеха стол запускается.
Повторно выбирать режим не требуется. Отказ/ошибка сохраняют предпочтение
для повторной попытки, но не запускают стол и не переключают на CPU.

Загрузка закреплённых компонентов проверяется по размеру и SHA-256:

| Среда | Компоненты | Загрузка |
| --- | --- | --- |
| Ubuntu 26.04 | Mesa 26.3.0-devel-20260824, сборка lfdevs для KGSL | 12 069 639 байт |
| Debian 13 | Mesa 26.3.0-devel-20260824, сборка lfdevs для glibc/KGSL | 11 648 933 байт |
| Alpine 3.24 | Mesa 26.3.0-devel-20260824, сборка lfdevs для musl/KGSL | 12 099 886 байт |
| Termux | официальный mesa-vulkan-icd-freedreno 26.2.5 и vulkan-loader-generic 1.4.365 | 1 752 700 байт |

Версии, URL и хеши находятся в `x11/src/main/assets/x11-gpu.py`.
Ubuntu и Debian требуют установленные libvulkan1 и libegl1;
Alpine — vulkan-loader и mesa-egl (проверяется загрузка Vulkan/EGL). Установщик
GPU проверяет версию выбранной системы и библиотеки, не устанавливает системные
пакеты автоматически; недостающие пакеты устанавливаются через её менеджер пакетов. Termux использует Mesa/Zink
установленного рабочего стола. Начальная проверка требует доступный KGSL и Adreno.
Произвольные ссылки и пакеты установщик не принимает.

Кэш: `files/workspace-x11-gpu` в частном каталоге приложения, отдельный подкаталог
для каждого ABI окружения. В APK библиотеки GPU не вложены. Установка использует
блокировку, временный каталог, ограниченную распаковку и атомарное переименование;
готовность проверяется по версиям и хешам файлов. Повреждённый существующий каталог
не перезаписывается автоматически. Отмена кооперативная: текущий сетевой вызов
может завершиться по таймауту; отменённая операция не запускает рабочий стол; выбранный режим сохраняется.
Окно не закрывается тапом снаружи. Завершённый кэш после поздней отмены может остаться.

Ubuntu, Debian и Alpine получают подключение к общему каталогу
через /tmp/termux-jobs-x11-gpu; это служебное подключение исключено из миграции.
Переменные LD_LIBRARY_PATH, Vulkan ICD и Mesa задаются только дочернему процессу
графического стола через x11-gpu-env.sh. Системные библиотеки и shell rc не заменяются.
Процесс установки не посылает сигналы пользовательским сессиям. Логика остановки
X11 не изменена. Ubuntu AI агентов не становится графическим целевым окружением.

## Проверка на устройстве

1. Остановить стол, выбрать Turnip + Zink и подтвердить загрузку.
2. Запустить стол Ubuntu. Открыть терминал **внутри XFCE**.
3. Запустить `glxinfo -B` (пакет mesa-utils) и `glmark2` (пакет glmark2-x11).
4. Проверить renderer: ожидается Zink/Adreno; llvmpipe означает программную отрисовку.
5. Повторить для Termux; только затем проверить два стола одновременно.

Обычная терминальная вкладка приложения не наследует GPU-переменные стола.
AppStream-каталог программ может не показывать glmark2-x11: искать в обычном
пакетном менеджере Ubuntu. Для возврата выбрать CPU после остановки стола.
Раздельные X11-серверы окружений сохранены, но GPU и ресурсы телефона общие.

Изолированный EGL-тест подтвердил фактическую GPU-отрисовку на этом телефоне,
но не проверяет GLX/DRI3 и показ окна через наш X11. Ускорение OpenGL-программ
не гарантирует ускорения всех окон XFCE, видеодекодирования или браузера.

Источники: [Mesa Zink](https://docs.mesa3d.org/drivers/zink.html),
[сборка Mesa для Ubuntu/KGSL](https://github.com/lfdevs/mesa-for-android-container/tree/mesa-26.3.0-devel-20260824),
[Termux Mesa](https://github.com/termux/termux-packages/tree/master/packages/mesa),
[glmark2](https://github.com/glmark2/glmark2).
