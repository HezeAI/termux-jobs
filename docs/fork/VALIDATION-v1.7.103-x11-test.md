# Частная v1.7.103-x11-test: явный путь клиента VirGL

Дата: 2026-10-23. Проверочная сборка, не GitHub-релиз.

## Основание

Разработчик подтвердил работу Arch/openSUSE после102 и Alpine/Fedora/Void после101.
Debian102 оставался на корневом фоне без оконного менеджера. Termux VirGL
показывал GPU INFO, но завершал glmark2 ошибкой; полная причина этой ошибки
пока не доказана.

Read-only инспекция существующего Debian xfce4-session: один поток, ожидание
futex. Только адреса кадров выбранного xfce4-session читались для символизации;
содержимое стека/авторизация не экспортировались. Debug-символы официальной
Mesa25.0.7-2+deb13u1 сопоставлены с build ID установленной libgallium.
Цепочка GTK/GLX → Kopper → pipe_loader_create_screen_vk → Zink → ожидание mutex
в zink_destroy_screen показывает нежелательный выбор Vulkan/Zink до virpipe.
Исходный Mesa25.0.7 glxext.c/drisw_glx.c подтверждает отдельный выбор GLX-loader.

## Изменения

- Общий POSIX helper x11-virgl-env.sh для всех восьми целей. Только в выбранной
  ветке VirGL выставляет GALLIUM_DRIVER=virpipe, собственный VTEST_SOCKET_NAME,
  LIBGL_ALWAYS_SOFTWARE=true и LIBGL_KOPPER_DISABLE=true. Флаг software выбирает
  swrast-loader; GPU-рисование остаётся через virpipe/Android, не llvmpipe.
- Удалены конфликтующие унаследованные Mesa/Vulkan/EGL-пути; Alpine получает
  только свой проверенный private musl-client. При неправильной цели/клиенте
  ошибка возвращается до изменения переменных окружения.
- Termux VirGL: ANGLE Vulkan, fork на соединение. Ubuntu сохраняет ANGLE GL и
  multi-clients; Debian/Fedora/Void/Arch — Vulkan+fork; Alpine/openSUSE — GL+fork.
  Запуск, проверка и установщик используют согласованный backend.
- Turnip/wrapper очищают software/Kopper и старые VirGL socket. Окружение нативного
  сервера очищается отдельно от клиента. CPU-ветки не переписаны.
- Диагностика сохраняет только фиксированный JOBS_GPU_GLX=drisw-virpipe.
  Произвольные значения после маркера отбрасываются.

## Проверки кода, ревью и жизненного цикла

- 66 Python проверок прошли: VirGL7, Alpine client6, renderer env3, GPU12,
  GPU tools18, session policy2, wrapper18. Журнал находится в
  .verification/virgl-termux-debian/python-tests.log.
- Новые shell-проверки выполняют настоящий helper для всех восьми целей с
  конфликтующими параметрами предыдущего рендера. Проверены пропавший/неверный
  Alpine client, запрещённая Ubuntu AI, выбор частного ICD Turnip и очистка
  переменных VirGL. Отсутствующий ANGLE Vulkan Termux не выдаёт READY.
- Проверены отдельные socket, fork-группы, смерть сервера, отмена, сохранение
  соседнего стола и отсутствие запуска сервера из CPU/Turnip/wrapper. После
  последней очистки host Kopper повторно прошла проверка двух собственных групп.
- 64 JVM проверки: X11Integration35, WorkspaceDesktopGpu9, DesktopProcessAsset5,
  X11StartupLog15. Проверены упаковка helper, редактирование рендера только до
  запуска, границы восьми сервисов и фильтрация диагностических значений.
- Bash/POSIX syntax и git diff --check прошли. Механизм завершения процессов,
  JNI/нативное ядро, системные Mesa/rootfs и настройки агента не переписаны.
- Ревью: параметры ограничены дочерним графическим процессом; helper не пишет
  пользовательские файлы, не открывает сетевой listener, не читает секреты.
  Путь Alpine cache задан собственным bind и проверенным именем, shell injection
  не добавлена. Подготовка → свой сервер → клиент → ошибка/завершение по прежнему
  guardian; чужие PID не усыновляются и глобальные kill не используются.

## Границы доказательств

В отдельном Xvfb до финального helper прошли GLX запрос/красный pixel для Ubuntu,
Debian, Fedora, openSUSE, Void и Arch. Это не воспроизвело исходный Debian hang:
Xvfb отличается от Android X11. Termux не нашёл socket, Alpine имел ошибку
загрузки в проверочном стенде; эти пробы не объявляются успешными.
Повторная матрица после доработки стенда не завершилась. После сообщения
разработчика о пропадании связи приложения с Codex графические пробы остановлены.
Причинная связь не доказана; полная успешная матрица GUI восьми целей не заявляется.

После103 нужны: полный запуск Debian VirGL с панелью/значками и GPU INFO;
Termux VirGL GPU INFO и glmark2; затем краткая регрессия прежних работающих целей.
Чистая установка на другом устройстве, Mali/Dimensity и стабильность всех
приложений этими проверками не подтверждены.
