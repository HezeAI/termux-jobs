В создании бэкапа Arch разработчик получил unsafe archive paths. Read-only осмотр
нативного TAR показал три штатных systemd slice имени с буквальной backslash-xHH
последовательностью, ранее запрещавшейся clean(). Теперь допускается именно
hex-escape написание, никогда не декодируется. Иные backslash, NUL, абсолютные
пути, .. и write-through-symlink по-прежнему отклоняются. Это не выключение
проверки безопасности и не признание любых backslash-путей безопасными.

31 Python-тест прошёл: новый тест сохранения literal имени при scan/extract,
непревращение буквального x2f в разделитель, отказ при malformed escape и traversal;
прежние checksum/ELF/PAX/links/manifest проверки прошли. Реальный незавершённый
бэкап Arch проверен исправленным scan:37022 записи, aarch64,853515238 unpacked bytes.
Полная перепаковка этого же файла в репозитории с перехваченным native вызовом:
37023 записи, один fresh alias, три literal systemd имени сохранены. Текущие
системы не менялись, реальный native restore этой проверкой не запускался.

Сборка/DEX runtime прошли; ZIP/package/version/minSdk/ABI/non-debuggable,
v2-подпись/сертификат/SHA проверены. Assets кроме workspace-backup.py и native
побайтно совпадают1.6.16; проверяемые приватные файлы/секретные маркеры отсутствуют.
git diff --check проходит. Java/UI unchanged, ранее32 теста1.6.14 не повторялись.

restore; escape остаётся частью одного имени. Инспекция scan/repack/extract
подтверждает сохранение буквальных имён и запрет реального parent traversal.
