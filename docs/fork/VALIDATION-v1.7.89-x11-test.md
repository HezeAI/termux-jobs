# Проверка v1.7.89-x11-test / code1304

Частная сборка с подробностями ошибок установки Linux-окружений.

## Изменения и совместимость

В списке окружений после неудачной/остановленной установки появляется кнопка
«Подробнее» слева от «Продолжить». Пока установка активна и после успеха она
скрыта. Окно показывает журнал последней попытки с прокруткой; «Назад»
возвращает к тому же списку, «В Download» сохраняет TXT без закрытия окна.
Реализация общая для всех устанавливаемых окружений, включая Ubuntu AI.
Путь: создание/настройки сессии или пресета → Окружения Termux → Окружение.

EnvironmentInstallProgress распознаёт `Failed to install:` до последней
подсказки `See 'proot-distro install --help'`. Ранее карточка скрывала настоящую
причину. Сам сбой Ubuntu у другого пользователя по двум скриншотам не установлен;
это добавление диагностики, не подтверждённое устранение причины его установки.
Потерянный вывод старой попытки до этого обновления восстановить нельзя.

Последние262144 Java chars вывода установщика хранятся с явным маркером усечения.
В карточку прогресса передаётся прежний tail12000. Последняя неудачная попытка
каждого alias сохраняется в приватной `.environment-control/logs/<alias>.txt`,
атомарно с правами0600; следующая ошибка заменяет её, успех удаляет. Просмотр
после перезапуска читает файл в worker. Нет накопления отдельных попыток.
Пользовательские TXT в Download автоматически не удаляются. Экспорт использует
штатный запрос доступа к хранилищу и фоновую запись, удаляет неполный TXT при
ошибке и оставляет окно для повторного сохранения. При просмотре нет polling,
запуска процессов или установки. Процессы/отмена/докачка не менялись.

Вывод очищается от ANSI/control-последовательностей, URL, распознаваемых полей
секретов, известных токенов и блоков private key до сохранения и экспорта.
Это эвристическая очистка, не гарантия отсутствия личных данных: окно просит
проверить текст перед отправкой. Журнал не читает переписку, команды терминала,
файлы ключей/авторизации или другие пользовательские файлы. Нет автоотправки.

Рабочие столы, GPU/Wrapper и чат агентов не меняются. Пакет/сертификат прежние;
versionCode1303→1304. Сброса/миграции окружений или данных нет. Существующие
сохранённые драйверы v1.7.88 остаются. Откат на телефоне не выполнялся.
GitHub не публикуется.

## Проверки

34 JVM-теста, без ошибок и пропусков:

- EnvironmentInstallLogTest4: лог больше12k, ограничение/маркер/сохранение хвоста;
  скрытие URL/секретов/токенов/private key; независимость всех8 окружений,
  замена/удаление последней попытки, права0600; отказ от traversal, символической
  ссылки и слишком большого файла. При отвергнутой ссылке её цель не меняется.
- EnvironmentInstallLogUiTest2: до разрешения нет TXT, после разрешения содержимое
  совпадает со snapshot; недоступный Download не закрывает окно, допускает повтор.
- EnvironmentInstallProgressTest5: ETA без выдуманного итога, некорректные проценты,
  missing-shell/network errors и новая строка `Failed to install:` перед help.
- EnvironmentInlineInstallTest6: повторное открытие/остановка/успех/докачка,
  просмотр и сохранность после пересоздания EnvironmentSetup, скрытие Details
  при активности/успехе, удаление старого журнала при успехе; у всех8 окружений
  Details стоит перед Resume и не вызывает установку/выбор сессии.
- UbuntuInlineInstallTest5: раздельные карточки двух Ubuntu, подписки/прогресс,
  stop/restart. Исправлено устаревшее ожидание Install после Stop: существующая
  ранее логика docache/recordAttempt правильно показывает Resume.
- StartupEnvironmentTest5 и AgentEnvironmentUiTest7: выбор окружения, согласие,
  кнопки удаления/защита используемых окружений и сохранность прочих действий.

Robolectric/файловые fixture — изолированные проверки, не подтверждение Android
permission UI, размера кнопок на конкретном телефоне и реальной установки Ubuntu.
Нужен тест разработчиком: получить новую ошибку установки, открыть Подробнее,
сохранить TXT в Download и открыть файл; затем передать для разбора причины.
Потеря приложения во время установки/изменения файла не имитировалась. Приватный
журнал публикуется при штатном окончании попытки; аварийно убитый процесс до
завершения может не сохранить новую попытку. Активный установленный bootstrap,
окружения и APK не изменялись проверками.
