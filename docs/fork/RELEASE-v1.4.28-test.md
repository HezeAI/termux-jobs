# v1.4.28-test — local AI settings and chat histories (testing)

## Local AI
New local sessions use the dedicated jobs-local-ai Ubuntu for tools and, for llama.cpp, inference by default. LiteRT inference remains Android-only. Existing sessions keep their environment/location until explicitly changed; confirmed conversion does not copy Termux dependencies. Environment offers optional Allow commands in Termux, off by default. Command requests may explicitly select environment termux; code checks full access, project restriction and the additional flag before routing to Main Termux HOME. There is no automatic error fallback. Inference location Android/Termux/Ubuntu is independent; CPU mode/threads stay in Engine settings. Missing Ubuntu uses existing confirmed installation/progress, retrying session creation after preparation.

Behavior instructions are a separate row below Permissions in creation/session/preset settings. Standard or copied custom .txt/.md UTF-8 (12KiB maximum, strict decoding, nonempty/no binary) can be viewed, replaced/reset. Picker opens shared storage with access request and a root boundary, not installed containers. No ongoing dependency on original file. Instructions consume context; larger prompts can increase latency or fail to fit.

View current shows behavior and Rights prompt on the opposite side from Back. Rights prompt is generated or custom-edited with red warning and mandatory acknowledgement. Custom text does not bypass code authorization; real settings are included independently. Changes to rights/project/environment/confirmations/engine location make a custom prompt stale and require review/reset. Custom behavior/rights are per session/preset, not shared global grants.

Standard guide covers permission-aware action examples, real Bash execution, missing dependency installation through allowed full-access commands, actual HTTP checks and bounded continuation after a promise to execute another requested step. Full access can install required packages using the selected environment package manager when commands are allowed. The fixed confirmed install-tool exception for read/project modes remains unchanged. No package installation occurs just from this app update. Small-model instruction compliance is not guaranteed.

## History and closing
Unsaved local/terminal sessions offer Keep history (default on), Close, or Add preset and close. There is no Cancel button; outside dismissal does nothing. Adding a preset keeps history. Closing local without history removes that exact conversation only after queued work has finished. Concurrently open references block removal. Ordinary close retains/deletes app-side Bash/session history only; native Codex/Claude/Gemini/OpenCode history is independent.

Global settings Chat histories provides search/filter/local/Codex catalogs, scrollable preview, vector delete button and explicit confirmation. Native Codex thread/delete is used without filesystem deletion or archive fallback. Unsupported Codex versions show failure; no success is claimed. Sources include local chats and Codex in Main Termux/working Ubuntu; missing Codex catalogs are reported as unavailable/partial. Catalog pages and previews are bounded and limitations displayed; Codex full-hydration support varies by version. Only user/assistant Codex text is previewed, not complete tool-event archives. Histories opened outside the app must also be closed by the user before deletion. Active app-managed chats are blocked and pending deletion prevents reopening. Presets survive deletion with their chat binding cleared. Project files/models/authentication are not deletion targets.
