# Выбор SSH-ключа сервера — v1.3.0

Актуальный выбор окружений: [общий менеджер источников и проверка доступа к памяти](LOCAL-FILE-SOURCES.md).

Сервер + Agent → профиль → «Файл SSH-ключа». Векторная папка справа от поля
открывает выбор места: Termux, Ubuntu или память устройства. Навигация и поиск
используют существующий файловый менеджер; в режиме выбора нажатие на файл
выбирает его, не открывая просмотр/экспорт/редактор. Ручной ввод пути остаётся.

SSH серверного рабочего пространства запускается в Termux. Приватный файл из
доступного приватного дерева Termux используется по его пути. Для ключа из
Ubuntu или общей памяти приложение предлагает «Скопировать и выбрать».
Без согласия копия не создаётся. Копия — в files/server-keys приложения, каталог
0700, уникальный файл0600; чужие файлы не перезаписываются, оригинал не меняется.
Файл читается через выбранное окружение отдельной ограниченной операцией,
не через пользовательский терминал. Не устанавливаются пакеты/среды.
Установленные дистрибутивы proot-distro обнаруживаются автоматически
в поддерживаемых layouts; новые окружения не устанавливаются.

Проверка: доступный обычный файл до256КБ с заголовком OpenSSH/PEM private key.
Публичный .pub не подходит. Это проверка формата заголовка, не доказательство
валидности ключа: окончательно файл загружает OpenSSH. Содержимое не показывается
и не пишется в диагностику. Импорт из общей памяти не делает исходный файл
приватным; исходник не удаляется. Новый импорт при отмене профиля удаляется,
при сохранении остаётся только выбранная копия. Ранее сохранённые ключи
автоматически не удаляются при замене/удалении профиля.
Импортированные файлы находятся вне HOME/PREFIX: резервная копия только HOME
их не включает. При переносе сохраните files/server-keys отдельно либо выберите
исходный ключ повторно. Автоматический перенос Keystore-секрета не обещается.

«Автоматически / SSH-ключ» в серверном пространстве означает OpenSSH с
BatchMode=yes и стандартными доступными ключами Termux. Файлы, выбранные для
других профилей, не превращаются в глобальные; Ubuntu автоматически не ищется.
Переход на пароль без участия пользователя в этом режиме не предлагается.
«Пароль» — пароль пользователя на сервере, другой режим аутентификации.

«Passphrase (если требуется)» — скрытый ручной ввод для зашифрованного файла
ключа. Пустое поле сохраняет прежнее значение только для того же профиля,
endpoint, режима и пути. Есть явное удаление сохранённого passphrase. Смена
ключа или режима не наследует пароль из другого режима. Секреты не сохраняются
в состоянии Android View и исключены из Autofill на поддерживаемых API.

Серверный профиль хранит секрет только шифротекстом Android Keystore, с прежней
привязкой к id/host/user/port. После переноса на другую установку может
потребоваться повторный ввод. Существующее поле encrypted используется для
пароля либо passphrase согласно auth; версияJSON не меняется.

При подключении, SFTP/передачах и файловых операциях passphrase передаётся через
существующий одноразовый same-UID askpass broker, не через argv/окружение/файл.
Он принимает только запрос выбранного ключа (с учётом100-байтного ограничения
пути в запросе OpenSSH), отклоняет запрос пароля пользователя и другого ключа.
PasswordAuthentication/KbdInteractive отключены для key mode в этих путях;
проверка доверенного ключа сервера сохранена. Секрет не отправляется серверу
как пароль. Автоматическое заполнение в отдельном интерактивном SSH-терминале
не добавлено: OpenSSH при необходимости запросит passphrase там самостоятельно.

Первичный источник формата запроса: [OpenSSH sshconnect2.c](https://github.com/openssh/openssh-portable/blob/master/sshconnect2.c), load_identity_file.
Это точечное расширение существующего SSH-механизма, не новый SSH-клиент.
