## Изменение и безопасность

Только для targetarchlinux native-host проверка owner700 выполняется до
входа для проверки компонентов и перед run. Недостающие права дают
MISSING:root-permissions и обычное подтверждение установки с явным описанием
восстановления owner read/write/search. Check/run ничего не исправляют.
В согласованном install до/после транзакции открывается только root-directory
выбранного Arch, проверяются тип/владелец; fchmod добавляет недостающие owner700,
сохраняя group/other/special bits. Используется fd, без recursive/chown.
Native-host Python устанавливается при необходимости только после install consent.

Каждый компонент containers/archlinux/rootfs либо installed-rootfs/archlinux
открывается O_DIRECTORY|O_NOFOLLOW; ссылка/чужой владелец/неизвестная операция
отклоняются. Контент корня не сканируется рекурсивно. Другие rootfs/агенты
не исправляются, глобальный PRoot/SDK/Android не обновляются. GIO/inotify
и нормальные события файлов не отключаются; фильтра событий не добавлено.

Новые фиксированные категории ROOTFS_OWNER_ACCESS_REQUIRED,
ROOTFS_OWNER_ACCESS_RESTORED и ERROR:ARCH_ROOTFS_OWNER_ACCESS не содержат
путей. Если реально изменён rootfs на диске при работе старого PRoot, открытая
сессия может иметь отложенное восстановление прав; поэтому исправление
привязано к подготовке до нового стола, а не применяется к зависшему процессу.
При разработке установленный rootfs не исправлялся, сессии не закрывались.
