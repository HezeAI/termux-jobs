# Частная v1.7.104-x11-test: GPU INFO Ubuntu VirGL

Дата2026-10-23. Проверочная сборка, не публичный релиз.

## Основание и изменение

Разработчик предоставил Screenshot_20261023_114203.jpg: Ubuntu XFCE запущен,
glmark2 показывает сцену, первые этапы214/201FPS. GL_RENDERER virgl/ANGLE
Qualcomm Adreno830, GL_VERSION2.1 Mesa26.0.8-1ubuntu0.3. Одновременно GPU INFO
через glxinfo завершился status1 с BadMatch, X_GetImage. Это не падение
рабочего стола или самого glmark2.

Ubuntu добавлена в allowlist общего EGL-info helper. Он запускается отдельным
дочерним Python-процессом с timeout20 секунд, наследует выбранный Mesa/socket,
использует собственные context/pbuffer и не меняет окружение стола. Вывод
подписан EGL; он не доказывает исправление произвольных GLX-приложений.

Backend Ubuntu остаётся ANGLE GL/multi-clients. Сам GPU-тест, Termux info GLX,
CPU, Turnip и wrapper не изменены. Пакеты/библиотеки/rootfs, GUI, ввод, сервер
Selectel и бот не менялись. Управляемая копия helper обновляется при очередном
запуске стола; пользовательские изменения сохраняются по существующей проверке
manifest. После обновления остановить/запустить Ubuntu нужно вручную; помощник
не изменяет работающую сессию.

## Проверки и границы

21 Python проверка прошла: GPU tools18 и renderer env3. Ubuntu охвачена выбором
EGL только в info/VirGL, сохранением glmark2 и GLX в CPU/Turnip. Проверены
timeout/crash без отката к падающему glxinfo, очистка собственных EGL-ресурсов,
обновление управляемого helper с сохранением пользовательских правок и выбор
рендера для восьми X11-целей. Git diff --check прошёл.

Ревью: изменение runtime — только дополнительная цель в существующей константе.
Обработка процессов, доверие к файлам, TLS/сеть, права и данные не переписаны.
Путь вызова prepare → managed copy → info → worker20s/cleanup проверен по коду.
Новые X11-пробы не запускались из-за ранее наблюдавшейся потери связи с чатом.
После установки104 требуется открыть GPU INFO Ubuntu/VirGL и проверить вывод
сведений вместо BadMatch. Чистое другое устройство и Mali отдельно не проверены.
JVM-код не менялся; результаты64 проверок103 остаются предыдущим доказательством,
повторный JVM прогон104 не заявляется.
