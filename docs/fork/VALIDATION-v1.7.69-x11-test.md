# Частная v1.7.69-x11-test / code1284

## Причина и изменение

Последний журнал DNF: openh264-2.6.0-3.fc44.aarch64.rpm с Cisco возвращает403.
Основной metalink Fedora отвечал200. Из 292 уже скачанных RPM прочитаны
заголовки: libheif требует libopenh264.so.8()(64bit).

Только две команды установки базового Fedora X11 (makecache/install)
получили --disable-repo=fedora-cisco-openh264. Файлы .repo не редактируются;
подписи, обязательные зависимости, полный набор XFCE и рендер сохраняются.
Сторонние репозитории, --nogpgcheck, --skip-broken, --allowerasing не добавлены.
Установка отдельных программ, каталог и общий пакетный менеджер не менялись.

Официальный noopenh264 предоставляет ABI, но является заглушкой и не даёт
H.264-декодирование. Другие форматы/декодеры этой правкой не проверялись.
Источники: [описание Fedora](https://packages.fedoraproject.org/pkgs/noopenh264/noopenh264/),
[пакет Fedora44](https://packages.fedoraproject.org/pkgs/noopenh264/noopenh264/fedora-44.html).

## Проверки

В отдельной фоновой команде Termux запущен настоящий DNF Fedora с --cacheonly
--assumeno и точным набором пакетов скрипта установки. Метаданные, rpmdb,
log/persist/tmp скопированы/направлены в .verification/fedora-cisco внутри
репозитория. Системные пакеты и настройки не изменены, рабочие сессии не
останавливались. Проверка плана отказалась от выполнения транзакции намеренно.

- Стандартный план выбирает openh264 из fedora-cisco-openh264.
- План без Cisco разрешает те же зависимости через noopenh264-2.6.0-4.fc44
  из fedora. Оба плана: 292 устанавливаемых пакета, 1 обновление, 1 замена
  (systemd-libs). Это штатный план DNF, не разрешение удаления произвольных
  пользовательских пакетов. Полная транзакция не выполнялась.
- Отдельный RPM noopenh264 загружен по HTTPS с зеркала из списка DNF
  в репозиторий. rpm --checksig с копией rpmdb подтверждает RSA/SHA256,
  Header/Payload SHA256: OK. Пакет не установлен в Fedora телефона.
- 6 тестов Fedora: обе команды используют локальный repo-флаг,
  запретов проверки подписей нет, сбой install останавливает дальнейшие шаги.
- 14 тестов рабочего стола прошли. Тесты изолированы от систем пользователя.

## Логическая инспекция и ограничения

set -eu сохраняет выход при ошибке makecache/install. Финальный check и
обновление сертификатов выполняются только после успешной установки.
Режимы Alpine/Termux не изменены. Java, UI, запуск/остановка X11,
другие агенты и механизм докачки окружений не менялись относительно68.

Нужна проверка настоящей установки Fedora X11 из обновлённого APK и запуска
рабочего стола разработчиком. Установка отдельных программ обычным DNF
может вновь обращаться к Cisco: её политика намеренно не менялась.

Совместимость: com.termux, прежний сертификат, versionCode1283→1284.
Миграций формата данных/сброса пользовательских файлов нет. Публикации нет.
