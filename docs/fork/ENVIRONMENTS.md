# v2.0 — current environment layout

Termux, Ubuntu, Debian, Alpine, Fedora, openSUSE, Void and Arch Linux ARM each
have their own supported XFCE/X11 desktop path. A desktop uses the selected
rootfs, not another distribution's Ubuntu. The base Termux runtime remains
shared at Android app level; these are not separate security sandboxes.

Ubuntu AI is the default for new agent sessions/presets. Existing profiles keep
their saved environment. Optional migration copies the original Ubuntu container
into Ubuntu AI with activity/space/source-change/checksum checks and explicit
credential-copy consent. External mounted phone files are not duplicated; the
original Ubuntu is not automatically deleted. Files/package operations and agent
preparation route to the selected alias. Ubuntu X11 Test is retired from creation.

Environment installs use inline card progress, an owned operation and error
export. Native proot-distro installs supported images and may reuse complete
verified cached layers; an interrupted layer can restart. Arch Linux ARM uses
its reviewed source archive and SHA validation. Do not infer network download
from a fast cached install. Busy environments reject destructive operations.

See [release/compatibility](RELEASE-v2.0.0.md), [agent migration](AGENT-ENVIRONMENTS.md)
and [sources](THIRD-PARTY.md). All older version entries below are historical.

## Частная v1.7.90: GPU & GPU INFO на рабочих столах X11

В Программы → Рекомендуемые добавлен английский пункт GPU & GPU INFO.
После согласия пакетный менеджер выбранной системы устанавливает инструменты,
затем создаются два ярлыка GPU и GPU INFO в её XDG Desktop (по умолчанию ~/Desktop).
Базовая установка стола не получает эти необязательные программы автоматически.
Если команды уже установлены вручную, следующий запуск стола создаёт ярлыки.

| Окружение | Пакеты | GPU |
|---|---|---|
| Ubuntu, Debian | glmark2-x11, mesa-utils | glmark2 (X11/GLX) |
| Termux | glmark2, mesa-demos | glmark2 |
| Fedora | glmark2, glx-utils | glmark2 |
| openSUSE | glmark2, Mesa-demo-x | glmark2-es2 (X11/EGL) |
| Void | glmark2, glxinfo | glmark2 |
| Arch | glmark2, mesa-utils | glmark2 |
| Alpine stable | mesa-utils | glxgears -info, без балла glmark2 |

GPU INFO запускает glxinfo -B. В стабильной Alpine glmark2 отсутствует;
edge/testing не подключается. Для openSUSE выбран ранее проверенный разработчиком
EGL-вариант, а не проблемный GLX glmark2. Баллы разных тестов/API/настроек
не считаются сопоставимыми. На CPU инструменты показывают программный рендер,
ярлык сам не переключает на GPU. Драйверы, DISPLAY и библиотеки наследуются от
своего рабочего стола; xfce4-terminal --disable-server исключает чужой старый
terminal server. --hold оставляет результат/ошибку в окне после завершения.

При удалении бинарника оставшийся ярлык покажет подсказку об установке группы.
Пользовательские изменения ярлыков/одноимённые файлы сохраняются; вместо их
перезаписи установка может сообщить о конфликте. Для отслеживания собственных
файлов используется ~/.local/share/termux-jobs/gpu-tools/shortcuts.json.
Повторный запуск не переписывает неизменённые файлы; ссылки и пути Desktop
за пределами выбранного home отклоняются. Shell eval пользовательских путей нет.

Пункты состояния/время/прогресс/кнопки установки локализованы ru/en;
имена GPU, GPU INFO, GPU & GPU INFO остаются английскими. Сырой вывод пакетного
менеджера не переводится. Программы ставятся обычным существующим механизмом
с фоном, отменой/продолжением. У агентов/Ubuntu AI нет новых ярлыков.
Старый кэш рекомендуемых без gpu-tools автоматически отклоняется и проверяется
снова, без сброса остальных каталогов. Пакет/сертификат прежние, code1304→1305.
Сброса пользовательских данных нет; GitHub не публикуется.

Проверки и пробелы: [VALIDATION-v1.7.90-x11-test.md](VALIDATION-v1.7.90-x11-test.md).

## Базовая установка и проверка на чистом окружении

Исходная точка для каждого поддержанного X11 — чистое приложение и собственное новое окружение, без пакетов телефона разработчика. Установщик запрашивает полный обязательный набор; уже установленные пакеты учитывает пакетный менеджер. Наличие метапакета XFCE не заменяет проверку отдельных частей: xfdesktop, xfce4-panel, xfsettingsd, xfconf-query и xfwm4. Termux xfce4 не включает xfdesktop, поэтому тот указан отдельно. Программные PDF/браузерные/мультимедийные дополнения остаются с соответствующими программами.

Изолированные проверки отсутствующих команд и успешный запуск на настроенном устройстве не доказывают запуск чистой системы на другом телефоне. Результаты чистой установки и графического теста фиксируются отдельно; пользовательские данные ради проверки не очищаются.

## Выбор и вход

В создании и настройках сессии/пресета доступны три семейства:
«Окружения Termux», SSH и AI Agents. В первом семействе отдельная плашка
«Окружение» выбирает Termux или конкретный экземпляр proot-distro.
Каталог включает Ubuntu, Debian, Alpine, Arch Linux, Fedora, openSUSE, Void Linux
и обнаруженные установленные экземпляры. Доступность установки зависит от
архитектуры и версии proot-distro. Void устанавливается из официального OCI `ghcr.io/void-linux/void-glibc-full:latest`,
где опубликована платформа linux/arm64. Для Arch на ARM64 используется **Arch Linux ARM**,
отдельный проект от x86-64 Arch. Установщик скачивает rootfs из официального
релиза Termux proot-distro v4.34.2 (2025-12-21), проверяет закреплённый SHA-256
и передаёт локальный архив менеджеру под именем `archlinux`. Это фиксированный,
не самый свежий образ rolling-системы; обновление пакетов проверяется отдельно.
Временный архив удаляется при штатном успехе/ошибке; принудительное завершение
процесса может оставить файл до последующей очистки. Старый proot-distro
продолжает использовать свои установленные плагины.

Под выбранным окружением показывается точная команда **из оболочки Termux**:

```sh
proot-distro login 'ubuntu'
proot-distro login 'debian'
proot-distro login --isolated 'jobs-abcdef123456'
```

Для установленного Void OCI, где в passwd указан отсутствующий Bash, используется:

```sh
proot-distro run --work-dir /root 'void' -- /bin/sh -i
```

Приложение выбирает этот путь только при наличии sh, отсутствующем /bin/bash,
соответствующей записи root и OCI-манифесте без Entrypoint. Произвольный
Entrypoint автоматически не запускается. Файловые операции используют ту же
логику. Начиная с1.6.14 восстановление создаёт минимальный безопасный OCI-манифест
для нового экземпляра, чтобы этот обход сохранялся и у восстановленного Void.
Поля исходного OCI (Entrypoint, Env, image_ref) не переносятся; файлы/passwd
не меняются. Фактический восстановленный запуск ещё требует проверки.

Используйте имя, показанное в настройках, а не имя сессии. `ubuntu` и другой
экземпляр с именем `jobs-…` — разные файловые системы. Прямой вход открывает
оболочку; рабочий каталог, команды запуска и история конкретного пресета
настраиваются приложением при запуске самой сессии.

**Существующая Ubuntu пока общая с AI Agents.** Никаких переносов, переименований,
обновлений или замены установленной Ubuntu эта сборка автоматически не делает.
Отдельная `ubuntu-ai` и перенос агентов обсуждаются для будущего обновления.
Termux остаётся общей базовой средой, а не новой копией Termux для каждой сессии.

## Установка и проверка

Выбор отсутствующей системы предлагает явное подтверждение загрузки и установки.
Прогресс показывает вывод установщика; окно не закрывается случайным касанием.
Установленные системы не сбрасываются и не заменяются. Если отсутствует сам
proot-distro, подтверждённая установка также устанавливает его через `pkg`.
Установка не прерывается кнопкой «Назад»: завершите её до закрытия приложения.
Время и размер загрузки определяет внешний менеджер; процент не выдумывается.

«Проверка среды запуска» проверяет наличие выбранного экземпляра, менеджера и
оболочки. Галочка отражает результат этой проверки, а не полноту пакетов,
работу всех утилит или доступность облачных моделей. После смены выбора
галочка сбрасывается. При отсутствии Bash новое окружение использует `/bin/sh`.
Существующий путь запуска Ubuntu/агентов через Bash сохранён.

## Файлы, пакеты и бэкап

Рабочий каталог и файловый менеджер используют выбранный alias. Просмотр,
редактирование и операции выполняются в нём; отсутствие необходимых утилит
даёт ошибку и не переключает выполнение в базовый Termux. Оболочки sh без
Bash и отличающиеся версии утилит требуют проверки на конкретной системе.
Менеджер пакетов APT пока поддерживает Termux и прежнюю Ubuntu; адаптация к
apk/pacman/dnf в эту сборку не входит.

Долгий тап по AI-сессии в списке на вкладке «Терминал» содержит «Установка пакетов»
для Codex, Gemini, Claude и OpenCode. Кнопка робота над чатом продолжает открывать
терминальное окно. При выполнении агента используйте предложенный вариант новой
сессии того же окружения, чтобы не отправить команду установки в поле агента.

Бэкап обнаруживает legacy `installed-rootfs/<alias>` и современные
`containers/<alias>/rootfs`; интерфейс называет их Linux/proot, а протокольное
поле `ubuntu` сохранено для совместимости. Новые архивы сохраняют исходный alias.
Полное восстановление создаёт новый `jobs-…`, не заменяя работающую систему.
Обычные пресеты восстанавливаемого экземпляра привязываются к новому alias,
с обязательной проверкой настроек перед запуском. Для восстановленных экземпляров
сохраняется прежний режим `--isolated`, в том числе для файлового менеджера. Агентские пресеты не мигрируют
автоматически. У старых архивов без исходного alias автоматическая перепривязка
не гарантируется: проверьте окружение вручную. Данные без системы только
извлекаются в отдельную папку, как прежде.

## Пакеты выбранного окружения — 1.6.9-test

Панель «Установка пакетов» определяет менеджер внутри выбранного экземпляра:
APT (Debian/Ubuntu), APK (Alpine), DNF (Fedora), Zypper (openSUSE),
XBPS (Void), Pacman (Arch). Списки установленных/доступных/обновляемых пакетов,
описания и действия используют его репозитории и архитектуру, без объединения
с другими окружениями. Читается локальная метаинформация; пустой каталог может
потребовать явного обновления. Обновление метаданных само по себе не устанавливает
пакеты, кроме явно обозначенного «Обновить систему» у Pacman.

Перед изменением показываются команда и выбор свободной текущей оболочки либо
новой сессии того же окружения. Не отправляйте команды занятому агенту/программе.
Для новых proot-сессий проверяется маркер alias: после exit в хост операция
отклоняется. Это защита от случайного запуска в другом окружении, не sandbox.
В сессиях, запущенных до1.6.9, маркер отсутствует: выберите новую сессию того же
окружения. Установленные пакеты сохраняются в этом экземпляре после закрытия сессии.

У Arch установка/обновление использует pacman -Syu и включает полное обновление
окружения; это явно поясняется до запуска. Частичные обновления не предлагаются.
Выбор конкретной версии в панели пока реализован только для APT; у остальных
доступна штатная версия из репозитория и план менеджера в терминале.

Проверка установки/удаления на устройстве ещё предстоит. Следующий этап — бэкапы:
сравнение пакетов пока APT/dpkg, а восстановление Void без OCI-манифеста требует
отдельной доработки/проверки, прежде чем считать его поддержанным полностью.

## Восстановление и выбор окружений — 1.6.14-test

В списке справа отдельная плашка «Установить» / Install; у установленной системы
серое неактивное «Установлено» / Installed. Саму установленную строку можно
выбрать, а установка отсутствующего окружения по-прежнему требует подтверждения.
Названия экземпляров не менялись.

Бэкап выбранного alias не объединяет его с другими Linux-системами. Полное
восстановление репакует rootfs под новым jobs-* и создаёт свой минимальный
манифест с пустым Entrypoint, Cmd=/bin/sh, Linux PATH и WorkingDir=/.
Исходные OCI-команды, Env, WorkingDir и image origin не импортируются, rootfs
и passwd не редактируются. В результате Void с отсутствующим passwd Bash может
использовать прежний безопасный native run; существующий Void не затрагивается.
Предложенная команда ручного входа — proot-distro run --isolated --work-dir /
'jobs-…' -- /bin/sh -i. Пресет остаётся isolated; приложение выбирает login/run
по доступным оболочкам. Программные тесты не заменяют реальную проверку запуска.

Для первой проверки в меню создания снимите библиотеку/HOME/PREFIX и выберите
только Linux / proot · debian. После создания сохраните всю папку архива, затем
выберите её manifest.json в проверке восстановления. Восстанавливайте только
Debian в новый экземпляр; исходный Debian должен остаться доступен. Проверьте
тестовый файл и tree --version, затем повторите другие системы. Для Void
проверять особенно восстановленный запуск и файловый менеджер.
Сравнение пакетов бэкапа остаётся Termux APT-only; пакеты гостя сохраняются
вместе с полной системой, отдельно в Termux не устанавливаются.

### Служебный .l2s у восстановленного Arch — 1.6.18-test
Разработчик подтвердил восстановление Arch, наличие файла, команды и повторный

не дублируется. Live среды не меняются. Для проверки повторить восстановление
того же Arch бэкапа в свежую копию; обновление APK само не меняет текущий экземпляр.


## Удаление восстановленных экземпляров — v1.7.0
Шестерёнка → Резервное копирование → Удаление восстановленных окружений.
Показываются источник, alias, размер и incomplete-статус. Подтверждённое
происхождение берётся из HOME отчёта прошлой успешной операции либо приватной
записи новой попытки. Старый неизвестный jobs-* виден серым: имя само по себе
не разрешает удаление. После успеха старые отчёты не разрешают удалять экземпляр,
повторно созданный под тем же alias (private tombstone). Пакеты/файлы копии и её
пресеты удаляются, архивы Download и отчёты сохраняются.
Удаление идёт только через проверенный native proot-distro с nonblocking locks:
если экземпляр занят — отказ без force/kill. Перед вызовом проверяются имя,
подтверждение происхождения и dev:ino выбранной директории; symlink не принимается.
Старый менеджер без поддерживаемых блокировок не допускается. После подтверждения
нет отмены удаления; возможную частичную копию после ошибки нужно перечитать.
