# v1.4.10-test / code 1116

Agent settings distinguish capabilities and scope without inventing identical guarantees across providers.

Codex: native read-only or read/write. For write mode, an independent checkbox selects workspace-write vs danger-full-access. It is labelled **restrict writes**, because reads outside the project and runtime-managed writable paths are not necessarily blocked. An independent confirmation checkbox selects on-request or never. On-request is the Codex approval policy, not a prompt before every action. Never refuses approval-based escalation; it does not disable the selected sandbox. Android/proot sandbox compatibility still needs real-device testing; there is no automatic full-access fallback. Both new and resumed chats use the selected settings and resumed chats must confirm matching parameters.

OpenCode v2.0.28: optional project/worktree scope uses native session permissions. It denies external_directory and all unknown actions, allowing read/glob/grep/question and (depending on access) edit. Shell, execute, subagents, skills and MCP remain denied in scoped mode. The checkbox is labelled restrict external paths, not complete project confinement. Path checks in this pinned runtime are lexical and do not guarantee prevention of symlink escapes. This is a tool policy, not OS isolation; the upstream boundary includes its non-root project worktree. Existing saved approvals cannot override configured deny rules in the inspected pinned permission implementation. A real runtime check remains required.

Claude/Gemini: their native permission/approval modes remain available. Project enforcement is not implemented in the Android/proot integration and is displayed as unavailable. No new sandbox backend or implicit flags are installed.

Existing profiles: absent Codex approval field preserves full→never, project/read→on-request. OpenCode project scope defaults off. Profiles/history/authentication are not cleared or rewritten at startup. Opening settings does not change them; explicit Save stores equivalent values unless controls were changed. New values apply on the next launch/manual restart, not to active processes. A new immutable Codex helper is added without overwriting the old helper; status/proxy uses the same protocol. The settings code does not restart user processes; installing an APK is a separate Android operation with its own lifecycle effects.

Compatibility: same com.termux package/signature, versionCode 1116. Optional v8 fields; no reset required. IMPORTANT downgrade limitation: old builds ignore codexConfirmActions and aiProjectOnly, so new confirmations or project restrictions may be lost on next launch in an older version. Review policies before downgrade. This is a private test build, not a GitHub release.
