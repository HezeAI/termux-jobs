# Проверки v1.7.84-x11-test / code1299

Частная сборка для раскрытия причины скачивания Arch X11. Публикации нет.

## Наблюдение и границы вывода

Разработчик сообщил обрыв установки. Скриншот22октября15:56 показывает
обрезанную строку `failed retrieving file 'libcups-2:2.4.20-1-aarch64.pkg.tar…'`.
Отчёт `Termux-Jobs-diagnostics-5883085026308211601.txt`: targetarchlinux,
selectedturnip, phaseerror, component stagedownloading, childexit1,
guardian137. Рабочий стол не запускался. Общая ошибка Pacman —
`failed to commit transaction (download library error)`.
Она не доказывает IPv6, несовместимость драйвера или падение XFCE.

Изолированный curl из установленного rootfs Arch запущен через его loader
и библиотеки, запись только в `.verification/arch-download`. Это не полноценный
вход Arch: часть системных путей и условий остаётся текущей Ubuntu.
Проблемный libcups257476байт скачан с автоматическим выбором адреса за4.095с
и с IPv4 за3.470с; обаHTTP200 и SHA256 совпал с каталогом Arch Linux ARM.
Отдельные HEAD-пробы IPv4 успешны для default/de3; IPv6-пробы не разрешили
имена в текущей сети. Причина прежнего сбоя не определена. Сеть, mirrorlist,
IPv4/IPv6, rootfs, пакеты и работающие сессии не изменялись.

## Исправление приложения

Сборщик `X11InstallErrors` ранее распознавал download/fetch, пропуская
Pacman `failed retrieving file`. Теперь retrieving включён; сохраняются
причины timeout/404/DNS/route/permission после прежнего ограниченного
best-effort обезличивания. X11StartupLog классифицирует retrieving и
commit/download-library как PACKAGE_DOWNLOAD_FAILED без сырого текста.
Существующие пределы, исключение обычного вывода и правила редактирования
секретов/путей/адресов сохраняются.

После ошибки в центральном экране установки есть «Подробнее»; нажать можно
также на строку. Окно показывает доступный хвост лога до8KiB без обрезания
строки по ширине, с переносом, прокруткой и выделением. Копирование в clipboard
только по кнопке «Копировать», окно остаётся открытым. Само оно не открывается.
Новый запуск скрывает ссылку на прошлую ошибку. Частые обновления состояния
не переключают её видимость через GONE/VISIBLE без смены состояния.
Raw-хвост остаётся локальным UI; обычный диагностический экспорт содержит
только отфильтрованные transfer errors. В журнале могут быть адреса репозиториев;
его копирование пользователем не меняет политику автоматического экспорта.

## Проверки

42 JVM-проверки пройдены:7 InstallErrors,10 StartupLog,3 StartupUi,
22 DesktopPreparation. Новые случаи: реальные формулировки Pacman с5 причинами,
удаление имени пакета/хоста, классификация download-library, отсутствие raw-текста
в категориях, открытие/полный текст/выделение/копирование/сохранение диалога,
скрытие подробностей при новом check. Прежние тесты секретов, фрагментов,
границ размера, отмены и переключения окружений проходят.

Release build успешен58с. DEX13502 определения,31 ранее рассмотренный
неразрешённый тип; JNI34 дескриптора проверены. Финальный ZIP, packagecom.termux,
minSDK26, arm64-v8a, versionCode1299, подписьv2/сертификат и SHA256 проверены.
Assets/native идентичны v1.7.83. Изменённые Java сверены со staging. Проверка
известных маркеров приватных ключей и авторизационных файлов прошла; она
не является исчерпывающим поиском всех возможных секретов. diff--check пройден.

Пакет/сертификат сохранены, code1299 выше1298; форматы пользовательских
данных не меняются, сбросов или миграции нет. APK обновляет диагностику/просмотр
ошибок, а не устраняет ещё неизвестную сетевую причину.

Свидетельства `.verification/arch-download/{probes.json,arch-curl-probes.json,
jvm.log,jvm-results.json,build.log,audit.log,apk-audit.json}`.
