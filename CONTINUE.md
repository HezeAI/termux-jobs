# Продолжение работы над форком Termux

Состояние на 11 октября 2026 года. Пользователь попросил сохранить контекст,
чтобы продолжить позже. Затем запросил вставку сохранённых команд через
звёздочку рядом с полем ввода терминала; эта функция добавлена.

## Требования пользователя

- Работать только в `/root/termux-fork`.
- Не изменять установленный Termux, его данные и окружение Ubuntu.
- Не устанавливать APK и не заменять текущее приложение.
- Новые инструменты и кеши хранить внутри репозитория; существующие читать.
- Готовый APK класть в `/sdcard/Download` для личной проверки пользователя.
- UI: AMOLED-чёрный фон, мягкие бирюзовые акценты, плавные переходы,
  скруглённые панели, минимум элементов.
- Референс: `/sdcard/Download/Buildtermyx.png`; копия в `docs/fork/reference.png`.

## Что сделано

База официального Termux v0.118.3, upstream `termux/termux-app`, ветка
`fork/base`. Коммит реализации: `f841f456`.

- Библиотека команд: название, текст, категория, поиск, избранное,
  редактирование, дублирование, удаление и вставка в поле текущего терминала.
  По последнему уточнению пользователя отдельная сессия не создаётся;
  поле каталога убрано из формы команды. Старые записи сохранены.
- Сохранённые сессии: имя, каталог, стартовая команда, отдельная история Bash
  и сохранённый вывод; восстановление настроек и повторный запуск по нажатию.
- Несколько терминалов, переключение вкладками, остановка и перезапуск.
- Нативный Android UI поверх оригинального TerminalView, сервис/PTY сохранены.
- Атомарное JSON-хранилище; повреждённые/неизвестные данные не перезаписываются.
- Отдельный локальный тестовый ключ подписи, скрипты изолированной сборки и CI.
- Звёздочка у поля ввода: библиотека с избранным первым, выбор вставляет текст
  без отправки. «Сохранить ввод» позволяет сохранить набранную команду.

Сохранённая сессия восстанавливает настройки и историю, а не работающий процесс.
Вкладки реализованы; переключение свайпами не реализовано. Файловый менеджер,
экспорт, дополнительные темы и группировка проектов пока не реализованы.

Последнее изменение: главная упрощена до журнала 25 отправленных команд,
с сохранением, внутренней прокруткой, вытеснением старых и очисткой.
Нижняя навигация содержит только Главную, Команды и Терминал.
Тестов теперь 157.

Последняя функция: «Интерактивный ввод» в меню терминала рядом с
«Дополнительными клавишами». Выключен по умолчанию: касание вывода не открывает
IME, ввод через нижнее поле. Включение открывает IME напрямую для TerminalView;
настройка сохраняется в SharedPreferences workspace-input. Нижнее поле остаётся.
В журнал записываются только отправленные из поля команды; пользователь явно
отменил идею записи при вставке. Правки затрагивают TerminalView и его клиент.
Поведение IME на физическом устройстве ещё требует проверки пользователя.

Последнее уточнение: поле ввода многострочное, Enter только переносит строку,
отправка только кнопкой. Поле растёт до шести строк, затем прокручивается.
Отправка использует TerminalEmulator.paste для поддержки bracketed paste
в программах, которые его включают, затем Enter. Интерактивный режим неизменен.

Версия 0.7 реализует концепт docs/fork/ui-concept-v1.png: поиск по журналу,
время отправки, нижняя панель действий ⋮ (вставить, сохранить в библиотеку,
скопировать). Вставка из журнала и Команд предлагает выбрать сессию, если
работает больше одного терминала. Звёздочка по уточнению пользователя всегда
вставляет в текущий. Новых процессов и автоматической отправки это не создаёт.
JSON v2 читает предыдущий v1; старые строки журнала помечены «Ранее».
После сохранения v2 сборки 0.6 и ранее не смогут изменять хранилище (защита
неизвестного формата), поэтому для дальнейших обновлений использовать 0.7+.

## Готовый APK

- `/sdcard/Download/TermuxFork-0.7-debug-arm64.apk`
- Исходная копия: `build/apk/termux-fork-0.7-debug-arm64.apk`.
- Версия `0.118.3-fork.7`, ARM64, Android 7+ (minSdk 24).
- SHA-256 актуальной сборки указан в `docs/fork/VALIDATION.md`.
- Подпись v2 проверена. Ключ `.signing/fork-debug.jks` исключён из Git;
  не удалять: он нужен для обновлений тестового APK.
- Alias и пароль по умолчанию: `termux-fork-debug` (только тестовый ключ).

Package остаётся `com.termux`: bootstrap и пакеты используют жёсткие пути
`/data/data/com.termux/files/usr`. APK нельзя установить параллельно с Termux
или обновить Termux с другой подписью. Пользователь намерен проверить его
на другом устройстве. Не предлагать удалять текущий Termux.
Для отдельного package потребуется адаптировать и пересобрать bootstrap/пакеты.
Пользователю уже объяснено, что bootstrap — начальное окружение Bash,
утилит и менеджера пакетов.

## Проверки и ограничения

Все 157 unit-тестов прошли: 145 эмулятора, 12 приложения. Сборка успешна,
подпись и совпадение APK в Download проверены. APK не устанавливался,
реальный запуск JNI/bootstrap и работа интерфейса на устройстве ещё не проверены.
Следующий шаг — получить результаты ручного тестирования пользователя,
исправить найденные проблемы либо выполнить его новые требования.

На ARM64-хосте сборка выполнялась через `scripts/build-local-arm64.sh`:
JNI из оригинального C/ASM отдельно, затем Java/ресурсы/DEX через Gradle.
Стандартная сборка основного Gradle-проекта на x86 CI ещё не проверена.
Детали и команды: `docs/fork/VALIDATION.md`, `FORK.md`.
Карта исходников: `docs/fork/ARCHITECTURE.md`; UI: `docs/fork/DESIGN.md`.
Главная реализация: `app/src/main/java/com/termux/app/workspace/`.

Все последующие инструменты и кеши находятся в `.tools/` и `.verification/`.
До уточнения границ пользователем были начаты загрузки JDK/SDK/Gradle
в общие расположения; они остановлены. Системные пакеты не устанавливались,
но частичные загрузки остались. Это ранее раскрыто пользователю: не утверждать,
что никаких скачиваний за пределы проекта никогда не было.

## Как возобновить

Прочитать `AGENTS.md`, этот файл и `docs/fork/VALIDATION.md`; проверить Git.
Сохранить ограничения пользователя и тестовый ключ. Продолжить с результатов
его проверки. Не устанавливать APK самостоятельно и не менять package простым
переименованием. Новые сборки подписывать тем же ключом и копировать в Download.

## Обновление 0.9 — отдельная прокрутка и последовательность запуска

На главной убран внешний ScrollView: журнал и сохранённые сессии занимают
два независимых участка оставшейся высоты (weight=1), каждый прокручивается
самостоятельно. Это устраняет перехват жестов внешним контейнером.
В редакторе сессии «+ Команда» добавляет поля до трёх; пустые пропускаются.
Команды выполняются в одной Bash-оболочке последовательно, следующая после
завершения предыдущей, при ненулевом коде выполнение цепочки прекращается.
`cd` и export сохраняются между шагами; интерактивная программа блокирует
последующие шаги до выхода. Автоввод в запущенные Ubuntu/Codex не реализован.
Одно прежнее стартовое поле читается и исполняется как ранее.
Хранилище JSON v3 читает v1/v2/v3; startup2/startup3 сохраняются и копируются.
После записи v3 приложение 0.8 и ранее не сможет менять библиотеку:
защита неизвестного формата сохраняет файл, поэтому не откатываться.
APK: `0.118.3-fork.9`, versionCode=1004, тот же ключ, ARM64.
Файл для пользователя: `/sdcard/Download/TermuxFork-0.9-debug-arm64.apk`.

## Обновление 0.10 — выбор среды и готовность Bash

Пользователь подтвердил новый сценарий: в профиле выбрать Termux/Ubuntu,
Ubuntu запускается приложением автоматически, затем до трёх команд в этой
среде. Вход через `proot-distro login ubuntu` из первого поля следует убрать.
В Ubuntu рабочий каталог относится к гостевой системе; при выборе переключается
стандартное значение Termux HOME на /root. Команды выполняются из Bash
PROMPT_COMMAND после инициализации rc, затем последовательно после возврата
предыдущей; ошибка прерывает цепь. Это готовность самой Bash, а не поиск #/$
в выводе и не ввод в Codex. Интерактивный Codex задерживает последующие команды
до завершения. `.bashrc` выбранной среды читается; Ubuntu запускается с явным
/bin/bash --rcfile, не с произвольной настроенной login-shell.
Каталог профиля bind-монтируется в Ubuntu по отдельному пути /tmp для rc,
истории и флага отмены. В меню терминала «Отменить команды запуска» отменяет
оставшиеся шаги, не прерывая текущий процесс. Ожидание Ubuntu и шаги видны
в выводе терминала. Закрытие/перезапуск сессии остаются отдельными действиями.
Старые профили по умолчанию «Как раньше», новый редактор выбирает Termux.
JSON v4 читает v1/v2/v3/v4; environment сохраняется и копируется. Старые версии
после записи v4 не могут изменять библиотеку; не откатывать на 0.9 и ниже.
Сборка 0.118.3-fork.10, versionCode 1005, тот же ключ.
APK: /sdcard/Download/TermuxFork-0.10-debug-arm64.apk.
